# 安装任务：准备 Codex 命令行版和自动值班脚本（不花钱，约 15 分钟）

## 背景
之后改成"自动值班"模式：用户睡觉时，`指挥/自动值班/值班.sh` 每 5 分钟检查 `指挥/队列/`，有任务单就调用 Codex 命令行版（`codex exec`）执行。本任务只负责把这套东西在这台 Mac 上准备好。

## 这次不做什么
- 不运行 `值班.sh`，不运行 `codex exec`，不执行 `指挥/队列/` 里的任何任务单（用户会自己在终端试跑）。
- 不碰 `指挥/当前任务.md`，不改项目代码。
- 如果 `git status` 显示有别的任务没提交的改动（例如任务 006 做了一半），**不要提交、不要还原、不要暂存（stash）它们**，只提交本任务自己的文件（报告、`值班.sh`）。
- 不改系统设置，不使用 sudo。需要 sudo 才能装的话，停下来写进报告。
- 不运行 `codex login` / `codex logout`（登录必须用户本人操作）。

## 要做的事

1. **检查命令行版**：`which codex`、`codex --version`。
   - 已经有：记录版本和位置。
   - 没有：用官方方式安装，优先 `npm install -g @openai/codex`；npm 报权限错误时，如果有 Homebrew 就用 `brew install codex`。装好后再确认 `codex --version`。
   - 确认在一个**新打开的终端**里也能找到 `codex`（例如 `zsh -lc 'which codex'`）。
2. **检查登录**：`codex login status`，原样记录结果（是否显示用 ChatGPT 登录）。没登录就在报告里写明，不要自己登录。
3. **核对脚本里的参数**：打开 `指挥/自动值班/值班.sh` 里的 `CODEX_ARGS` 那一行（"可调的设置"一节）。用 `codex exec --help` 核对：
   - `--sandbox workspace-write` 这个写法是否存在；
   - 用 `-c sandbox_workspace_write.network_access=true` 打开联网，在当前版本里是否仍是这个配置名（可查 `codex --help`、官方文档或本机 `~/.codex/config.toml` 说明）。
   - 说明：这个模式下 Codex 改不了 `.git`（无法自己 commit），这是已知情况，脚本已改成由脚本负责保存和推送，**不需要为此放开权限**。
   - 写法不同就**只改这一行**成当前版本的正确写法，并在报告里写明改前改后。不要改成完全放开权限的模式（`--dangerously-bypass-approvals-and-sandbox` 之类），如果只能这样才能联网，写进报告，由总指挥和用户决定。
4. **检查脚本本身**：`bash -n 指挥/自动值班/值班.sh` 语法检查；`chmod +x 指挥/自动值班/值班.sh`；确认 `caffeinate`、`pkill` 命令存在。
5. **只读查看休眠设置**：`pmset -g` 原样记录（只看，不改）。
6. **检查 git 推送**：`git remote -v`、`git status` 简要记录；确认在普通终端里 `git push` 不需要每次输入密码（看 credential helper 配置即可，不用真推）。

## 报告
写到 `指挥/报告/自动值班-安装.md`：每一项一行，写结果和是否正常；最后列出"需要用户亲手做的事"（例如登录）。

## 完成后
提交并推送：报告 +（如有改动）`值班.sh`。提交说明写 `自动值班安装检查 (No SPEC Change)`。回复里只说三件事：完成了什么、报告路径、有没有需要用户亲手做的事。
