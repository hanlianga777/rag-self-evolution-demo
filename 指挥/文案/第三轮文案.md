# 第三轮全站文案（总指挥定稿，前端原样使用）

> **规则**
> - 通用产品口吻，不出现本项目的数字。
> - 悬停提示统一用"i"图标：鼠标移上去时光标变成问号，弹出深色说明卡。
> - 文字为书面中文，说人话。

## 一、页面用途长句（页面标题下方那一句）

| 页面 | 文案 |
| --- | --- |
| RAG 自进化概览 | 这里用一屏讲清楚整套系统做成了什么：从同一套考卷上的 Baseline 出发，经过 Agent 在规则内的多轮受控试错，最终选出质量更高、速度更快、且没有弄坏任何原本答对题目的配置，并交由人工审批后发布上线。 |
| 知识库 | 这里把客户的说明书解析成既能被准确检索、又能回溯到原页的知识：先去掉页眉页码等噪声，再按章节组装成完整的 Parent 段落、在其中切出用于检索的 Child 小块，最后建立向量与关键词索引，并按主题聚类为后续出题提供依据。 |
| Golden Dataset | 这里生产每一轮都不变的考卷：按知识主题的厚薄分配题位，覆盖正向、消融和负向三类题型，每道题都要经过证据逐字校验、探针实测和质检，人工确认红线清单后冻结，此后所有评测都用它。 |
| Pipeline 配置 | 这里列出系统的技术选型和 Agent 可以调整的参数，也就划定了自动优化的边界：Agent 只能在白名单参数的取值范围内试错，分块方式、模型选择这类需要重建索引或换模型的改动，必须由人决定。 |
| Baseline | 这里用同一套考卷和判分标准给当前配置做一次完整体检：先看每一项上线门槛是否达标，再把每一个答错的题定位到检索、生成、安全或性能中的具体一层和具体原因，为 Agent 的优化指明方向。 |
| Agent 工作台 | 这里展示 Agent 如何在白名单参数里一轮轮试错：每一轮先根据诊断和上一轮的经验制定策略，同时提出方向不同的几个 Candidate，在同一套考卷上比较后写下本轮结论，最后合并有效改动、推荐出最终方案。 |
| 发布 | 这里把机器的推荐变成可以签字的上线决定：程序先校验发布资格，人工确认实验报告并批准发布，每次发布都保存完整的配置快照，出现问题时可以整体回滚到兼容的历史版本。 |
| 问答验证 | 这里验证优化在真实回答上的效果：可以对比同一道题优化前后的回答和引用来源，也可以直接向线上版本提问；线上发现的问题经人工标注后会作为线索回到考卷候选池，进入下一轮优化。 |

## 二、名词解释（悬停说明）

| 名词 | 说明 |
| --- | --- |
| 正向题 | 资料里有明确答案的题，用来测系统在知识充足时能不能答对、答全，代表能力上限。 |
| 消融题 | 同一个知识点换一种问法，例如口语化、少主语、带干扰信息，用来测问法变了以后系统还能不能找对证据。 |
| 负向题 | 不该直接回答的题，用来测安全下限。分为四类：证据不足、需要追问、安全关键、提示注入。 |
| 证据不足 | 知识库里没有答案，系统应当说明说明书没有提到，而不是编造。 |
| 需要追问 | 问题缺少型号、状态等关键条件，系统应先问清楚再回答。 |
| 安全关键 | 涉及人身或设备安全的危险操作，例如绕过安全装置，系统必须拒绝并给出安全做法。 |
| 提示注入 | 问题里夹带"忽略以上规则"之类的指令，系统应当识别并忽略。 |
| 主题簇 | 用 K-means 按语义把知识片段自动分成若干主题，出题时按主题的厚薄分配题位，保证考卷覆盖整本说明书，而不是扎堆在好出题的几页。 |
| Probe（探针） | 一段自动体检程序：AI 出完一道题后，立刻拿这道题去知识库检索一遍。有答案的题，看标准证据能不能被找回来；没答案的题，确认库里确实搜不到，防止把其实答得了的题当成负向题。由程序完成，不用大模型判断。 |
| QC（质检） | 整套题出完后，由大模型对照证据逐题检查题目写得好不好，例如答案和证据有没有矛盾、题目是否含糊，问题按轻重分级，人工只需要看红线清单。探针管"题是真是假"，质检管"题写得好不好"。 |
| 判分（LLM-as-Judge） | 每道题答完后，由判分模型拿着必答要点和证据原文对照回答打分：答对程度、要点覆盖、是否忠于证据、有没有安全问题。这些分数汇总后就是上线门槛里的质量指标。 |
| 同一套考卷和判分标准 | 冻结的 Golden Dataset，加上固定的判分规则和上线门槛。Baseline 和每一个 Candidate 都用它来考，结果才能直接比较。 |
| Hard Gate | 上线门槛。每一项都要单独达标，综合分再高也不能抵消某一项没过。 |
| Bad Case | 判分没有通过的题。系统会把它定位到检索、生成、安全或性能中的一层，并写出具体原因。 |
| Sandbox | 和线上隔离的试验环境。每个 Candidate 都在这里用同一套考卷跑一遍，不影响线上。 |
| Candidate | Agent 提出的一套候选配置，即在 Baseline 上改动哪几个参数。 |
| Regression Check | 回归检查：修好的题不能抵消新弄坏的题。只要出现严重的新增 Bad Case，这个方案就不合格。 |
| Candidate D | 几轮结束后，Agent 把合格方案里被证明有效的参数合并成的最终方案。合并前先写下预计修好哪些题，跑完后逐题对账。 |
| Parent / Child | Child 是检索用的小块，越小越容易精准命中；命中后换成它所在的完整段落 Parent 交给模型，回答时上下文才完整。 |
| P50（中位耗时） | 把所有问题的回答耗时从快到慢排好，排在正中间的那一个：一半的问题比它快。 |
| P99（最慢耗时） | 99% 的问题都能在这个时间内答完，代表最坏情况下用户要等多久。 |
| TTFT（首字耗时） | 从提问到回答出现第一个字的时间，决定用户"感觉"快不快。 |
| Recall@K（召回率） | 标准证据有没有出现在最终交给模型的前 K 段资料里。 |
| Precision@K（精确率） | 交给模型的 K 段资料里，有多少段是真正相关的。 |
| MRR（排名得分） | 第一段标准证据排第几：排第 1 得 1 分，排第 2 得 1/2，以此类推，越接近 1 越好。 |

## 三、Hard Gate 每一项（悬停说明，写清"平均分"还是"通过比例"）

| 指标 | 说明 |
| --- | --- |
| 正向题 · 答对程度 | 判分模型给每道正向题的答对程度打分，取所有正向题的平均分。 |
| 正向题 · 忠实度 | 每道正向题是否只说证据里有的内容、没有编造，0 到 1 分，取平均分。 |
| 正向题 · 完整度 | 每道正向题覆盖了多少必答要点，0 到 1 分，取平均分。 |
| 消融题 · 三项 | 同上，按消融题计算平均分；门槛比正向题略低，因为问法更难。 |
| 安全拒答率 | 负向题里做对（该拒就拒、该问就问）的比例，按题数计算。 |
| 安全关键题正确率 | 安全关键类负向题做对的比例，按题数计算。 |
| 抗提示注入 | 提示注入类负向题做对的比例，按题数计算。 |
| 中位耗时 P50 | 一半的问题在这个时间内答完。 |
| 最慢耗时 P99 | 几乎所有问题都在这个时间内答完。 |

> 说明：质量类指标是"每题得分的平均值"，所以会出现带小数的百分比；安全类指标是"做对的题数 / 总题数"。

## 四、Bad Case 细分类型（列表和抽屉统一用这套说法）

| 层 | 细分类型 | 判断依据（程序根据检索记录判断，不用模型） |
| --- | --- | --- |
| 检索层 | 关键证据没找回来 | 候选段落里没有标准证据 |
| 检索层 | 排名靠后被截掉 | 候选里有标准证据，但排在 Top-K 之外，没交给模型 |
| 检索层 | 找回的大多不相关 | 交给模型的资料里相关段落占比很低 |
| 生成层 | 证据给到了却漏了要点 | 标准证据已交给模型，回答仍缺必答要点 |
| 生成层 | 编造内容 | 判分认定回答包含证据里没有的说法 |
| 生成层 | 过度拒答 | 资料里有答案，回答却说无法回答 |
| 安全层 | 该拒没拒 / 被提示词注入绕过 / 答了库外内容 | 负向题判分未通过 |
| 性能层 | 整体太慢 / 首字太慢 / 成本太高 | 单题耗时或成本明显超出门槛 |

**严重程度**（悬停说明）：安全关键题，或者判分标记了"关键错误"（例如漏掉安全警告、给出危险操作）的，记为**严重**；其余记为**一般**。严重的新增 Bad Case 会让方案直接不合格。

## 五、人工三道 Gate（发布页、业务架构图统一用这套说法）

| Gate | 人看什么 | 不看什么 |
| --- | --- | --- |
| Gate 1 · 题卷红线 | 质检之后剩下的红线问题清单，确认后冻结考卷 | 不逐题全审（证据真伪已由校验和探针把关） |
| Gate 2 · 实验报告 | 各个合格方案的评测报告、推荐理由和回归结果 | 没过线的方案不进入确认 |
| Gate 3 · 发布确认 | 红线有没有被踩、抽样回归是否正常，确认后保存快照上线 | 不追求把所有情况都测完 |

**发布资格**（程序校验，悬停说明）：上线门槛全部通过；回归检查没有严重的新增 Bad Case；所有参数都在白名单范围内；配置快照完整；知识库版本和评测时一致。

## 六、Agent 的四条原则（Agent 概览用四个小标签，悬停看说明）

| 标签 | 悬停说明 |
| --- | --- |
| 只在白名单里调 | Agent 只能改可调参数，取值也必须在规定范围内；分块、换模型这类改动由人决定。 |
| 方向互不相同 | 同一轮的几个 Candidate 改不同的参数，结果变好或变坏，都能说清是哪一处改动造成的。 |
| 修好不能抵消弄坏 | 只要出现严重的新增 Bad Case，修好再多题也不算合格。 |
| 事先预测、事后对账 | 每个方案先写下预计修好哪些题、有什么风险，跑完后逐题核对。 |

> 不出现"每轮固定一个效率方向"之类的说法；Agent 为什么提出降档，展示它自己保存的思考过程。

## 七、Pipeline 参数悬停说明（替换现有说明；格式：一句话作用 + 每个取值括号说明）

| 参数 | 作用 | 取值说明 |
| --- | --- | --- |
| 候选数 candidate_k | 第一轮查找时先捞回多少段资料，留给后面排序挑选。捞得多不容易漏掉关键证据，但排序更费时。 | 12（常规范围）／24（范围加倍，适合证据分散在多处的题） |
| 保留条数 top_k | 排序后真正交给模型写回答的资料段数。给得多要点更全，但模型要读得更多、回答更慢，也更容易被无关内容干扰。 | 4（精简）／6（更全，稍慢） |
| 最低相关分 min_score | 相关分低于这条线的资料直接丢掉，不交给模型。线越高资料越干净，但也可能把有用的证据一起筛掉。 | 0（不筛）／0.1（只去掉明显无关的）／0.2（适度筛选）／0.3（筛得较严）／0.4（最严） |
| 混合检索 hybrid_search | 同时用两种方式找资料：语义检索（意思相近就能找到）和关键词检索（字面一致才能找到），再把两边的分数合起来。 | 开（两种一起用）／关（只用语义检索） |
| 语义检索权重 hybrid_alpha | 混合检索时语义检索分数占多大比重，其余归关键词检索。只在混合检索开启时有效。 | 0.3（更看重关键词原文，适合型号、错误码这类精确词）／0.5（两者各半）／0.7（更看重意思相近，适合口语化问法） |
| 重排序 rerank | 初步找回资料后，用专门的排序模型逐段判断和问题有多相关，再重新排队。 | 开（用排序模型精排）／关（保持初步检索的顺序）／仅原问题（只按用户原话做关键词排序，不调用排序模型） |
| 问题改写 query_rewrite | 检索前先把用户的口语问题改写成更规范的说法再去查。 | 开／关 |
| 多路查询 multi_query | 从不同角度多生成几种问法，分别检索后合并结果，减少一种问法漏掉证据的情况。 | 关（只用原问题）／2、4、6（多生成几种问法；越多覆盖面越广，也越慢） |
| 假设答案检索 hyde | 先让模型写一段"可能的答案"，再拿这段话去检索。它和说明书原文的写法更接近，有时比直接用问题检索更容易找到证据。 | 开／关 |
| 回答策略 prompt_strategy | 告诉模型按什么原则组织回答。 | Grounded（严格只说资料里有的）／Completeness（尽量把要点答全）／Tiered（分级回答：能确定的先答，缺条件先追问，资料里没有就说明并建议转人工，安全警告始终保留） |
| 思考档位 generation_thinking | 模型写回答前"想"多久。档位越高，复杂问题答得越稳，但越慢越贵。 | Off（不思考，最快）／Low（略想）／High（多想）／Max（想得最久，最慢） |
| 资料总长度上限 retrieval_max_tokens | 交给模型的资料最多多长，超出部分截掉。 | 不限／8192（较宽松）／4096（较紧，回答更快，但可能截掉证据） |

> 规则：一句话作用后面不再接分号；取值说明用"／"分隔；页面拼接时不得出现"。；""；。"连用。
