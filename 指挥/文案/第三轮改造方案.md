## 一、已定的决定（11-14 用户拍板 + 11-15 现状）

1. **回答格式**：新回答使用结构化 Prompt `generation-vnext-3`，这一点已在 031b 落地。
   - 已保存的回答有新有旧，在前端用**同一个回答渲染组件**统一展示，**文字一个字不改**。
2. **分块**：已真实修复为 `parent-child-v2` 并重跑（031c/031d）。
   - "分块诊断"展示的是**真实的健康指标**，不是缺陷说明：碎块数、平均每个 Parent 的 Child 数、单 Child Parent 占比。
   - 所有数字从接口读，不写死。
3. **Gate 保留三道**，每道写清"人看什么、不看什么"，文案见 `第三轮文案.md` 第五节。
4. **Agent 工作台页签**：概览｜Candidates 对比｜回归与推荐。
   - 原"进化路线"和"Sandbox 对比"并入"Candidates 对比"。
   - "Candidates 对比"按"Agent 策略 → 三个 Candidate → 本轮结论"三段展示，Round 1/2/3/D 标签吸顶。
5. **发布状态**：新版本（11-14 实验）尚未发布，用户还在看结果。
   - 页面一律按接口数据渲染，**同时兼容**"线上是旧版本"和"线上是新版本"两种状态。
   - 不写死任何实验编号、题号或数字。
6. **"一把尺子"**：全站改为"同一套考卷和判分标准"。第一次出现时用"i"拆开解释：考卷、判分、上线门槛。
7. **"降档"**：不出现"每轮固定一个效率方向"之类的说法。
   - Agent 提出降档时，只展示它自己保存的思考过程。
   - 效率规则触发时，标签写"Agent 策略 · 效率优化"。

## 二、给面试讲解用的解释（页面"i"提示依据）

1. **判分（LLM-as-Judge）**：每道题答完后，由判分模型拿必答要点和证据原文对照回答打分，包括答对程度、要点覆盖、忠实度、安全。汇总起来就是 Hard Gate 的质量项。
2. **百分比带小数**：质量类指标是每题得分的平均值；安全类是"做对题数 / 总题数"。
3. **P50 / P99**：中位耗时（一半的问题在这之内答完）/ 最慢耗时（几乎所有问题都在这之内答完）。
4. **严重程度**：安全关键题，或判分标记了"关键错误"，记为严重；其余为一般。
5. **检索路径**：必须按必答要点逐条对齐，每条要点写清召回排第几、Rerank 后排第几、是否进入回答。不能只追踪一段证据，也不能把召回 / Rerank / Top-K 混在一行。
