## 0. 目标（面试演示用）

面试官打开 demo，3 分钟内要能看懂这条故事线：

客户说明书 → 知识库 → 黄金测试集 → Baseline 测出错题 → Agent 按错误原因提出方案 → 沙盒并排对比 → 合格方案 → 人工确认 → 发布

每一页都要讲清三件事：这一步做什么、产出了什么、下一步是什么。数字是主角，原始日志是配角。

## 1. 术语规范（全站统一）

### 1.1 保留英文的核心词

Agent、RAG、Pipeline、Baseline、Judge、Candidate、Bad Case、Token、Chunk、API。

- 大小写统一，例如统一写 "Bad Case"，不写 "badcase" 或 "BadCase"。

## 3. 表达结构化

- 超过两行的说明段落，改成卡片，或"1-2-3 要点"列表，每条一行，关键词加粗。
- 结论放在最前面，例如"✓ 合格""✗ 有新错题"；理由和数据放后面，可以折叠。
- 长报告文本（复盘原文、Judge 理由）默认只显示第一句，"展开全文"放进抽屉。
- 重要数字用大号字体；单位和口径说明用小号灰字。

## 5. UI 细节

1. **卡片和标签**：状态统一用标签（tag）。颜色：
   - 绿：合格 / 对 / 修好
   - 红：错 / 新错 / 不合格
   - 琥珀：存疑 / 临界
   - 灰：未运行 / 不适用
2. **次要信息**：12px，颜色 #8a8f98 一类的浅灰。包括：ID、版本号、指纹、来源路径、时间戳、代码名。
3. **重点信息**：加粗或放大。包括：答对数、门槛结果、结论、修好和新错的题号。
4. **对齐**：
   - 表单和详情页用左右两栏，标签栏固定宽度、右对齐；
   - 表格中的数字列右对齐，用等宽数字（tabular-nums）；
   - 同一个页面里各卡片的标题基线对齐；
   - 表头吸顶。
5. **题号标签**：全站统一，点击都打开同一个题目抽屉。抽屉里依次是：问题、参考答案、各运行的回答、Judge 三维分、证据进入情况。
6. **空状态**：没有数据时写清楚原因和下一步，例如"题卷冻结后显示"，不要显示一个光秃秃的"—"。
7. **悬停卡**：所有术语和口径都有悬停解释，解释不超过两句话。
