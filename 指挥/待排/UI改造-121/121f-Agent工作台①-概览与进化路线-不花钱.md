# 121f Agent 工作台①：概览 tab 与进化路线 tab（不花钱）

前置：121b 已通过总指挥验收，且 E5（120b）已经跑完。先读 `00-共同规范.md`。只改 `frontend/`。依据互审 51：逐层推进、Winner 累积门、D 触发规则。

## 概览 tab

1. **实验选择器**
   - 不再直接显示原始 ID，改为「E5 · 初始优化 · 11-25」这样的格式，ID 放进 title。
   - 默认选中最新的正式实验。
2. **首屏**放 4 张 KPI：答对 Baseline → 当前 Winner、修好几题、已用 Sandbox x/12、已用费用。
   - 下方是「各轮目标层」一行时间线，例如「第 1 轮 检索层 → 第 2 轮 生成层 → D」，数据取自 staged_decision / target_layer 记录。
3. **删除内部状态外露**：例如「规划未完成：4/5 道已有 Candidate 覆盖」（`ui/evolution/AgentOverview.tsx:24`）。如果确实需要保留，放进技术记录。

## 进化路线 tab

1. **每一轮按统一顺序展示**：
   1. 本轮目标：目标层，以及为什么选它，一句话；
   2. 三张方案卡；
   3. 本轮复盘：一两句；
   4. 下一步决策：进下一轮、转层、进 D 或停止，再加一句理由。
2. **方案卡**
   - 同一行等宽等高，字段对齐；
   - 标题不截断，过长时换行；
   - 卡内不滚动。
   - **首屏只放 5 项**：
     1. 方案名：例如「A · 扩大检索范围」，第 1 轮 A 写「第 1 轮 A（Agent 提出）」；
     2. 资格标签；
     3. 参数改动：用 `diffParams`，形如「候选数 12 → 24」；
     4. 一句话假设；
     5. 结果三格：答对 x/50、修好 n、新增错题 m。
   - 其余内容（证据、预测命中、规则版本、Gate 明细、不合格方案的错题列表）全部进 Candidate 抽屉，那是 121g 的范围。
3. **D 的卡片**设计语言相同，额外显示两行：「相对 Winner 新增改动」和「相对 Winner 回退 x 题」。
4. **「原因」文字墙**拆成上面的「本轮复盘」和「下一步决策」两段短句。
5. **生成诊断**：120a 的 PROBE 记录放在两轮之间，作为一个小节，不显示成 Candidate。只列实际跑过的档位和真实结论，不写固定文案。
6. **方案数量**：一轮只有 1～2 个方案时，按实际数量显示，不放空卡凑成 3 列。
7. **分开表达「合格」和「成为 Winner」**：相对 Baseline 合格，不等于相对上一轮 Winner 可以晋升。两者用两个字段分别显示。
8. **二级入口**：历史实验切换、Sandbox 高级指标、候选目标题列表、可调参数说明，改用 `DrawerShell`，内容按共同规范精简。
