- **日期**：2026-11-26

**这份文档要讲清楚四件事：**

1. 我们定了哪些设计原则；
2. 每个页面、每个 tab、每个抽屉长什么样，表格有哪些列，每列显示什么；
3. 字号、颜色、粗细的具体规范；
4. 哪些东西坚决不出现。

## 第一部分 设计原则（总纲）

### 原则 1：首屏讲结论，第二层讲过程，抽屉讲证据，原始记录折叠

| 层级 | 放什么 | 例子 |
|---|---|---|
| 首屏 | 一句话就能回答「这页想告诉我什么」的数字或状态 | 概览首屏：答对 45 → 48 / 50 |
| 第二层（页面下半部分、tab 内） | 结论是怎么来的：过程、分布、对比 | 每轮 A/B/C 方案卡 |
| 抽屉 | 单个对象的完整证据：题目、回答、引用原文、判分 | Bad Case 抽屉 |
| 折叠区（「展开技术记录」） | 给技术面试官追问用的原始记录：ID、Trace、3 次判定明细 | 运行 ID、Judge 原始分 |

### 原则 2：能用卡片就用卡片；抽屉里也是一张张卡片叠起来

- 页面由卡片组成，每张卡片只讲一件事，有一个标题。
- 抽屉内容按区块分成一张张卡片，从上到下排，每张卡片上方有一行小标题，例如「01 题目」「02 诊断结论」。
- 不搞「卡片套卡片套卡片」。卡片里需要分组时，用细分割线或留白，不再嵌套边框。

### 原则 3：能量化的用「大数字」，能比较的用「图表」

| 信息类型 | 展示方式 |
|---|---|
| 单个关键指标（答对数、修好题数、费用） | **大数字卡**：大号黑色加粗数字，旁边是浅灰色小字单位，下方一行浅灰色说明 |
| 前后对比（Baseline → 方案） | 「45 → 48」：前一个数用浅灰色，箭头用浅灰色，后一个数用黑色加粗；变化量用绿色或红色小标签，如「+3 题」 |
| 构成或分布（错题分在哪几层） | **横向分段条**，每段标出层名和数量，例如检索 3 · 生成 2 |
| 多个方案在多个指标上的对比 | **对比表**：每个方案一列，每个指标一行，最好的值加粗 |
| 时间或轮次推进 | **横向时间线**：第 1 轮 → 第 2 轮 → D → 发布，每个节点下写一行结论 |
| 范围类数值（P50/P99 对门槛） | **进度条加门槛刻度**：条长表示实际值，竖线表示门槛位置 |

### 原则 4：颜色只表达含义，不做装饰

| 颜色 | 只用于 |
|---|---|
| 绿色 | 答对、合格、已发布、修好 |
| 红色 | 答错、不合格、新增错题、门槛没过 |
| 橙色 | 风险提示、「注意」类安全警告 |
| 蓝色 | 进行中、当前选中、可点击的链接 |
| 灰色 | 未运行、未晋升、不适用、辅助信息 |

**检索层、生成层这类分类不用状态色**，统一用中性的浅灰底标签。否则会让人误以为「生成层 = 坏」。

### 原则 5：重要的用黑色加粗，不重要的用浅灰小字

视觉上只有三档，下面的字号规范就是围绕这三档定的：

1. **主信息**：黑色，加粗或中粗，字号大。例如数字、题目、结论。
2. **正文**：深灰色，常规粗细，14px。
3. **辅助信息**：浅灰色，小字号。例如单位、说明、ID、时间。

### 原则 6：不留空，不写「未知」，空值有固定写法

| 真实情况 | 统一写法 |
|---|---|
| 值就是 0 | `0` |
| 没有记录 | `—`（浅灰色） |
| 这项对它不适用 | `不适用`（浅灰色） |
| 还没跑 | `未运行`（灰色标签） |
| 正在读取 | 骨架屏（灰色闪烁占位块） |
| 历史版本没存这个字段 | 只在抽屉里写一句「该版本未记录」（浅灰色），表格里用 `—` |
| 整列都没有值 | 整列隐藏 |
| 评测必需的字段缺失 | 红色提示「结果不完整」，不能显示成通过 |

**禁止**：把「0 → 未知」当成参数变化；为了不留空，凭空补 0 或补默认值。

### 原则 7：同一个东西，全站只有一个叫法

全站统一术语，参数用中文名，在技术详情里附上代码名：

| 代码名 | 卡片上显示 | 技术详情里显示 |
|---|---|---|
| candidate_k | 候选召回数 | 候选召回数 `candidate_k` |
| top_k | 最终保留数 | 最终保留数 `top_k` |
| min_score | 最低相关分 | 最低相关分 `min_score` |
| hybrid_search / hybrid_alpha | 混合检索 / 混合检索权重 | 同左，附代码名 |
| rerank | 证据重排 | 证据重排 `rerank` |
| query_rewrite / multi_query / query_decompose / hyde | 问题改写 / 多路查询 / 问题拆解 / 假设文档检索 | 同左，附代码名 |
| retrieval_max_tokens | 资料长度上限 | 资料长度上限 `retrieval_max_tokens` |
| generation_thinking | 思考档位（Off / Low / High） | 同左，附代码名 |
| prompt_strategy | 回答策略（Strict / Looser / Safe） | 同左，附代码名 |

### 原则 8：全站禁止出现的内容

| 禁止 | 原因 |
|---|---|
| 「要点 1」「要点 2」「（补充）」「记录缺失：未保存完整的要点判分记录」 | 参考答案改为正常答案的写法（参照 RAGAS），这些是评测内部结构，不给人看 |
| 「资料边界」灰框 | 回答按模型原文分行显示，不再拆出单独的灰框 |
| 「不稳定」「波动」 | 判定统一按 3 次多数，明细放进折叠区 |
| 「人工保留」 | 沿用来源只在技术记录里如实写明 |
| Stepwise、Grounded、TableCheck、Thinking Max | 已经删除的选项 |
| 「设计巧思」这类研发笔记 | 不是产品文案 |
| 超大黑色悬浮提示框（Tooltip） | 长内容改成点击展开 |
| 抽屉里再套一层滚动框 | 抽屉只允许整体一层滚动 |

## 第二部分 样式规范（Design Token）

### 2.1 字号与字重

| 用途 | 字号 | 字重 | 颜色 |
|---|---|---|---|
| 页面标题，如「Agent 工作台」 | 24px | 700 | 黑 #111827 |
| 页面职责说明（标题下一行） | 14px | 400 | 浅灰 #6B7280 |
| 区块标题，如「Sandbox 对比」 | 18px | 600 | 黑 |
| 卡片标题 | 16px | 600 | 黑 |
| KPI 大数字 | 36px（次要 KPI 用 28px） | 700 | 黑，变化后的值可用绿或红 |
| KPI 前值，如 45 → 48 中的 45 | 24px | 500 | 浅灰 #9CA3AF |
| 单位，如「/ 50」「秒」 | 14px | 400 | 浅灰 #9CA3AF |
| 正文、表格内容 | 14px | 400 | 深灰 #374151 |
| 表头、字段名 | 13px | 500 | 中灰 #6B7280 |
| 辅助说明、时间、ID | 12px | 400 | 浅灰 #9CA3AF |
| 标签文字 | 12px | 500 | 跟随标签颜色 |

- 数字统一使用等宽数字（tabular-nums），这样上下对齐。
- 行高：正文 1.6，标题 1.3。

### 2.2 颜色

| Token | 色值 | 用途 |
|---|---|---|
| 页面背景 | #F6F7F9 | 主内容区底色 |
| 卡片底色 | #FFFFFF | 所有卡片、抽屉 |
| 边框 / 分割线 | #E5E7EB | 卡片边框、表格线 |
| 主文字 | #111827 | 标题、数字、重点 |
| 正文 | #374151 | 正文 |
| 辅助文字 | #6B7280 / #9CA3AF | 说明、单位、ID |
| 主色（蓝） | #2F5FD0 | 链接、选中、进行中 |
| 成功（绿） | #15803D，浅底 #ECFDF3 | 答对、合格、已发布 |
| 失败（红） | #B91C1C，浅底 #FEF2F2 | 答错、不合格 |
| 警示（橙） | #B45309，浅底 #FFF7ED | 「注意」、风险 |
| 中性（灰） | #6B7280，浅底 #F3F4F6 | 未运行、未晋升、分类标签 |
| 左侧导航背景 | 保持现有深色 | 用户已确认保留深色 |

### 2.3 间距、圆角与尺寸

- 间距都取 4 的倍数：页面边距 24、卡片内边距 20、卡片之间 16、模块之间 24。
- 圆角：卡片 10，按钮、输入框、标签 6。
- 表格行高 48；按钮高 36。
- 抽屉宽 800px，窄屏时自适应。抽屉头部固定，内容区只有一层滚动。

### 2.4 标签（只允许四类）

| 类别 | 可用值 | 样式 |
|---|---|---|
| 评测结果 | 答对 / 答错 | 绿底绿字 / 红底红字 |
| 方案资格 | 合格 / 不合格 | 绿 / 红 |
| 工作流状态 | 未运行、评测中、等待恢复、已完成、已暂停、执行失败、已跳过 | 灰 / 蓝 / 橙 / 绿 / 灰 / 红 / 灰 |
| 决策状态 | 未晋升 / 已推荐待审批 / 已审批待发布 / 已发布 | 灰 / 蓝 / 蓝 / 绿 |

题型、层级、参数名、ID 一律用普通文字或浅灰底标签，不用彩色。

## 第三部分 公共组件

### 3.1 页头（所有页面统一）

由三部分组成：
- 页面标题，24px 黑色加粗；
- 一行职责说明，14px 浅灰；
- 右侧可选的操作区，比如实验选择器。

8 个页面的职责说明（已定稿）：

| 页面 | 职责说明 |
|---|---|
| 自进化概览 | 查看优化成果、进化过程与当前线上版本。 |
| 知识库 | 管理知识文档、索引及原文证据。 |
| Golden Dataset | 构建并管理用于质量评测的标准测试集。 |
| Pipeline 配置 | 查看系统技术选型与可调参数。 |
| Baseline | 评估初始回答质量并定位错误根因。 |
| Agent 工作台 | 根据评测问题探索、验证并推荐优化方案。 |
| 发布 | 核验推荐方案并管理线上版本。 |
| 问答验证 | 对比优化前后回答，验证线上实际效果。 |

### 3.2 左侧导航（保留深色，分三组）

```
RAG Evolution
  自进化概览
  ── 准备 ──
  知识库
  Golden Dataset
  Pipeline 配置
  ── 评测与优化 ──
  Baseline
  Agent 工作台
  ── 发布与验证 ──
  发布
  问答验证
```

- 分组标题用 11px 浅灰大写间距字。
- 选中项：浅色底，文字为白色加粗。
- **修复「点两下才切页」的 bug**：任意两个页面互切，单击一次就要成功。

### 3.3 KPI 大数字卡

```
┌───────────────────────────┐
│ 答对题数              ⓘ   │  ← 13px 中灰字段名，右侧小图标解释口径
│ 45 → 48  / 50             │  ← 45 浅灰 24px；48 黑色 36px 加粗；/50 浅灰 14px
│ [+3 题]  较 Baseline       │  ← 绿色小标签 + 12px 浅灰说明
└───────────────────────────┘
```

- 同一行的 KPI 卡等宽等高，数字底边对齐。
- 每张卡只放三层：字段名、数字、一行说明。

### 3.4 题目行（所有题目列表通用）

| 列 | 显示内容 | 样式 |
|---|---|---|
| 题号 | Q05 | 13px 中灰，等宽字体 |
| 问题 | 完整问题，最多显示 2 行，多出的用 … | 14px 深灰；悬停不弹黑框，点击整行打开抽屉 |
| 题型 | 正向 / 消融 / 负向·证据不足等 | 浅灰底标签 |
| 结果 | 答对 / 答错 | 绿 / 红标签 |
| 错在哪层（仅错题） | 检索 / 生成 / 安全 / 性能 + 严重度 | 浅灰底标签；严重度为「致命」时文字加粗 |
| 操作 | 「查看」 | 蓝色文字链接 |

### 3.5 抽屉外壳（所有抽屉通用）

```
┌ 抽屉头（固定）──────────────────────────────┐
│ ← 返回 Baseline                         ✕   │  12px 浅灰面包屑；关闭按钮只有一个
│ Q05 · 正向 · [答错]                         │  18px 黑色加粗：编号 + 类型 + 状态标签
├──────────────────────────────────────────────┤
│ 01 题目                                      │  ← 每个区块是一张卡片，左上方是 12px 编号加 13px 区块名
│ ┌──────────────────────────────────────────┐ │
│ │ ……                                       │ │
│ └──────────────────────────────────────────┘ │
│ 02 ……                                        │
│ ▸ 展开技术记录（默认折叠）                    │
├──────────────────────────────────────────────┤
│ 底栏（只有需要操作时才出现）：[主操作] [次操作] │
└──────────────────────────────────────────────┘
```

- 抽屉只有一层滚动。
- 焦点恢复、Esc 关闭、未保存时提示确认，这几项行为都保留。

### 3.6 回答与参考答案的显示

- 参考答案：正常答案。简单题一两句话，操作题用 1. 2. 3. 分行。**不显示「要点 1」「（补充）」**。
- 系统回答：按模型原文分行显示：
  - 以「注意：」开头的行：橙色左边线加浅橙底，文字照常；
  - 引用编号 [1] 显示为蓝色小角标，点击后在抽屉内展开对应的原文卡片；
  - **不再拆出「资料边界」灰框。** 模型写的「提供的资料里没有找到……」就作为普通的一行显示。
- 两者并排对比时用两列：左边参考答案，右边系统回答，两列等宽，顶部对齐。

### 3.7 证据引用卡

```
┌──────────────────────────────────────────┐
│ IRB 1300 产品手册 · 第 1 部分 · p.128   [核心证据] │  ← 14px 黑：短文档名 + 页码；右侧浅灰底标签
│ 轴4 | 175-187 Hz | 209-219 Hz            │  ← 原文 14px；与答案相关的片段用浅黄底高亮
│ ▸ 查看完整原文                             │  ← 12px 蓝色链接
└──────────────────────────────────────────┘
```

- 完整文件名、chunk ID、召回排名、重排排名放在「展开技术记录」里。
- 表格原文按表格渲染。解析不出来的，按原文显示，并加一行浅灰说明：「原文为表格，可在知识库查看」。

## 第四部分 逐页设计

### 4.1 自进化概览（用户最喜欢的版式：保持版式，只修细节）

**保留**：大数字对比、卡片分区、业务架构和技术架构两个 tab。

**首屏 4 张 KPI 卡（一行）：**

| 卡片 | 大数字 | 下方说明 |
|---|---|---|
| 答对题数 | Baseline → 线上，如 `38 → 45 / 50` | `+7 题` 绿标签 · 较 Baseline |
| 修好的错题 | `7` | 共 12 道 Bad Case |
| 新增错题 | `0` | 发布要求 0 |
| 当前线上方案 | 方案名，如「第 2 轮 Winner」，18px 加粗 | 发布时间，浅灰 |

**第二层：**

1. **「进化路径」横向时间线**：Baseline → 第 1 轮（目标：检索层）→ 第 2 轮（目标：生成层）→ D → 发布。每个节点下写一行结论，例如「3 个方案 · 2 个合格 · 修好 4 题」。
2. **「修好 / 仍错」两栏卡片**：
   - 左栏列出修好的题号，绿色题号标签，点击打开问答验证；
   - 右栏列出仍错的题号，红色，附错因层。
3. **「Agent 推理能力」小卡**（E6 新增）：三个百分比大数字，分别是「事先预测命中率」「实际修复覆盖率」「风险预测命中率」。

**要修的问题：**
- 对齐：同一行卡片等高，字段名、数字、说明三层分别对齐。
- 不再出现「Temperature 0 → 未知」。参数变化只在「当前线上方案」卡里显示一次。
- D 的状态严格区分：未晋升（灰）、已推荐待审批、已发布。
- 没有数据的灰色空进度条直接隐藏。

### 4.2 知识库

**首屏**：3 张小 KPI，分别是文档数、切块数、知识库版本（短名）。

**文档表：**

| 列 | 内容 | 样式 |
|---|---|---|
| 文档 | 短名，如「IRB 1300 产品手册 · 第 1 部分」 | 14px 黑；完整文件名放进详情 |
| 设备型号 | IRB 1300 / IRB 1200 | 浅灰标签 |
| 页数 | 184 | 等宽数字 |
| 切块数 | 351 | 等宽数字 |
| 处理状态 | 已索引 | 绿标签 |
| 操作 | 查看 | 蓝链接 |

- 表头固定，滚动时不消失。
- 「文档分类」列如果全是「其他」，整列隐藏。

**文档详情抽屉：**
1. 01 文档信息：型号、页数、来源网址、下载日期；
2. 02 切块浏览：按章节树展开，点切块显示原文卡；
3. 03 技术记录：文件 ID、解析参数，默认折叠。

### 4.3 Golden Dataset

**首屏 KPI**：总题数 50 · 正向 20 · 消融 10 · 负向 20，用一条分段横条表示题型构成。

**题目表**：

| 列 | 内容 |
|---|---|
| 题号 | Q01 |
| 问题 | 最多 2 行 |
| 题型 | 正向·跨段综合 / 消融·口语 / 负向·安全关键 等 |
| 难度 | 简单 / 中等 / 复杂（浅灰文字） |
| 业务主题 | 维护 / 安装 / 维修 / 规格 等；没有值时整列隐藏 |
| 操作 | 查看 |

**题目抽屉（按顺序）：**
1. **01 题目**：完整问题；下面一行浅灰小字写「真实用户为什么这样问」。
2. **02 参考答案**（负向题改叫「预期行为」）：正常答案，按 3.6 节显示。
3. **03 核心证据**：证据引用卡，可以有多张。
4. **04 备注**：只在 `notes` 有内容时出现，浅灰底小卡，标题写「补充信息（不参与评分）」。
