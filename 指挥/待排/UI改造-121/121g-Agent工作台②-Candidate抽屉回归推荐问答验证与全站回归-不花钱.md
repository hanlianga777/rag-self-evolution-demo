## Candidate 抽屉（`DrawerShell`，拆分 `CandidateWorkspace.tsx`）

按以下顺序排列：

1. **方案摘要**：名称、来源（第几轮 / Agent 提出）、底座、资格。
2. **参数变化**：修改前后的值、继承自哪一轮的 Winner。
3. **优化假设**：目标问题、机制、逐题证据。
4. **评测结果**：答对、修好、新增错题、Gate x/11。
5. **预测与实际**：命中、未命中、附带修复。
6. **回归**：逐题回退、性能。
7. **复盘**：一两句。
8. **技术记录**（默认折叠）：
   - 完整请求、账本、运行身份；
   - E5 第 1 轮 A 在这里写「沿用自 E4 第 1 轮评测（用户授权，未重跑）」；
   - 3 次判定明细也放在这里。

D 的抽屉额外显示「相对 Winner 的差异与晋升判断」。

## 回归与推荐 tab

1. 非回退检查用统一表格：题号 / Baseline / Winner / 候选 / 结论。
2. 推荐依据最多 3 条要点。
3. 推荐与发布状态与发布页使用同一份状态映射。

## 问答验证（保留结构，只做微调）

1. **统一字号与组件**
   - 字号、间距接入 token；
   - 引用块用统一的证据引用组件；
   - 答案用 `RichContent`。
2. **「这道题为什么变好」**
   - 参数变化用 `diffParams`；
   - 组合参数的修复不能只归因于其中一项，例如 Q17 要同时写候选数和 Top-K 两项。
