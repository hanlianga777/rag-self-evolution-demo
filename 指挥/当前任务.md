# 任务 002：让 GitHub 上的 main 和本地真实代码保持一致（不花钱）

## 目的
任务 001 发现：本地 main（`fb15504`）比 GitHub main 多 19 个提交，两边已经分岔。GitHub 上现在是旧代码，总指挥看不到真实代码；以后每次"拉取最新代码"也会失败。这次只做一件事：让 GitHub main = 本地最新的代码和文档，同时保证不把任何数据传上去。

## 这次不做什么
- 不修改任何业务代码、数据库、知识库。
- 不调用 DeepSeek 或任何付费模型，不启动 demo、评测或测试。
- 不删除任何本地文件和分支，也不删除远端的 `codex/本地快照-001`。

## 注意
按固定指令"先拉取最新代码"时，`git pull` 会因为分岔而失败，这是预期的，不用处理，直接按下面步骤做。

## 步骤
1. **检查那 19 个提交**：列出它们新增或修改过的所有文件里，有没有以下任何一种：数据库文件、`.env`、密钥、运行数据和运行产物（例如 `output/`、`backend/data/` 下的运行结果、日志、截图、账本、Golden/Judge 的 JSON 数据）、单个超过 10MB 的文件。包括"中间某个提交加了、后来又删掉"的情况。
2. **按检查结果二选一**：
   - **2a. 一个都没有**：把 `origin/main` 合并进本地 main（远端多出的只有 `指挥/` 目录，应该没有冲突），然后推送 main。
   - **2b. 有任何一个**：不要推送这 19 个提交。先把本地 main 改名为 `本地旧main-备份`（只留本地）。再从 `origin/main` 新建 main，把本地旧 main 当前的全部代码和文档放进来，排除第 1 步找到的那些文件，做成一个提交，推送 main。
3. **防止以后误传**：把任务 001 里那 590 个未跟踪文件中属于数据、运行产物、备份、压缩包的路径加进 `.gitignore`（按目录或后缀写规则，不要逐个列文件名）。和第 2 步一起提交。
4. **推送前最后检查**：确认这次要推送的内容里没有第 1 步列出的任何一类文件，也没有超过 10MB 的文件。
5. **推送后确认**：本地 main 跟踪 `origin/main`，两边提交号一致，`git status` 显示工作区干净（被忽略的文件不算）。

## 报告
写到 `指挥/报告/002-代码同步.md`，用大白话，一页以内：
- 第 1 步查到了什么（没有就写"没有"；有就列文件路径和大小）。
- 用的是 2a 还是 2b，为什么。
- 推送后 GitHub main 的提交号；`.gitignore` 加了哪些规则。
- `git status` 的结果。

## 完成标准
- GitHub main 包含本地最新代码（例如 `backend/app/providers.py` 里有 `DEFAULT_TASK_THINKING`）和 `指挥/` 目录。
- 没有任何数据库、数据、密钥、大文件被推送。
- 报告已推送。
