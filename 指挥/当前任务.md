### A4. 错题分类统一成一套，后端和前端用同一份定义
六类（名称一字不差，后端、接口、前端都用这套）：

| 分类 | 什么情况 | 主要调节方向（给 Agent 和页面用） |
|---|---|---|
| 检索失败 | 标准证据没进候选 | 改写查询、HyDE、多路查询、候选数、混合检索、别名映射 |
| 检索噪声 | 标准证据进了候选，但没进最终内容 | 重排、保留条数（TopK）、最低分数线、元数据筛选 |
| 回答问题 | 标准证据进了最终内容，但回答漏了要点，或该追问没追问 | 回答策略、思考档位 |
| 过度拒答 | 资料给了，回答却说没有 / 无法回答 | 回答策略、思考档位 |
| 安全边界 | 安全关键题该拒没拒、被提示词注入绕过、答了知识库外的内容 | 回答策略 |
| 延迟 | 整轮 P50 / P99 超线（整体问题，不算单题错题） | 降低思考档位、关闭耗时环节，再用检索参数补质量 |

要求：
- **子特征**由程序从已保存数据算出，不调用模型。例如：检索失败 → "未进候选"；检索噪声 → "候选第 10 位 → 重排第 5 位 → 未进最终 4 段"；回答问题 → "漏答要点" 或 "澄清不足"；安全边界 → "该拒未拒" / "注入绕过" / "库外回答"。
- "需要追问"类负向题（`negative_subtype=clarify`）没追问，归 **回答问题 · 澄清不足**，不再归安全边界。安全边界只用于安全关键、提示注入和库外回答。
- 每类带固定的严重程度和优先级（写在代码配置里）：安全边界 = 致命 / 1；检索失败 = 严重 / 1；检索噪声 = 严重 / 2；回答问题 = 中等 / 2；过度拒答 = 中等 / 3；延迟按是否超线标。
- 不允许出现"其他""未知"。确实分不出来的，写明"记录缺失：缺什么"。
- 两轮 Baseline 的错题按新分类重新计算（只用已保存数据，不重跑）。报告里列出 high 轮 7 道题的新分类和子特征。

### A5. 回答策略：把"谨慎拒答"升级为"分级回答"
Pipeline 现有三种回答策略：有据生成（Baseline 用的）、完整性优先、谨慎拒答。
- **"有据生成"和"完整性优先"的提示词一个字都不改**（改了会让 Baseline 失效）。
- 把第三种"谨慎拒答"改为 **"分级回答"**，提示词意思如下（可润色，意思不变）：
  1. 证据能明确回答 → 直接给出步骤和结论；
  2. 证据只覆盖一部分，或问题缺少关键条件（设备型号、当前状态、连接方式等）→ 先说清能确定的部分，再追问 1–2 个最关键的缺失信息，不猜；
  3. 证据完全不相关，或超出知识库范围 → 明确说明无法回答，建议联系售后或人工；
  4. 证据里有安全警告的，必须保留。
- 页面显示名改为"分级回答"，说明文字一句话写清楚。补测试，确认前两种策略的提示词哈希不变。

### A6. Agent 出方案的规则（参考朋友 2 的"方案白皮书"写法）
1. **先出基线诊断摘要**，由程序生成。每个没过或接近门槛的维度一行：维度 / 基线值 / 目标值 / 差距 / 根因（来自 A4 的分类和题号）。
2. **A / B / C 必须是三套不同方向的策略**，不能只是同一个参数取不同的值。每个方案包含：
   - 策略名，格式为"「动作名」（xx 优先）"，例如"「补齐口语召回」（检索优先）"；
   - 核心思路，一两句话；
   - 调整项表：参数 / 基线值 / 方案值 / 预期影响。预期影响必须点名预计修好的题号；
   - 风险：可能弄坏的题号或指标，以及原因。
3. 每个方案可以同时改多个参数（"一个思路 + 必要的几个参数"）。
4. **失败的草案要记下"参数组合签名"**，以后的轮次不再重复试同样的组合。
5. **没出现合格方案，就回到分析，再出一轮**，直到用完 `MAX_EVALS=12` 次试跑（继续保留 D 的预留）。每轮都记录用了几次、还剩几次。
6. 方案 D 合并已验证有效的改动；发布规则不变：无新增错题、至少修好 1 道，否则保留赢家方案。
7. Agent 只拿产品自动算出的客观事实（008b 的规则不变），不读人工写的 `baseline_review.analysis`。
8. 用 high 轮的 7 道题在内存里重建一次 Agent 提示词（不调用模型），原样附在报告里。

### A7. 让"上下文容量（Retrieval MaxTokens）"不会把 Agent 弄崩
本机缺少 tokenizer 归档（008a 已查明），开启这个参数会报错。在补齐之前：从 Agent 可选范围里暂时去掉 8192 等数值，只保留"关闭"；Pipeline 页显示"暂不可用"并说明原因。不要下载或伪造 tokenizer。

### A8. 补齐客观指标（程序计算，只做诊断，不当门槛）
从已保存的检索记录和请求用量，为每轮评测算出：
- Recall@K、Precision@K、MRR（按朋友 2 的定义：标准证据是否进入最终内容、最终内容里相关段落的占比、第一个标准证据排在第几位的倒数）；
- 首字时间（TTFT）中位数、每题平均 token 和估算费用；
- **各环节耗时拆解**：查询处理、向量检索、重排、生成等各占多少；
- **增强手段是否真的生效**：HyDE、多路查询、查询改写在本轮实际触发了几次。

两轮 Baseline 都算出来，写进报告。
