# 任务 006：补跑 Probe 和 QC，按正规流程重新冻结题卷（花小钱，分两段做）

## 背景
任务 005B 用"人工审定导入"冻结了新题卷 `GD-20261101083612`，但跳过了产品原有的两步机器检查：Probe（试检索 + 可答性判断）和 QC（模型审题）。页面上显示 Probe 0/50、QC 0/50 就直接"人工通过"，演示时讲不通。

本任务按产品正规顺序重走一遍：**同样 50 道题 → Probe → QC → 确认测试集 → 冻结**，生成一份新编号的题卷，内容与 `005B-数据/定稿50.csv` 完全一致。`GD-20261101083612` 退为历史版本，保留不删。

**本任务允许调用 DeepSeek 和 Embedding**（只用于 Probe 和 QC）。不设费用上限，但报告里写明实际调用次数和费用。

## 这次不做什么

- 不跑 Baseline，不做速度测试。
- 不改前端，不改门槛，不改判分和 Agent 逻辑。
- 思考档位用代码现有默认值（Probe/QC 属于 auxiliary，即"高"档），不要改。

## 为了省额度：分两段做

整轮 Probe + QC 大约 100 次模型调用，会持续较长时间。**你不需要在会话里盯着它跑完。**

### 第一段：准备并启动（用户发固定的那句话时做这一段）
1. 拉取最新代码，确认 demo 正在用 `start_demo.command` 方式运行（8010、5174 正常）。如果没在运行，就用这种方式启动。
2. 用 `定稿50.csv` 的同样内容新建一轮候选，挂在新的生成记录下。如果现有"人工审定导入"入口会因为和旧题卷重复而拦截，做最小修改让它允许"同内容重走机器检查"，并写清楚改了什么。
3. 通过**正在运行的 demo 后台**（不是你会话里临时起的进程）启动这 50 题的 Probe 和 QC，让它在后台自己跑完。
4. 确认前 2–3 道题的 Probe 正常完成（有结果、没报错），然后就结束本段。**不要等全部跑完，不要循环轮询进度。**
5. 在 `指挥/报告/006-机器检查.md` 写一个简短的"第一段记录"：新生成记录编号、启动时间、前几题的结果、如何查看进度（页面位置或接口）。提交并推送。
6. 本段结束时**不要关掉 demo**，后台任务要继续跑。

如果第一段里 Probe 一启动就报错（例如接口不通、密钥无效），停下来，把错误原文写进记录并推送，不要反复重试。

### 第二段：收尾（用户之后单独发"请执行任务 006 第二段"时再做）
1. 拉取最新代码，查看这轮 Probe 和 QC 是否已全部完成。
   - 没跑完：在记录里写明进度（Probe 几/50、QC 几/50），推送后结束，不要等待。
   - 中途有失败的：写明哪些题、错误原文。失败的题只补跑一次；还失败就停下报告。
2. 全部跑完后，汇总结果：
   - Probe：每题是否检索到标准证据、可答性判断结论；
   - QC：每题结论（通过 / 有异议），有异议的写出 QC 的原话理由。
3. **判断是否继续：**
   - **50 题 Probe、QC 全部通过** → 用产品正常的"确认测试集"动作完成确认（确认人记为"用户（对话中确认，Codex 代为执行）"，原因写"任务005红线清单已确认；任务006机器检查已完成"），然后冻结，生成新题卷，并确认它成为当前使用的题卷。
   - **有任何题 Probe 或 QC 不通过** → **停在确认之前**，不要改题，不要确认，把这些题和理由写进报告，交给总指挥判断。
4. 冻结后（如果走到这一步）：
   - 50 题判分合同编译全部通过；
   - 门槛分母和 005B 一致（安全关键 4、提示注入 3）；
   - 导出新题卷为 `指挥/报告/006-数据/新题卷50.csv`，与 `005B-数据/定稿50.csv` 逐题比对一致；
   - 页面上 Golden Dataset 能看到新题卷的 Probe、QC 结果和人工确认。
