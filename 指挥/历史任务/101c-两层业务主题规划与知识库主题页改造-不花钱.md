# 101c：两层业务主题规划（章节业务主题 + 章内 K-means）+ 知识库"知识主题覆盖"只显示这一套（不花钱）

**依据**：用户 11-20 11:22 选定"两层：章节业务主题 + 章内 K-means"。

**背景**：总指挥实测，按子块做全库 K-means 时，一个簇里最主要的章节平均只占 26%。维修步骤的写法高度相似，被聚到了一起，这样分出来的簇不是业务主题。另外，知识库页面现在显示的是系统内置 Coverage Plan（44 簇）：主题名取的是簇内第一个片段的路径，题数列显示的是旧自动出题的"计划题位"，用户看着乱。

**性质**：只用已有的向量做计算，加上前端展示，**不调用任何付费接口**。本单的计算结果会再经 Claude 与 GPT 审核；如需调整，会另发补丁单。

## 1. 第一层：业务主题（按文档和一级章节映射；不参与聚类的前言内容排除在外）

| 业务主题 | 来源 |
|---|---|
| IRB 1200 产品规格 | IRB 1200 产品规格书全部章节 |
| 安全 | IRB 1300 手册第 1 章 |
| IRB 1300 产品说明与规格 | 第 2 章、第 10 章 |
| 安装与调试 | 第 3 章 |
| 维护 | 第 4 章 |

| 标定 | 第 6 章 |
| 故障排除 | 第 7 章 |
| 参考信息、备件与停用 | 第 8、9、11 章 |

- **口径**：基于 101b 的活动索引，按正文去重，排除前言。逐主题列出子块数。
- **正向题配额**：共 20 题。权重 = √（主题去重子块数），按最大余数法分配，每个主题至少 1 题。贴出每个主题的子块数、权重和配额。

## 2. 第二层：章内 K-means

1. 对配额 ≥2 的业务主题，在**主题内部**用已有子块向量跑 K-means：
   - 公式与 golden_v2 相同：k = min(n//40, isqrt(n)+1)，seed 42，n_init 10，小于 3 个子块的簇合并；
   - 只在主题内去重聚类。
2. 该主题的配额按章内簇大小，用最大余数法分配到各簇；优先每簇最多 1 题。
3. **章内簇命名**：取簇内占比最高的编号小节（到第三级为止），写成"<小节名>（占 x%）"。
   - 如果第二名的编号小节占比 ≥25%，就写成"<小节 1> / <小节 2>"；
   - 同一主题内名字重复的，加序号区分。
4. 每个章内簇再算一个**纯度**：最主要编号小节的占比。逐簇列出纯度，并给出各主题的纯度中位数。
