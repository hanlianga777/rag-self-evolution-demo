## 1. 每页一句"这一页解决什么"（克制，只有一句）
8 个页面标题右侧（或标题下方），各加一行**浅灰 12px 小字**，不超过 22 字，说明这一页在闭环里的作用：

| 页面 | 一句话 |
| --- | --- |
| 概览 | 从知识到上线的完整闭环 |
| 知识库 | 说明书变成可检索、可追溯的知识 |
| Pipeline 配置 | 固定底座 + Agent 可调的 12 项参数 |
| Golden Dataset | 50 题冻结考卷，每轮用同一把尺子 |
| Baseline | 当前版本体检：门槛与 Bad Case |
| Agent 工作台 | 按 Bad Case 原因提方案、沙盒比较 |
| 发布 | 程序给资格，人来批准，可回滚 |
| 问答验证 | 优化前后的真实回答对比 |

- 之前删掉的长副标题不要恢复；只用这一句。
- 样式用 `.ui-kicker` 或同等的浅灰小字，不加粗。

## 2. 术语与说法逐页检查
- **混用**：同一概念全站只用一种说法。重点检查以下几组：
  - "Bad Case / 错题 / 失败"；
  - "Candidate / 方案 / 候选"；
  - "回答生成 / Generation"；
  - "Winner / 赢家"。
- **规则**：
  - 行业通用词保持英文：Bad Case、Candidate、Winner、Hard Gate、Top-K、Rerank、P50、P99；
  - "错题"一律改"Bad Case"；
  - "方案"可以作为 Candidate 的中文解释出现在悬停提示里，正文统一 Candidate。
- **英文的内部字段名、代码写法、全大写状态码**：例如 PASS、FAIL、MET、NOT_MET、pending、running。页面显示一律换成中文状态，例如"通过 / 未通过 / 满足 / 未满足 / 等待中 / 运行中"。
- **报告**：用表格列出替换清单。拿不准的不改，单列出来。
