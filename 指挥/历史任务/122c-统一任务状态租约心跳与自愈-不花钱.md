# 122c 统一任务状态、租约、心跳与死任务自愈（ST-03，不花钱）

依据：互审 56 第二节第 3 条。前置：122b 完成。

## 要做的事

1. **业务状态与进程占用分开**：
   - 业务状态：queued、running、retry_wait、recovering、blocked、paused、completed、failed；
   - 进程占用：用「租约」表示，记录 `lease_owner`（pid + 主机名 + 令牌）、`heartbeat_at`、`lease_expires_at`。
2. **心跳**：执行中的任务每 30 秒续一次租约。租约超过 3 分钟没有续，就判定为死任务，安全回收：状态转为 `recovering`，从断点续跑。
3. **以下判断全部改为看租约**，不再只看状态字段：
   - `optimization_cycle.status=='running'`：`optimization_cycle.py:37`、`main.py:2428`；
   - 候选 `queued/running`：`optimization_cycle.py:39`；
   - `external_runner` 永久跳过：`main.py:122`、`optimization_cycle.py:617`；
   - 评测的 owner_pid 和线程判断：`governance.py:2698-2717`；
   - Agent 生成的 claim：`governance.py:2970-3041`；
   - `paid_schedule.py:92-209`。
4. **执行令牌**：所有写入结果的操作都要带令牌。令牌已过期的旧 worker 写入会被拒绝，防止重复写入。
5. **用户停止要持久化**：自动恢复不得把用户停止的任务重新拉起。
6. **兼容历史记录**：`completed` 但 `evaluation_complete=false` 的历史记录，新逻辑一律视为未完成。
7. **单测**（临时数据库）：
   - 进程被 kill 后租约过期，任务能回收并续跑；
   - 两个 worker 抢同一个任务，只有一个能成功；
   - 旧 worker 带过期令牌写入，被拒绝；
   - 用户停止后不会被自动恢复；
   - 旧状态（running 加死 pid、external_runner=True）能被正确回收。

## 约束

- 不调用真实模型。
- 所有测试都用临时数据库。
