## 1. Candidate D 决策区加载时会短暂显示错误结论（最优先）
**现象**：
- 刚进入 Agent 进化路线，D 区"预测 vs 实际"表的"重点盯的受保护题"一行会先显示"0 题守住，8 题待核对"，下面还有"正在读取保存的逐题结果…"；约 5 秒后才变成"8 题全部守住"。
- 面试官如果正好在这几秒里看，会以为 D 没守住保护题。

**原因方向**：`frontend/src/components/EvolutionStory.tsx` 第 165–166 行。读取中被算成了"待核对"。另外 025 调整了预读优先级，D 区需要的逐题结果可能不再提前读。

**改法**：
- 逐题结果还在读取时，这一格显示灰色骨架条，不出现任何数字和"待核对"字样。
- 只有读取真正失败或数据确实缺失时，才显示"待核对"。
- D 区要用到的那一份逐题结果加入预热，并排在高优先级（只限 D 这一份，不要恢复整卷预读）。
- **目标**：概览预热 30 秒后进入 Agent 页，D 区直接显示最终结论。

**同一张表里改一处措辞**："实际修好的剩余 Bad Case：Q04"改为"修好 Q04；Q06 未修好"。题号按真实数据生成；未修好的部分用灰色。

## 2. Pipeline 配置页：让人一眼看出 Agent 改了哪 3 项
**现象**：
- 参数控件里白色选中的是 Baseline 值（Candidate K 12、Top-K 4、Thinking Max），线上的 D 只用一个小蓝点表示。
- 客户会把白色选中理解成"现在线上用的配置"，产生误解。

**改法**：
- **说明行**：在"Agent 可选参数"卡片标题下加一行 13px 说明，例如"当前线上 Candidate D 相对 Baseline 改了 3 项：Candidate K 12 → 24、Top-K 4 → 6、Thinking Max → High"。从保存的配置差异计算，不写死。
- **高亮**：这 3 个参数所在的行加淡蓝底（`--ui-accent-tint`），其余行不变。
- **图例**：右上角图例改成"白底 = Baseline 起点　● 蓝点 = 当前线上"，或在不改变控件交互的前提下用同等清楚的写法。
- **按钮**：页头"查看可选参数"和下方卡片"Agent 可选参数"重名，按钮文字改为"参数说明"，功能不变。

## 3. Hard Gate：标出"压线"的门槛
**现象**：
- Baseline 的安全拒答率是 95%，门槛也是 ≥95%，刚好压线。
- 这正是 Round 1、Round 2 好几个 Candidate 把安全拒答拉到 90% 而被淘汰的原因，但页面上看不出来。

**改法**：
- Baseline → Hard Gate 页签里，实际值与门槛的差距不超过 1 个百分点（耗时类不超过门槛的 5%）的项，在数值旁加一个灰色小标签"压线"。
- 悬停提示："余量很小，后续 Candidate 容易在这一项失败"。
- 判定规则写进报告；按真实数据算，可能只有安全拒答一项。

## 4. 问答验证：页签顺序与讲解顺序一致
**现象**：讲解路线是先看 Before/After 证明效果，再现场提问，最后讲线上反馈；但现在默认打开的是"实时问答"。

**改法**：
- 页签顺序改为"Before/After｜实时问答｜线上反馈 → 再次进化"，默认打开 Before/After。
- 旧链接和 tab 参数继续可用。
- 概览大卡上的"去问答验证"按钮落到 Before/After。

## 5. 线上反馈 → 再次进化：把闭环讲完整
**现象**：
- 这是"自进化"闭环的最后一环。
- 现在页面上有两个重复的空状态（"当前尚无实际问答记录"和"当前尚无反馈记录"），外加一条流程文字，下半页空白。

**改法**（不新增任何问答或反馈记录）：
- **闭环卡**：一张卡，四个节点横排，样式参照概览流程条：
  - 线上问答（附出处）
  - 人工标记 Bad Case
  - 进入下一轮输入
  - Agent 新一轮 → Golden 复测 → 人工发布

  节点文字只写系统实际支持的行为，拿不准的写法在报告里列出。
- **下一轮已知输入**，下面一行说明：
  - "本轮仍未修好：Q06、Q27"（来自保存的回归结果，可点击打开题目）；
  - "线上标记的 Bad Case：0 条"（来自现有反馈记录数量）。
- **空状态**：两个重复空状态合并成一行灰色小字："暂无线上反馈；在「实时问答」提问后，可在这里标注回答是否属于 Bad Case。"
- 有反馈记录时，原来的记录表和操作保持不变。
- 删掉"符合现有触发规则后，再人工确认关联优化上下文"这类内部说法。

## 6. 概览：补上"还没修好的"与几处小细节
- **右侧"修好的 4 道题"卡**：
  - 卡片底部加一行灰色小字"仍未修好：Q06、Q27"，可点击打开对应题目，数据来自保存结果。
  - 诚实地展示剩余问题，是面试加分点，也能把卡片底部补齐。
- **同卡 Q38 行**：右侧缺少参数来源标签，其他三行都有（如"Candidate K 12 → 24"）。按保存的归因数据补齐；如果确实没有归因，就显示灰色"—"，并在报告里说明原因。
- **左侧"优化过程"**：Round 1、Round 2 的文字前面有"本轮经验："前缀，在概览里去掉，左列已有轮次名。
- **44 → 48 大卡**：左下方有一块约 80px 的空白。收紧卡片高度，或把"已发布 Candidate D · 去问答验证"挪到左侧指标行同一高度，让大卡内部没有空洞。
