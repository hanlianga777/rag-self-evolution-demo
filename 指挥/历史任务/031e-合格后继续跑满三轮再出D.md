## 1. 代码：新增"跑满轮次"策略
新增实验字段 `result.round_policy = {"mode": "full_rounds", "max_rounds": 3}`，只对带这个字段的实验生效；旧实验的行为不变。

1. **`optimization_cycle.run_until_qualified`**：`full_rounds` 模式下，出现合格方案时：
   - 不跳过同一轮未跑的 A/B/C，本轮全部跑完；
   - 不提前进入 Gate 2 和 D。
2. **每轮跑完写本轮结论（`conclude_round`）之后**：
   - **继续下一轮**：轮次 < max_rounds，且 A/B/C 剩余预算 ≥ 1（D 保留 1 次）。下一轮仍由 Agent 生成 3 个方向不同的 Candidate；预算不够 3 个时，按剩余预算生成。
   - **结束轮次**：达到 max_rounds 或 A/B/C 预算用完。
     - 有合格方案：走现有的 `advance_qualified`，即 Gate 2 报告确认（actor=用户，audit_note「用户 2026-11-14 预先授权」）→ 生成 D → 跑 D → 停在发布前。
     - 没有合格方案：按现状 `budget_exhausted / review`。
3. **第 2、3 轮的 Agent 输入**：在原有四部分要求之外，补充给 Agent 下面这些事实：
   - 当前最优合格方案（按 `candidate_rank`）的参数；
   - 它剩余的 Bad Case（层、细分类型、题号）；
   - 各项 Hard Gate 实际值，以及和门槛的距离；
   - 它的 P50 / P99。

   要求 Agent 针对"剩余 Bad Case"和"离门槛最近的指标"出方案，可以组合前几轮被证明有效的参数。参数仍相对 Baseline 填写，且必须在白名单内。所有说明文字都必须是 Agent 自己写的，不要预填理由。
4. **"用掉 6 次仍无合格方案 → 效率方向"规则**：保持原样。它只在"还没有合格方案"时生效；本实验已有合格方案，所以不会触发。
5. **`conclude_round`、D 生成，以及所有检查 `strategy_contract == 'agent-strategy-3'` 的地方**：
   - 同时接受 `agent-strategy-4`；
   - `full_rounds` 实验使用 `agent-strategy-4`。
6. **D 的规则不变**（用户 11-14 确认）：
   - Agent 二选一：合格方案部分融合，或 Winner + 被证明有效的参数；
   - 合并前写预计修好的题号，跑完后逐题对账；
   - D 不比 Winner 好，就推荐 Winner。

   D 的输入要包含三轮里所有跑过的方案。
7. **测试**：用 Mock 写离线测试，证明以下四点：
   - 第 1 轮 A 合格时，B、C 照常跑；
   - 第 1 轮跑完进入第 2 轮，第 3 轮跑完才进入 Gate 2 和 D；
   - 预算不足时提前结束且给 D 留 1 次；
   - 旧实验（没有 `round_policy`）行为不变。

   另外跑全部已有后端测试和前端构建。
