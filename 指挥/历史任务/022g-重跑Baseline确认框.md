# 任务 022g：给"重新运行 Baseline"加确认框（不调用模型，自动值班）

用户已授权：中间所有确认默认同意，不要停下来等人。在 022f 之后执行。原有已跑通的功能和按钮一个都不能坏。

## 背景
022e 报告指出：Baseline 页的"重新运行 Baseline（新版本）"按钮（已移到"更多指标"折叠区）点下去直接走启动预检 `prepareStart`，**没有独立确认弹窗**。这是一个会花钱、会产生新正式评测的动作，演示时误点后果严重。

## 要求
- **加确认框**：点击后先弹出现有的 `ConfirmDialog`（与发布、回滚同一个组件），内容写清三点：
  - 会用当前 Pipeline 配置对 50 题重新评测；
  - 会调用模型并产生费用；
  - 不会影响当前线上版本。
- **确认后**才进入原有的 `prepareStart` 流程；取消则什么都不发生，不发任何请求。
- **其他入口一并检查**：全站其余会调用模型的按钮，包括运行 Probe、运行 QC、生成方案、运行 Sandbox、生成 D、实时问答发送以外的批量动作。没有确认框的同样加上，报告列出。
  - 实时问答"发送"按钮**不加**，它是演示本身。

## 测试与验收
- **新增测试**：点击重跑按钮后出现确认框；点取消时 `fetch` 未被调用。
- 相关测试通过；全量前端、后端保持全绿。
- **本任务不真的启动任何评测**：浏览器验收只点到确认框为止，然后点取消。

## 硬性约束
- 不调用模型，不改评测数据，不发布，不回滚。
- 不要运行 git 写命令；不改 `指挥/当前任务.md`；demo 保持运行。
