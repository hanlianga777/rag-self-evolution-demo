## 1. 新增"继承参数"（只对 `round_policy.mode=full_rounds` 的实验生效，旧实验不变）
1. **Agent 输出格式**：第 2 轮起，每个 Candidate 可以多写一个可选字段：
   ```
   inherited_from: "<前几轮某个合格方案的ID>"
   inherited_parameters: { 参数: 值, ... }
   ```
   - `inherited_parameters` 必须是该合格方案改过的参数的子集，值完全一致；
   - `changed_parameters` 只写本方案新增的改动，不写继承来的参数。
2. **最终配置** = Baseline 配置 + 继承参数 + 新改动。
   - 保存时同时保存 `changed_parameters_vs_baseline`，即继承参数和新改动合在一起、相对 Baseline 的完整差异，供 D、发布资格和前端使用；
   - 白名单和取值范围检查用完整差异。
3. **同轮"方向互不相同"**：只检查 `changed_parameters`（新改动），继承参数不算共用。
4. **调整项 `adjustments` 只对应新改动**：
   - 每项的 `baseline_value` 是 Baseline + 继承参数这份配置里的值；
   - 每项必须点名目标题号。
5. **其他校验保持不变**：
   - 和历史方案完全相同的配置仍然拒绝；
   - 预计修好题号、风险、依据、四部分结构等要求不变。
6. **Prompt**：给 Agent 的说明里把上面的格式写清楚，附一个最小示例。

7. **前端**：Candidates 对比页的方案卡上，继承参数显示为一行小字"在 Candidate A 的基础上"，并列出继承参数（灰色）。新改动照常高亮。

## 2. 出方案容错
1. **只修括号**：JSON 解析失败时，先做一次只补括号的语法修复。
   - 扫描字符串外未闭合的 `{`、`[`，按顺序在末尾补上对应的 `}`、`]`；补完能解析才接受。
   - 不改任何内容，不删任何字符。
   - 在审计里记录 `syntax_repair: {"appended": "…", "original_length": n}`。
   - 补完仍不能解析，就照常拒绝并重出。
2. **整轮重出**：`full_rounds` 模式下，如果整轮出方案用尽 4 次（`ProposalValidationExhausted`），循环自动再发起一次全新的整轮出方案，最多再来 2 次。每次失败都保留在审计里，不消耗 Sandbox 预算。
3. **兜底**：仍然失败，并且已经有合格方案时，不要停在 `analysis_exhausted`，而是按"轮次结束"处理：写清"第 N 轮未能生成合法方案"，然后进入 Gate 2（actor=用户，audit_note「用户 2026-11-14 预先授权」）→ 生成 D → 跑 D → 停在发布前。没有合格方案时，维持现状。
