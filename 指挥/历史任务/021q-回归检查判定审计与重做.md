# 任务 021q：回归检查判定矛盾——先审计，再按真实规则修（不调用模型，自动值班）

用户已授权：中间所有确认默认同意，不要停下来等人。在 021p 之后执行。这是发布和面试前的 **P0**。

## 现象（总指挥 11-06 逐页通读时发现，GPT 审核也独立指出）
Agent 工作台 →「回归检查」页签 → 第 3 轮，"3 个候选已保存回归检查"这一段写着：

> 候选方案 A：修复 1 个指定目标；新增严重 0、普通 3 个失败（上限分别为 0、1）。；正式阻断 0 题，资格仍按保存的 回归检查结果判定 保存判定：通过……

有三处问题：
1. **自相矛盾**：普通新增 3 个，上限是 1，却写"保存判定：通过"。
2. **口径不一致**：这段写"新增严重 0"，下面的新增失败表却把 Q13、Q30、Q37 标成"严重退化"。
3. **措辞**：日志腔，而且"候选方案 A"没写是第几轮。

## 要做的

### 1. 先审计（只读），找出真实原因
- **逐层核对第 3 轮 A/B/C 和方案 D**，每一层写清字段来源和实际值：
  - 逐题 PASS→FAIL 清单；
  - 每题的严重级别字段；
  - 规则上限，以及严重、普通各自的子判定；
  - "正式阻断"计数；
  - 保存的 regression 结果；
  - 最终 `release_qualification`。
- **回答以下问题**：
  1. "保存判定：通过"读的是哪个字段？
  2. "严重退化"和"新增严重"是不是两套分级口径？例如影响类型和严重程度。
  3. 第 3 轮 A 的最终资格到底是什么？目前已知 A 是"未通过"，原因是新弄坏 Q13、Q30、Q37，以及安全拒答率、P99 未达标。
- **核对其他轮次**：第 1、2 轮的回归页签有没有同样的矛盾。

### 2. 再修
- **如果是后端判定或保存有错**：
  - 按产品规则修正判定逻辑。规则是：严重新增上限 0，普通新增上限 1，修好的题不能抵消新增退化。
  - 已保存的历史 regression 结果**不改写**，展示时按修正后的逻辑重新计算。
  - 报告里写清差异。
  - **不许只改前端文字让页面好看。**
- **如果后端没错、只是展示拼接错了**：修展示，并统一分级口径，让"严重退化"和"新增严重"指同一件事。
- **任何修正都不能改变已有的最终资格结论**：第 3 轮 C、方案 D 合格，其余不合格。如果审计发现真实资格和现在页面显示的不一致，**停下来写进报告**，不要自行改资格或推荐。

### 3. 展示重做：长段落改成表
回归检查页签里，这段长文字改成一张表，每个方案一行。

- **列**：方案（写成 "Round 3 · Candidate A" 这种格式）、修好、新增严重、新增普通、上限（严重 0 / 普通 1）、Regression 判定、最终资格。
- **判定必须和本行数字一致。**
- 表下一行写规则："严重新增上限 0、普通新增上限 1；修好的题不能抵消新增的 Bad Case"。
- 下面的逐题新增失败表保留。表里的严重级别与上面表格的口径一致。
