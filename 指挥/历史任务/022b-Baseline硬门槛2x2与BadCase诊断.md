## 1. Hard Gate 页签（用户原话："四种不同属性，能不能放成 2×2 的大卡片形式，更加简洁一点？现在要通过滚轮去查看，比较麻烦"）
- **替换**：原来纵向排列的四张长表，换成 `HardGateGrid`。
- **数据**：全部来自现有 Hard Gate 数据，**不写死**。
  - `actual` 和 `requirement` 用页面原来的格式；
  - `ratio` = 实际值占 100% 的比例，延迟类用"实际值 ÷ 60 秒"；
  - `threshold` = 门槛位置；
  - `pass` 用现有判定。
- **组内指标名**：去掉重复的题型前缀。例如"正向（Positive）正确性"在"正向（Positive）"卡里只写"正确性"。
- **验收**：1440×900 下四张卡一屏放下，不需要滚动。

## 2. Bad Case 诊断页签（用户原话："最上面和下面的列表显得有点割裂……要么单纯在上面放一张卡片展示一个好的 UI，要么就完全删掉"）
**总指挥决定：保留，改成归因卡片。** 这页是面试故事的关键一环："评测负责发现问题，Bad Case 分类负责定位问题，配置表负责承接优化动作"。6 个 Bad Case 都能归到层，这正是 Agent 知道该调哪些参数的依据。

- **删除**：顶部"优化优先级"表、一排筛选按钮、单独一行的延迟说明。三者合并成一行 `BadCaseLayers`。
- **四张归因卡**：
  - 检索层 / 生成层：`count`、`severity`、`remedy`（修复思路）都来自原优化优先级表；
  - 安全边界 / 性能：`count` 为 0 时，`note` 写一句事实，例如"安全拒答 95%，本轮无单题问题""P50 16.7 秒、P99 42.2 秒，在 Hard Gate 内"，数字从数据取。
- **筛选**：`active` 和 `onSelect` 接现有筛选状态。点卡片筛选下面的列表；"全部"卡恢复全部。
- **卡片标题行**：改成一句话，"6 个 Bad Case：以单遍结果为准"中的"以单遍结果为准"删掉。"进入 Agent 处理"按钮保留，用 `.ui-btn-tint`。
- **下面的列表精简**：
  - 删掉"判定方式"列：每行都是"单遍判错"，没有信息量；
  - 删掉"优化方向"列：已经在归因卡里写过，同屏信息只出现一次；
  - 保留：题号、问题、分类、缺了什么、严重程度；
  - "缺了什么"列用 `ClampText` 2 行，悬停看全文，这一列给宽一点；
  - 严重程度徽章被裁切的问题一并修好，用 `.ui-verdict` 或 `StatusBadge`，不要出现半截圆角；
  - 每行高度一致。
