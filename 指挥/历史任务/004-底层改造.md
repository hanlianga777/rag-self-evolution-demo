## A. 去掉开发期的授权、审批、等待环节

**删除**：所有"具名授权""预算授权""等待负责人批准""authorize_provider 开关""未知账单就停并等待对账"之类，开发期间为了控制 Codex 调用而加的拦截。代码里大约有 100 处相关字样（`authoriz`、`Owner`、`具名` 等），逐一判断。

**保留**：
1. 单次模型调用的超时；
2. 调用失败或结果未知时，不自动重复发送同一个请求（避免重复扣费），但要直接报错，不能卡在"等待授权"；
3. "最多试跑 12 次"（`MAX_EVALS`），这是产品功能；
4. **产品流程里的三道人工确认按钮**：确认测试集、确认 A/B/C 报告、确认发布。这是演示要展示的产品功能，不是开发期审批，必须保留。

产出：报告里列一张表，写明每个被删或保留的拦截在哪个文件、原来做什么、删除还是保留、理由。

## B. 判分格式出错时自动重判一次

现在判分模型的回复只要格式稍有不对（`scoring_contract.py`、`providers.py` 里大量抛出 `ValueError` 的检查），整题就记为"无法评测"。

改成：
- 格式出错时自动重新判分一次；
- 第二次还出错，才记为"无法评测"，并保存两次出错的原因；
- 重判计入调用次数和费用记录。

不放宽判分标准本身，只是给一次重来的机会。

## C. 每道错题都有明确结论（最重要）

重写错题归因（`diagnostics.py` 的 `automatic_analysis` 一带）。要求如下。

### 判断方法
只用**该次运行保存的检索记录**（`retrieval_trace` 里的 candidates / final，里面已存有原文）、题卷里的**标准证据原文**、已保存的**模型回答和判分结果**，用程序做文字比对。

- 不调用大模型。
- **不依赖当前知识库有没有变化。** 现在 `_current_corpus` 在知识库指纹不一致时直接返回空，导致旧运行无法诊断，这是"显示不出原因"的技术原因之一，要去掉这种依赖。
- 比对用证据原文的文字，不用切块编号（可以做空白、标点归一化）。

### 五类结论
按顺序判断，命中即停：

| 类别 | 适用题型 | 判断规则 |
|---|---|---|
| 1 检索失败（查不到） | 正向、消融 | 标准证据原文没有出现在检索候选里 |
| 2 检索噪声（查到了错的） | 正向、消融 | 证据在候选里，但不在最终交给模型的内容里 |
| 3 回答问题（漏了或写错） | 正向、消融 | 证据已交给模型，但判分为错，且不属于第 4 类 |
| 4 过度拒答（该答却没答） | 正向、消融 | 证据已交给模型，回答却表示"资料里没有 / 无法确认 / 不能回答"（依据已保存的判分结果或回答文字判断） |
| 5 安全边界问题 | 负向 | 该拒绝没拒绝，或不该拒绝的被拒绝（依据已保存的判分结果） |

一道题有多段证据时：任意一段没进候选，就算第 1 类；全部进了候选、但有一段没进最终内容，就算第 2 类。

**兜底**：检索记录缺失、标准证据缺失等情况，结论写"记录缺失"，并写清楚缺的是什么。**任何一道错题的结论字段都不能为空，也不能是"Unknown"。**

### 附带输出
每道题（不只是错题）用程序算三个检索指标，只用于诊断展示，不作为门槛：
- **召回率 Recall@K**：标准证据有几段进了最终内容；
- **精确率 Precision@K**：最终内容里有几段含标准证据；
- **排名分 MRR**：第一段含证据的内容排第几。

### 每类错题的说明和优先级
每类附一句大白话说明。按严重程度排优先级：检索失败 > 检索噪声 > 回答问题 > 过度拒答。安全边界问题单独标为"安全"。

## D. 新的合格规则

`policy.py` 的 `evaluate_regression` / `qualify_candidate`，以及 `evaluation.py` 里调用它们的地方，改成以下规则。

### A/B/C 筛选合格
同时满足以下四条：
1. 11 项门槛全过；
2. 错题总数比 Baseline 少；
3. 至少修好 1 道目标错题；
4. 安全关键题、提示注入题没有新坏的。

普通题新坏几道都不算不合格，但要记录下来，交给方案 D 合并时处理。

### 发布合格（方案 D 或最终方案）
- 11 项门槛全过；
- 相对 Baseline **零新增错题**；
- 至少修好 1 道。

不满足时，结论为"保留赢家方案"：在已合格的 A/B/C 里选错题最少的作为赢家，并记录原因。没有任何合格方案时，结论为"保持 Baseline"。

### 回退复核
某个方案下"新错"的题（Baseline 对、方案错），自动再跑 2 次（重新生成回答 + 重新判分）。3 次里错 2 次以上，才算真的新错；否则记为"偶发波动"，不计入新增错题。
- 复核次数和费用要记录。
- 这次只实现，不实际运行，用假数据的测试验证逻辑。

### 验证（不花钱）
用 10-22 Recovery 轮（`EXP-RECOVERY-20261022T0649135884120000`）已保存的 A/B/C 结果，按新规则重算一次（不做回退复核，因为它要花钱），写进报告：
- 旧结论 vs 新结论；
- 各方案修好几道、新坏几道；
- 新坏的题里有没有安全题。

## E. Agent：对照表 + 动作名称 + 精简提示词

1. **15 个可调参数全部保留**（`ALLOWED_SEARCH_SPACE` 不删项）。
2. 给 Agent 一张"错题类型 → 优先尝试的参数"对照表：

   | 错题类型 | 优先尝试的参数 |
   |---|---|
   | 检索失败 | 改写查询、HyDE、多路查询、候选数、混合检索及其比例、别名映射、查询拆解 |
   | 检索噪声 | 重排、TopK、最低分数线、元数据过滤、检索长度上限 |
   | 回答问题 / 过度拒答 | 回答策略、思考档位 |
   | 速度门槛不过 | 降低思考档位、关闭耗时环节（HyDE、多路查询等），同时用检索参数补质量 |

   这是"优先"，不是"只能"。
3. **一个方案 = 一个思路 + 必要的几个参数**，可以同时改多个参数（例如"降档 + 加大候选数"）。
4. 每个方案输出时多存一个字段 **动作名称**，用中文短语概括这个方案，例如"加大候选池 + 放宽 TopK""关闭深度思考 + 多路召回补质量"。页面怎么展示以后再定，这次只存数据。
5. **精简 `optimization.py` 里给 Agent 的提示词。**
   - 现在一段两千多字的规则要删减到只剩这几样：目标、错题清单（含五类结论和理由）、对照表、可调参数和允许值、上一轮结果、输出格式。
   - 删掉互相打架和防御性的规则（例如大段关于 Unknown、exploratory、coverage_obligations 的说明）。
   - 参数合法性校验保留在程序里，不需要写进提示词。
6. **验证（不花钱）**：用 10-27 Baseline 的 12 道错题和新归因结果，拼出新的 Agent 提示词全文，存到 `指挥/报告/004-数据/agent提示词示例.md`，并统计新旧提示词各多少字。**不要实际调用模型。**
