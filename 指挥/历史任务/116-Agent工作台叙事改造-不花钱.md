# 116 Agent 工作台叙事改造（不花钱）

**防卡住（必须遵守）**：
- 每次开始先查真实状态，从断点接着做。
- 后台作业运行期间，用 `sleep 60` 轮询等待，不要提前结束这次运行。
- 原本要点按钮的流程，直接调用接口。
- 遇到报错先自己修；实在修不了就写进报告，然后完成本单。
- **不启动任何原生浏览器**（本机会出现 SIGTRAP），验证一律用接口和 DOM 检查。
- 每完成一个小步骤就提交一次。

**依据**：`指挥/互审/35`、`36`、`37`，规则总表 2026-11-23 08:55 条款。

目标：让人一眼看懂 Agent 每一轮在做什么、为什么这么做，以及怎样一步步接近答案。

1. **首屏双曲线**：横轴依次为 Baseline、第 1 轮、第 2 轮、第 3 轮、D。
   - 一条线是"本轮最好成绩"，可以上下起伏；
   - 另一条线是"累计合格 Winner"，只有出现合格方案时才更新；
   - 每个点标出合格数、稳定修好的题号（来自 115）、被拦下的原因。
2. **首屏摘要**：
   - 当前 Winner；
   - 已确认的修复（稳定 / 不稳定）；
   - 剩余问题及其所在环节；
   - Agent 是否主动停止，以及停止原因。
3. **跨轮因果链**：每轮用固定六格展示：本轮假设、继承了什么、排除了什么、验证结果、结论、下一步，并用箭头连接到下一轮。被机制校验拦下的方案也要显示出来，标明"被拦原因"。
4. **账本抽屉**：参数 × Bad Case 矩阵，状态分为修好、弄坏、无效、未知、组合不可归因，点击可查看证据排名变化。抽屉入口放在次级位置，不占首屏。
5. **改造前后对照**：E2（改造前）和 E3（改造后）并排展示，对比合格率、被机制拦下的方案数、预测命中率、是否主动停止。
6. **结局卡**：
   - 推荐方案；
   - 稳定性复测结果；
   - 能力边界（例如 Q15）；
   - D 的结论；
   - 发布建议（状态显示"等待用户决定"）。

所有数字都必须从保存的数据推导，不得写死。前端测试和构建都要通过，用 DOM 检查覆盖 Agent 工作台的各个 tab。

**交付**：`指挥/报告/116.md`，首行写 `116：双曲线/摘要/因果链/账本抽屉/改造前后对照/结局卡 完成=是`
