## 2. 逐题对比 CSV

- 题号、题型、出题方式；

  - 回答耗时（秒）。

## 3. 随机性检测（重点）

只用已保存的数据回答，给出数字和题号：

1. **对错翻转的题**：每个 Sandbox 相对 Baseline 翻转的题（对→错、错→对），逐题归为 (a) 最终资料集合变了；(b) 资料相同，但思考档位或生成参数变了；(c) 资料和生成参数都相同，只是顺序或格式不同。
   - (c) 类附上两次判分理由原文。
   - (b)、(c) 类再标明回答文本是否相同。如果回答完全相同而判定不同，就是判分随机，附 3 次判分原文。
2. **回答完全相同的题**：判定是否都一致？不一致的列出题号和 3 次判分原文。
3. **Judge 3 次的一致率**：每个 Run 有几题 3 次结论不一致。
4. **检索阶段的模型调用**：query_rewrite、multi_query、hyde 有没有开启。开启时，同一题的改写结果是否影响了证据。

## 4. 第 1 轮 Agent 分析（原文导出）

- **输入**：Agent 实际拿到的字段和条数，包括是否含 `issue_tags`、门槛、速度事实、最慢题。
- **思考设置**：thinking 或 reasoning 设置，返回的 reasoning 长度。不贴推理原文。
- **本轮整体策略**：原文全文。
- **A/B/C 每个 Candidate**：
  - 改了哪些参数；
  - 理由原文；
  - 事先预测原文：修好哪些题、可能弄坏哪些题、风险；
  - 预测的保存时间早于 Sandbox 开始时间的证据；
  - 实际结果：修好、新坏、仍错各是哪些题。
- **事后对账原文**：如果已经保存。
- **规则符合情况**：每个 Candidate 最多改 2 个参数；A/B/C 方向不同；检索没变时不归因给检索参数；预测在运行之前保存；输出为中文。
- **花费**：调用次数、token、估算费用。
