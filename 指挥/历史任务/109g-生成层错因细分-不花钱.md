# 109g 生成层错因细分（不花钱）

**问题**：Agent 的输入里，Baseline 的两道生成层错题都被归成了"答案出现幻觉"，但两道题的真实错因不同：
- **Q15**：107 已查明是**读表归类错误**（36 个月的项目被算进了 12 个月），应该对应 TableCheck；
- **Q05**：概念混淆，再加上"说明书里没有给出"这样的**错误否定**，应该对应 Grounded。

这两道题的错因写不准，Agent 就会选错手段。现在的规则在 `backend/app/diagnostics.py:283-304`。过度拒答的正则里没有"说明书"这个词，所以 Q05 没被识别出来，落到了"幻觉"。

## 要做的事

1. 在 `diagnostics.py` 的生成层分支里，**按以下顺序**细分 subfeature。判断依据只能用已保存的回答、Judge 的 issues 和理由、标准证据，**不调用模型**：
   - `表格读取或归类错误`：标准证据中至少有一条是表格行格式（含 `|`，或"项=值；…"这类多列结构），并且 Judge issue 是 contradiction 或 unsupported，涉及数值、周期、数量或清单（理由或回答引文里出现数字、周期、"项"、"个"）；
   - `错误否定（资料有却说没有）`：回答里有实质性内容，同时又出现"说明书/手册/资料/文档…没有/未给出/未提到"之类的否定，而且被否定的对象出现在交给模型的 Final 资料里（可以复用 106 的机械初筛思路）。正则里补上"说明书"。如果回答整体是拒答，仍归入原来的"过度拒答"；
   - `漏子问`：召回成功，但回答漏掉了参考答案里的必答要点（"（补充）"要点不算），并且题目里含有多个子问（问号多于 1 个，或出现"和""以及""分别""各"）；
   - 以上都不符合时，保持原有分类（答案出现幻觉、安全提示丢失、召回成功但答案漏要点）。
2. 在 `diagnostic_categories.py` 的生成层 directions 和 repair_hint 中补充对应关系，并同步到 Agent 说明里的"诊断→动作对照"（109b 已经写过的部分，口径要统一）：
   - 表格读取或归类错误 → TableCheck；
   - 错误否定 → Grounded；
   - 漏子问 → Stepwise。
3. 只读重算 Baseline `EVAL-20261120213645613191` 五道错题的诊断，报告每题的前后对比。预期 Q15 → 表格读取或归类错误，Q05 → 错误否定。如果结果和预期不同，就如实写出原因，**不要为了符合预期去改判断条件**。
4. 不改任何已保存的成绩，不改 Judge。诊断只用于展示和作为 Agent 的输入。新实验从第 1 轮开始就使用新的诊断。
5. 补测试，覆盖三种新细分类型各一个正例、一个反例；109f 的守卫测试仍须通过。
