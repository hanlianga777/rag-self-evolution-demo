# 任务 021z：全站列表一次预加载，切换筛选和页签不再重新加载（不调用模型，自动值班）

用户已授权：中间所有确认默认同意，不要停下来等人。在 021y 之后执行。原有已跑通的功能和按钮一个都不能坏。

## 用户 11-08 07:30 原话
"我点击正向题、负向题、消融题的时候，画面不要加载这些，全部都预存好，不要每次都加载，显得很卡。""所有列表都一样的。"

## 已查明的原因（以 Golden 题表为例）
- `GovernancePage.tsx` 第 60 行把筛选拼进了接口地址：`listPath = …&status=…&group=positive`。
- `usePagedCandidates` 按地址分页，每页 30 条。
- 所以每点一次筛选按钮，都要重新请求后端、显示骨架屏，再滚动加载剩余的题。

数据量其实很小：冻结题卷 50 题，候选池也只有约一百条，完全可以一次拿全。

## 要求
### 1. 统一原则（所有列表、表格、筛选、页签）
- **一次拿全，本地筛选**：
  - 列表数据在页面第一次打开时**一次性读全**（不分页，或后台把剩余页自动读完）；
  - 之后切换筛选（全部 / 正向 / 消融 / 负向 / 机器合格 / 待处理……）、切换页签、切换轮次（Round 1/2/3）、搜索，**全部在浏览器内存里过滤**，不发请求，不出现骨架屏或"正在读取"。
- **缓存跨页面保留**：离开页面再回来，直接用内存或现有 `cachedJson` / `goldenCache` 里的数据先显示，后台静默刷新。只有 `data_version` 变了才替换。
- **预取**：
  - 进入页面后，空闲时把各筛选下要用的数据预取好；
  - 对常点的详情（题目详情、方案详情、Bad Case 详情），鼠标悬停在行上约 150ms 就预取，点击时直接显示。
- **滚动加载**：数据量 ≤ 200 行的列表，取消"滚动到底再加载 30 条"，直接渲染全部；超过 200 行的保留分页，但筛选仍在本地进行。
- **数字一致**：筛选按钮上的数字（例如"正向 20"）和点击后显示的行数必须一致。

### 2. 逐个检查的列表（至少）
- Golden：当前测试集的筛选、候选池的筛选（全部 / 可用 / 待治理）和搜索；
- 问答验证：Before/After 左栏（修好的 / 仍未修好 / 全部）和搜索、线上反馈列表；
- Baseline：Hard Gate、Bad Case 诊断的筛选和分页；
- Agent：Sandbox 轮次切换、A/B/C/D、Regression Check、进化路线卡片点开的方案详情；
- 发布：版本历史；
- 知识库：文档列表搜索、主题详情；
- 所有抽屉里的分页和筛选。

**每个都要实测**：打开浏览器开发者网络记录，切换筛选或页签时，网络请求数应为 0（首次进入页面和后台静默刷新除外），画面不闪骨架屏。

### 3. 不变的东西
- 后端接口不删，可以保留分页参数供以后用，但前端不再按筛选反复请求。
- 已冻结题卷只读、各按钮的权限和确认框逻辑不变。
