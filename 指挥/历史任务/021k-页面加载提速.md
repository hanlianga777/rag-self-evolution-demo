# 任务 021k：页面、页签、抽屉加载提速（不调用模型，自动值班）

用户已授权：中间所有确认默认同意，不要停下来等人。

## 用户要求
点一级导航、切换任何页签、打开任何抽屉，现在背后都要加载很久。用户要求：只要不是网络问题，切换过去就要**立刻显示**。

## 要做的

### 1. 先测量，找出真正的慢点
- 用真实前后端，在 1440×900 下逐个打开并记录：
  - 8 个一级页面；
  - Agent 工作台的 6 个页签；
  - Baseline、Golden 等页面的主要页签；
  - 常用抽屉：题目详情、方案详情、证据、配置。
- 每一项记录：
  - 首次打开时，主要内容出现的耗时；
  - 再次打开时的耗时；
  - 背后发了哪些请求：条数、单个响应大小、各自耗时、是不是串行等待。
- **注意**：现在没有活动评测。测量时如果出现活动评测，不许读取它的进度或逐题结果。

### 2. 按测出来的原因修，常见方向供参考
- **前端缓存**：同一接口的结果先显示缓存，后台再静默刷新。已完成的评测、历史方案、冻结题卷这类**不会再变的数据**，可以长期缓存。
- **只取需要的字段**：列表和主画面用轻量接口；完整逐题结果、检索 trace 这类大数据，只在打开抽屉或详情时才取。取过之后缓存。
- **后端缓存**：已完成记录的展示投影按记录版本缓存，不要每次请求都重算。加 gzip 压缩。
- **并行和预取**：互不依赖的请求并行发。空闲时预取下一个可能要看的页面数据。鼠标悬停在"查看详情"上时预取抽屉数据。
- **运行中的数据**：正在跑的评测等数据保持现有刷新节奏，不能因为缓存显示过期太久的状态。

### 3. 目标
| 场景 | 目标 |
| --- | --- |
| 已打开过的页面、页签、抽屉，再次打开 | 100 毫秒内显示 |
| demo 启动后，第一次打开任一页面 | 主内容 1 秒内显示 |
| 抽屉打开 | 300 毫秒内显示主内容 |

大数据可以先显示骨架，但**不能整页白屏或一直转圈**。
