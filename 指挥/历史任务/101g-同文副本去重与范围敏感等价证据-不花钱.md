# 101g：同文副本去重（候选池阶段）＋ 范围敏感的等价证据（不花钱）

**依据**：

- GPT 终审修订意见（定稿见 `指挥/互审/15-…`）。

**必须在第一次检索型探针（102）和 Baseline 之前完成。**

**性质**：改代码、补测试，不调用付费接口。规则指纹会变化。

## 背景

101f 的 1,883 个子块里，按两种口径统计重复：

| 口径 | 处于重复组的子块 | 组数 | 冗余数 |
|---|---|---|---|
| 原文严格相同 | 618 | 182 | 436 |
| NFKC 归一化并去空白后相同 | 720 | 203 | 517 |

原因是手册在不同小节里逐字重复了同一段程序。例如"轴 3 电缆保护器"的处理步骤，在 5.3.1、5.4.2、5.5.1、5.7.2 等 8 个小节里都有。

## 1. 同文关系表（版本化）

1. 采用"NFKC 归一化并去空白后相同"的口径，建立同文组。报告里两种口径的数字都写上。
2. **范围兼容**才允许合并：同一产品（同一份手册系列）、同一个文档号。IRB 1200 和 IRB 1300 之间即使文字相同，也不合并。
3. 同文关系表按 `knowledge_identity` 保存，并带版本号 `equivalence_version`。它只用于当前知识库；旧 run 的结果不重新解释。

## 2. 检索：在候选池阶段去重，不是重排之后才去重

修订后的流程：

1. 向量检索和 BM25 召回时，原始候选数取 candidate_k × 3。
2. 按同文组合并：每组只留**本次查询融合分最高**的那一份作为代表。**不准按最小 ID 选代表。** 代表凑满 candidate_k 个不同内容为止。
3. 之后照旧：Rerank → MinScore → TopK → Parent Expand → 生成。
4. trace 中记录每个代表对应的同文副本：原始 ID、分数、章节路径。这样诊断时能分清一条证据是没召回、被合并了，还是被排序淘汰了。
5. Baseline 和所有 Candidate 都用同一套去重规则，不能中途切换。规则总表四.1 新增一条"候选池同文去重（开）"，rules.py 同步，规则指纹更新。

## 3. 等价证据：分两层判定，所有地方共用一份

1. **内容等价**：召回块与标准证据块在同一个同文组里。
2. **范围等价**：在内容等价的基础上，召回块还要满足题目限定的范围，即和标准证据块在同一个编号小节（第三级；只有更浅编号时取最深那一级），并且型号、版本相同。
3. **严格等价 = 内容等价 + 范围等价**。只有严格等价才能算"标准证据已召回"，才能用于覆盖结论。
   - 只有内容等价、范围不同的，记为"同文其他来源"，只用于辅助分析，不能补足 Golden 证据。
4. 以下各处必须共用同一份版本化的等价关系，口径一致：
   - `retrieval.py` 的 evidence_coverage；
   - Recall 计算；
   - Judge 的证据观察；
   - `diagnostics.py` 的 Bad Case 定位。

## 4. 测试

**正例**：
- Q08/Q28：在 5.5.1 召回的副本算严格等价；在 5.3.1 召回的副本只算"同文其他来源"。
- Q17/Q24：同文副本也按上面规则判定。

**反例**：
- 文字相似但型号不同，不合并；
- 文字相似但安全条件不同，不合并；
- 跨产品的相同文字，不合并。

**其他**：
- 候选池去重后，多样性（不同内容数）提升，用 Q08、Q17 的查询各贴一次前后对比；
- 旧 run 的详情不受影响；
- 规则一致性测试、`rules_e2e_check.py` 通过。
