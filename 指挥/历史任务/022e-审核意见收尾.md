## 1. Bad Case 诊断"缺了什么"列是 Judge 原始理由（最重要）
- **现状**：列里显示的是判分模型的原文，夹杂 Required、verdict、FAIL、AtomicResults、NOT_MET、Forbidden 等内部英文词，像日志，面试时很扎眼。
- **改法**：用已保存的逐条要点判定，由程序拼成一句人话：
  - 缺一条：`缺要点 ①：只在室内存放设备`；
  - 缺多条：`缺要点 ①③`，悬停时列出每条要点原文；
  - 违反禁止项时写 `触犯禁止项：……`；
  - 负向题该拒答没拒答，写 `应拒答 / 应追问，但给出了操作步骤`（按题型和已保存的判定）。
- **只换展示**：Judge 原文不删，放进 Bad Case 详情抽屉里单独一张"判分原文"小卡片，默认折叠。
- **其他地方同样处理**：Agent、Regression Check、问答验证中，凡是直接显示 Judge 原文的位置，都按同样规则换成人话。报告列出位置。

## 2. Agent 推理原文里的代码写法
- **现象**：推理原文里出现 `top_k`、`high`、`safe_rejection`、`candidate_k=24`、`p99`、`multi_query` 等写法，例如 Candidate D"Agent 当时的预测"、A/B/C/D 卡片的预期效果和风险。
- **改法**：只在**页面展示时**做一次替换映射，保存的原文不改：

  | 原写法 | 页面显示 |
  | --- | --- |
  | top_k | Top-K |
  | candidate_k | Candidate K |
  | multi_query | Multi-Query |
  | high / max / low | High / Max / Low |
  | safe_rejection | 安全拒答率 |
  | p99 / p50 | P99 / P50 |
  | `=` 连接的参数（例如 `candidate_k=24`） | `Candidate K 24` |
- 映射表写在一个公共函数里，全站复用；单元测试覆盖上面这些写法。
