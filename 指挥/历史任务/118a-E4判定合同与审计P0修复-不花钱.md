## 一、接口约定（Claude 定，照此实现）

### 1. 最终判定层（唯一结果来源）

新增模块 `backend/app/verdict.py`。按 run 保存每题的最终判定，可以是新表或现有表新增字段，由你决定，但必须能保存以下内容：

```
question_id, run_id, final_passed(bool), samples: [
  {sample_no: 1|2|3, source: 'sandbox'|'recheck'|'baseline_original'|'baseline_recheck',
   passed, rubric_scores, risk(bool, 严重违规), answer, decompose_ref,
   candidates, reranked, final_context, generation_request_sha256,
   judge_raw, latency_ms, diagnostic_id}
], rechecked(bool), recheck_reason('changed_vs_baseline'|'changed_vs_winner'|None)
```

- `final_passed` 的规则：
  - 有 3 份样本时取多数；
  - 只有 1 份样本时以这 1 份为准；
  - 任一样本 `risk=True` 时，资格判定按不合格处理，多数票不能抵消。
- 提供 `final_verdicts(run_id) -> {question_id: final_passed}`。所有消费方都改为调用它，不再直接读保存的 `passed`：
  - `agent_mechanism.saved_passed`；
  - `optimization.py` 的错因分布、剩余问题、继承收益（约 955–1010 行）；
  - 参数效果账本；
  - Regression；
  - `policy.qualify_candidate`；
  - `evaluation.finalize_saved_candidate` 中 D 的非回退比较（约 1267–1310 行）；
  - 推荐。
- 旧实验（E2、E3 等）没有判定层记录时，回退读取原 `passed`，原成绩不重算。

### 2. 复核规则（资格版本 2026-11-24）

**Baseline**（118b 使用）：
- 样本 1 为原正式运行 `EVAL-20261120213645613191`；
- 再补 2 份新样本；
- 每题都有 3 份样本。

**方案**：
- Sandbox 跑完后，第 1 份为 Sandbox 本身。
- 凡 `sample1.passed ≠ Baseline.final_passed` 的题，再补 2 份，合计 3 份。
- **不是补 3 份**，不允许出现 4 份。

**D**：
- 复核条件为"与 Baseline 最终判定不同"或"与 Winner 最终判定不同"，满足任一即复核。

**补样本的要求**：
- 拆问复用本实验固定的拆问结果（见第 3 条）；
- 生成和 Judge 绕过请求缓存，每份使用独立的 `diagnostic_id`；
- 完整保存第 1 条里列出的全部字段。现有 `_diagnostic_trials` 只存了 passed、risk、judge、usage，需要补齐。

**11 项门槛**：
- 复核过的题，每个维度取 3 份样本的中位数；
- 没复核的题，用那 1 份样本；
- 然后照原公式算全卷平均；
- 延迟只用第 1 份完整试跑的数据；
- 门槛数值一律不改。

**资格条件**：11 项门槛全过、无严重风险、新错 = 0、修好 ≥ 1。新错和修好都按最终判定计算。

### 3. 拆问固定

- 同一实验内，每道题第一次拆问的结果持久化。之后所有方案和所有补样本都复用这份结果，不再调用模型。
- `bypass_reuse()` 不得绕过这一层。

### 4. 禁止历史复用（扩大范围）

- `parameter_effect_ledger.historical` 必须为空，校验器拒绝非空的情况。
- E4 及以后新建的实验，`request_reuse.matching_configuration()` 只能命中**本实验内**的运行。不得复用 E2、E3 或其他实验的答案、判分、成绩。
- 允许使用的范围：
  - 冻结题卷和知识库；
  - 118b 指定的原 Baseline 样本；
  - 本实验产生的结果；
  - 用当前知识库重新执行的检索预演。

### 5. 开跑条件强制执行

- `LAUNCH.min_bad_cases = 5` 改为在 `create_experiment` 处强制执行：Baseline 最终判定的错题数小于 5 时，拒绝创建实验，并返回明确原因"需按二.7 加难"。
- 加难本身不在本单范围内。

### 6. 删除三档策略

- 从 `PIPELINE_VALUES['prompt_strategy']` 和 Agent 可选范围中删除 Stepwise、Grounded、TableCheck。
- 保留显示历史记录所需的常量。
- 新方案如果选用这三档，校验器拒绝。

### 7. 规则版本与兼容

- 把 `RULES_VERSION` 和资格版本改为 `2026-11-24`。
- 把 `rules.py` 与规则总表末尾 JSON 同步（含六.2、六.5、七.2 的正文描述）。
- 原 Baseline 必须仍能作为 118b 的样本 1 被读取。
- E2、E3 的资格判定保持原版本结果，不被自动重算。
- 不兼容的 run 禁止原地续跑。

### 8. 停止分支

- 一轮允许少于 3 个方案，甚至 0 个，前提是 Agent 输出了"证据不足以继续"。不得为了凑满 A/B/C 而生成没有依据的方案。
- 确认 `optimization_cycle.staged_decision()` 覆盖以下情况：
  - 第 4 轮；
  - 零合格；
  - 预算耗尽。

### 9. CI

在 `.github/workflows/rules.yml` 中增加两项：
- 本单新增的测试文件；
- 已登记失败清单检查：用 189b 的 224 条失败登记作为基线，后端全套测试新增失败数必须为 0。

如果全套测试太慢、不适合放进 CI，就把检查做成 `backend/scripts/check_no_new_failures.py`，在报告里给出本地运行结果。
