# 任务 020a：修复"前几轮复盘"校验的类型误判，并让 Agent 循环接着跑第二轮（自动值班）

## 现在出了什么事（总指挥已用只读接口核实）

- 新实验 `EXP-20261105143048349606` 第一轮 A/B/C 已全部跑完，预算 3/12。
- 第二轮出方案时，Agent 连续 3 次被系统拒绝，循环在 2026-11-05 17:01 UTC 停在 `analysis_exhausted`，报错：
  "前几轮复盘每套须写改动、修好/弄坏题号、证据原因、结论"。
- 根因：`backend/app/optimization.py` 第 116 行 `validate_prior_round_review` 要求 `plans[].changes` 必须是**字符串**；Agent 三次都把改动写成了**对象**，例如 `{"candidate_k":24,"multi_query":2}`。内容本身是对的（题号、证据、结论都写全了），只是格式类型不一致。第 277 行给 Agent 的提示也没说 changes 必须是字符串。
- 这是我们自己的校验 bug，不是 Agent 没复盘。

## 要做的

1. **修校验**：`changes` 接受"非空字符串"或"非空对象（参数名→新值）"两种写法。其他字段（evidence_reason、conclusion 为非空字符串；fixed_question_ids、new_failure_question_ids 为列表且须与保存结果一致；conclusions、review_conclusion_ids 引用）规则不变。
2. **顺手查同类问题**：只查"复盘 / 出方案 / D 组合 / 推荐"这几处 Agent 输出校验里，有没有同样"内容对、只是类型写法不同就整轮拒绝"的地方（比如数字写成字符串、单个题号没包成列表）。有的话照同样原则放宽**类型**，并在报告里逐条列出。
   - **不许放宽任何业务规则**：A/B/C 三个方向不同、恰好一套效率方案、同轮参数互斥、质量方向不得降 Thinking、照搬伤害门槛的完全相同配置要拒、D 必须有合格 winner 且要胜过 winner、题号必须与保存结果一致——这些全部保持原样。
3. **补测试**：临时库测试覆盖 changes 为字符串、为对象两种都通过；为空字符串、空对象、缺失仍被拒。
4. **重启后端**装上修复（当前没有正在跑的收费作业，循环已停）。重启前后确认无活动评测。
5. **续跑**：对同一实验调用一次 `POST /api/experiments/EXP-20261105143048349606/run-cycle`，body 为 `{}`（不要带 current_round_only）。不新建实验，不改第一轮结果，不清预算。无人值守授权保持开启。
6. **确认后就结束**：看到第二轮方案生成通过、第一个 Sandbox 新完成 2–3 题且技术失败为 0，就写报告结束。不要守着跑完。
   - 如果第二轮又被拒，且原因仍是"内容对、只是类型/格式写法"问题：可以按第 1–2 条原则再修一次、再续跑一次（最多再一次）。
   - 如果被拒原因是业务规则（方向、互斥、Thinking、照搬等）：不要改规则，原样续跑一次让 Agent 重出；还不行就在报告写清楚原文原因，结束。
