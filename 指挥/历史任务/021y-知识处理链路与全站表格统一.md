  | 步骤 | value | meta |

## 2. 全站表格 / 列表统一（重点）
**范围**：8 个页面所有页签，以及所有抽屉、弹窗里的 `<table>` 和长得像列表的表格。至少包括：
- Golden 当前测试集题表、候选池表；
- 知识库文档列表、主题详情；
- Baseline 的 Hard Gate 表、Bad Case 诊断表、更多指标里的耗时表；
- Agent 的 A/B/C/D、Regression Check、Sandbox 高级指标；
- 发布页版本历史与回滚表；
- 问答验证线上反馈表；
- Pipeline 的"查看可选参数"抽屉；
- 各详情抽屉里的表。

**逐张表执行**：
1. **删掉页面 CSS 里和新样式冲突的旧规则**：表头灰底、外框、粗表头、不同的行高 / 内边距 / 字号。`extra.css` 的全局样式是唯一标准。
2. **列内容精简**：
   - 题号列加 `className="id"`；
   - 题型、出处、时间这类次要信息加 `className="muted"`；
   - 数字列（分数、条数、耗时、百分比）加 `className="num"` 右对齐。
3. **整行可点的表**（例如 Golden 题表点行打开详情）：
   - 删掉"操作 / 查看详情"列；
   - 行尾加一个窄列，放 `<span className="ui-row-go"><Icon name="go" size={15} /></span>`；
   - 保留键盘 Enter 打开。
   - 行内有多个按钮的表（例如回滚）保留按钮列，但按钮用 `text-button` 小字。
4. **对 / 错、通过 / 未通过**：统一用 `<span className="ui-verdict ok|bad">对</span>`。错因（检索层 / 生成层）放在后面的 `<small>` 里。不再出现"错 · 检索层问题"这种长串。
5. **长文本列**（问题、理由）：一行省略，悬停看全文（沿用现有 `TruncatedText` / `ClampText`），不要两行挤在窄列里。
6. **列宽**：问题这类主文本列占剩余宽度，其他列按内容给固定窄宽；1280px 下不出现横向滚动。
7. **Golden 题表的具体要求**：
   - 题型只写"正向 / 消融 / 负向"短词，表头上方的筛选按钮保留完整写法；
   - 出处用短名，例如"操作说明 · p54–55"；
   - 评分要点写"2 条"。
