## 本单范围（方案 #19、#21–#28）
1. **#19** Golden 当前测试集和候选池两个列表加列：
   - 主题簇；
   - 题型（正向 / 消融 / 负向）；
   - 负向子类（证据不足 / 需要追问 / 安全关键 / 提示注入），正向和消融题显示"—"；
   - 考查环节（检索 / 生成 / 安全）。

   要求：
   - 候选池尽量丰富。列多时允许横向滚动表格本身，但页面不横向滚动。
   - Probe、QC 列头加"i"，文案见"文案"第二节，写明 Probe 由程序完成、QC 由模型完成。
2. **#21 Baseline 报告的 Bad Case 卡**：
   - 改名"Bad Case"，标题不写数量；
   - 各行在卡内均匀分布，不上挤下空；
   - 每行显示"层 · 细分类型"，细分类型见"文案"第四节。

   细分由后端根据保存的检索记录按规则判断，不调用模型。规则：
   - 候选里没有标准证据：关键证据没找回来；
   - 候选里有，但在 Top-K 之外：排名靠后被截掉；
   - 交给模型的资料里相关段占比很低：找回的大多不相关；
   - 已交给模型但仍缺要点：证据给到了却漏了要点；
   - 其余按判分标记。

   判断不了的只显示层名。规则和测试写进后端，作为只读字段。
3. **#22** 设计巧思缩成一句，删掉"耗时中有多少来自生成"这类图上已能看到的话。
4. **#23** 检索与用量六张小卡：

   - 数字字号和加粗与上方卡片统一；
   - 整块挪到报告下方，滚动才看到。
   - 删除"重新评测 Baseline"按钮。
5. **#24** Hard Gate 抽屉和"查看案例"二级抽屉：第一屏只回答三件事，其余收进折叠：

   - 哪几题拉低了它。
