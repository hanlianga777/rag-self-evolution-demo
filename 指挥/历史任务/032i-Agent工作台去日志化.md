## 用户原话

> 现在 Agent 工作台里面的文字太多太乱了，想办法在前端优化一下，比如：1. 分成多张卡片；2. 文字太多就收起来；3. 或者把文字简化一下。之前关于 candidate 卡片里面的内容，上一版就挺好，为什么这次要做修改呢？……我们不要这种日志化的情况。

## 总指挥看到的问题（11-15 06:10，Round 3 实际页面）

- **"上一轮总结"**：把 Agent 保存的整段复盘原样铺开，约 10 行密集文字，再接 6 行 ▶ 条目。
- **"本轮结论"**：每个 Candidate 都是 5–6 行连续长段，包括预测、实际、未符原因、参数判断、依据，像日志。
- **"各方案计划"**：每张卡里风险一段就 7–8 行。
- **Candidate 卡片**：032f 把它缩成只剩数字。用户认为上一版（032f 之前）更好。
  - 根因：总指挥方案第 33/34 条把"不要重复"理解成"把策略从卡片挪到上面"。用户当时说的是**点进去之后的抽屉**太日志化，不是卡片本身。
- **题号显示成 "-29""-04""-45"**：Agent 原文里写了简写，例如 "CSV-…-20、-29"，前端只缩短了第一个完整编号。
- **英文原词外露**：`latency_p99=51.797s`、`prompt_injection_resistance=66.67`、`alpha=0.7`、Tiered、Thinking、clarify、final、candidate，以及 "Rerank 方式ed" 这种乱码。

## 原则

- **只改展示**。不调用模型，不改 Agent 保存的内容和任何评测数据，不补造内容。
- 简化的手段只有四种：
  1. 拆成卡片；
  2. 结构化字段：标签、题号徽章、数字；
  3. 长文字默认收起，用 2 行截断加悬停全文，或"展开"；
  4. 显示层的名词替换。
- 每个字段默认最多显示 **2 行**。超出的部分截断、悬停看全文；整段的分析放进默认关闭的"展开 Agent 分析 / 展开完整复盘"。
- 同一件事只出现一次。

## 要做的事

### 1. Candidate 卡片恢复上一版的内容

以 `git show 2b5285d:frontend/src/pages/EvolutionPage.tsx` 里的 `CandidateCard` 为准。卡内按这个顺序：

1. 思路：2 行截断。
2. "在 Candidate X 的基础上"：灰色小字。
3. 改动参数：做成标签，"参数 旧 → 新"；继承来的参数用灰色标签。
4. 针对的题：题号徽章。
5. 预计修好：题号徽章。
6. 风险：2 行截断，悬停看全文。
7. 结果：答对、门槛通过、修好（绿色徽章）、新错（红色徽章）。

保留 032f 的这几样：右上角合格 / 不合格徽章、圆角按钮、抽屉的去日志化。"依据"放在卡内，默认收起。

卡片已经包含每个方案的计划，所以**删除"① Agent 策略"下面的"3、各方案计划"**，不重复。

**右卡：Bad Case 分布**
- 保留现在的分布标签。
- 下方说明 2 行截断。

### 3. ③ 本轮结论：每个 Candidate 一张小卡，和上面三张卡片列对齐

每张卡：
- **顶部**：状态标签，加一句结论（2 行截断）。

### 4. Candidate D 用同样的规则

- 多张卡都写"具体失败原因未知：保存记录缺少可展示的逐条判定"时，合并成一行，例如"Q21、Q50、Q06 新增 Bad Case（逐条原因未保存）"，不要每张卡重复。
- 数字统一按第 5 条的格式显示，例如 "51.797s" → "51.8 秒"。

### 5. 显示层名词规范

集中在 `frontend/src/display.ts` 的 `agentDisplayText` 或相邻函数里。只改显示，数据不变。每条规则都要有单元测试。

| 原文 | 显示为 |
| --- | --- |
| 完整题号（`CSV-…-15`、`GD-…-Q15` 等） | Q15 |
| Agent 简写：紧跟在"、""（""(""/"、空格、行首后面的两位数 `-20`，且前面不是数字或字母 | Q20 |

  简写规则不要误伤日期、数值区间和负数，要有反例测试。

| 原文 | 显示为 |
| --- | --- |
| `latency_p99=51.797s` | 最慢耗时 51.8 秒 |
| `latency_p50=…` | 中位耗时 … 秒 |
| 三位小数的秒数 | 保留一位小数，加"秒" |
| `prompt_injection_resistance=66.67` | 提示注入抵抗 66.67 |
| 其余 snake_case 指标 | 沿用 `gateNames` 的中文名 |

在 Agent 页面里，指标名用短名，例如"正向正确性"，**不带"（Positive）"**。

| 原文 | 显示为 |
| --- | --- |
| `alpha=0.7` / hybrid_alpha | 向量权重 0.7 |
| Tiered | 分级回答 |
| Thinking | 思考档位 |
| clarify | 追问 |
| final（指交给模型的证据时） | 交给模型的证据 |
| 句中小写 candidate | 候选 |

"Rerank 方式ed"之类的乱码：找出是哪条替换规则造成的，修掉根因。

**验收断言**：在 Agent 工作台三个页签的默认可见文字里（不含已折叠的技术详情），不出现 snake_case 英文词（`/[a-z]+_[a-z]+/`），也不出现"-数字"形式的题号。
