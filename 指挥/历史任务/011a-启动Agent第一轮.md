# 任务 011a：启动优化 Agent 第一轮（花钱，第一段：生成方案并启动自动试跑，自动值班）

## 背景
- 010b 已完成：判分统一用 low；当前 Baseline 是 `EVAL-20261102140722852830`（回答 high · 判分 low，42/50，门槛 10/11）。错题复核结论已经挂在 Baseline 上：真错题 Q04、Q06、Q24、Q27、Q29、Q46 是优化目标；不稳定题 Q17、Q37 需保持判对。
- 用户授权（11-02）：Agent 跑出合格方案后，人工确认由总指挥代为确认，并继续跑方案 D、出推荐方案，**停在发布前**。本单只负责启动，不做确认，不跑 D。
- 现在是平价时段。花钱不设上限，报告写清实际花费（拿不到的写“未知”）。

## 要做的事
1. 确认当前 Baseline 就是 `EVAL-20261102140722852830`，判分档位为 low，没有其他评测、复核或实验在跑。改正式库前先备份。
2. 按产品现有流程，基于当前 Baseline 创建优化实验，让 Agent 生成第一轮 A/B/C 三套方案。
3. 检查三套方案是否符合要求：
   - 三个方向互不相同；
   - 每个调整的参数都写了预期影响，并点名题号；
   - 写了风险；
   - 没有重复失败签名。
   
   不符合就按产品现有规则处理（拒绝的草案不消耗试跑次数），不要手工改方案内容。
4. 用现有的 `/api/experiments/{run_id}/run-cycle` 启动自动循环：A/B/C 依次在 Sandbox 试跑；没有合格方案时 Agent 自动再出一轮；最多 12 次，1 次留给 D。
5. 确认第一套方案的前 2–3 道题已经正常出结果、没有技术报错，就结束本单。**不要等全部跑完，不要循环轮询。**

## 遇到这些情况就停，写进报告后照常收尾
- 当前 Baseline 不是 010b 的版本，或判分档位不是 low：不要创建实验；
- 方案生成失败、连续被拒，或 Sandbox 前 3 题出现技术失败：停掉，写清原因；
- 后端需要重启却被权限拦住，或有作业在跑：不要硬来。

## 报告
写到 `指挥/报告/011a-启动Agent第一轮.md`，用大白话写清：
- 实验编号，启动时间；
- **三套方案原文**：方案名、核心思路、每个参数（原值 → 新值 → 预期影响点名的题号）、风险、目标错题；
- 被拒的草案（如果有）及原因；
- 第一套方案前几题的结果；
- **查进度的方法**：浏览器能直接打开的只读接口地址，看哪些字段能知道当前在跑哪套方案、完成了几题、已用几次试跑、循环是否结束、是否已有合格方案；
- 数据库备份位置；
- 截至结束时的调用次数和费用估算。

- 启动后 demo 保持运行。**本单结束后，后续任务都不会重启后端，Agent 循环会一直在后台跑**；
- 不改题目、判分规则、门槛、发布规则；不做人工确认，不跑方案 D，不发布。
