## 1. 抽屉：每个区块一张小卡片（用户原话："每个结构能不能通过一个比较小的卡片的形式去呈现，而不是混在一起"）

- Golden 题目详情、候选池详情；
- Baseline Bad Case 详情；
- Agent 方案详情；
- 发布完整配置；
- 引用原文；
- 分块示例；
- 问答验证反馈详情。

**处理规则**：
- **区块结构**：凡是有多个区块的抽屉，每个区块都用 `DrawerSection` 或等价结构（`.drawer-section`），让它们统一变成小卡片。没用这个结构的，比如 EvaluationPage 的 `candidate-card`，改成同一结构或同样的卡片样式。
- **空区块不显示**：例如"业务场景：暂无""加分：暂无"整块不渲染，不要显示"暂无"。
- **Q45 抽屉顶部的大块空白**：查明是哪个空区块造成的，去掉。
- **核心证据去重**：Q21 的同一段证据重复出现了 3 次（同文档、同页、同文本）。相同文档 + 页码 + 文本只显示一次，有多处命中时在出处后面写"命中 3 处"。
- **质检结果**：Probe 和 QC 两张卡并排、等高。QC 说明这类截断文字统一用 `ClampText`（悬停或点击看全文，`extra.css` 已给截断文字加了提示光标）。原来是普通省略号、悬停没有任何反应，这是用户指出的问题。
- **"出处"统一短名 + 页码**：与 Golden 表一致。

## 2. 按钮配色（用户原话："运行 Probe、运行 QC 以及右下角的替换等按钮，都可以考虑增加一些颜色，但风格要跟我们现在的一样"）
`extra.css` 定义了三档按钮：
- **`primary`（蓝底白字）**：每个区域最多一个，表示最终动作，例如批准、确认发布、保存草稿、去问答验证。
- **`.ui-btn-tint`（浅蓝底蓝字）**：主要辅助动作，例如运行 Probe、运行 QC、编辑、替换、查看评测报告、进入 Agent 处理。
- **`.ui-btn-danger`（浅红底红字）**：删除、回滚、放弃修改等不可逆或撤销类动作。
- **其余**：保持现在的白底灰边，例如关闭、取消、次要入口。

**全站逐个按钮分类并加上对应 class**，报告列出每个按钮归到哪一档。会花钱或改数据的按钮，确认框逻辑不变。

## 3. 右上角"更多"菜单精简（用户原话："里面有的是 1 项，有的是 3 项……能不能设置成 1 个或 3 个按钮？或者有的内容没有必要，可以直接删除"）
逐页列出"更多"菜单里的每一项，按下面规则处理：
- **只有 1 项**：取消"更多"，直接显示成一个按钮。
- **2–3 项且都有用**：直接平铺成 2–3 个按钮，不要折叠菜单。
- **演示用不到或重复的入口**：删掉入口，后台功能和代码保留。判断标准：面试演示时会不会点它。

  - 例如"新建测试集"在题卷冻结后已经用不到。
