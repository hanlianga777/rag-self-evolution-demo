## 要做的

### 1. 引入 ui.css
在 `main.tsx` 里，`import "./styles.css"` 之后加一行 `import "./ui/ui.css";`。

- **逐页检查**：8 个页面逐页检查换肤后的效果，1440×900 和 1280×800 都要看。
  - 不能出现文字看不清、元素重叠、按钮不可点。
  - 局部冲突用最小改动修，优先在 `ui.css` 里修。
- **抽屉动画**：`ui.css` 用 Radix 的 `data-state` 属性做抽屉滑入。如果 `Dialog.tsx` 的抽屉没有这个属性、动画不生效，在 `Dialog.tsx` 上补，**不改抽屉的开关逻辑和焦点逻辑**。

### 2. 长文本改用 ClampText

| 位置 | 显示行数 |
| --- | --- |
| Golden 题表、Baseline Bad Case 列表、Regression 逐题表、问答验证左侧题目列表、最终推荐落选理由里的题目原文 | 2 行 |
| A/B/C/D 卡片和进化路线卡片里的"核心思路"、Agent 推理摘要、落选理由、没修好的原因、D 的"Agent 当时的预测" | 3 行 |
| 反馈列表、Bad Case 里的回答摘录 | 4 行 |

- **替换旧的内部滚动框**：卡片里原来"小格子 + 内部滚动条"的长文字，换成 ClampText。换完后同一排卡片仍然等高、字段顺序一致。
- **例外**：问答验证 Before/After 两栏完整回答，以及抽屉里的详情，保持现状。
- **现有提示组件**：已有的 `.text-tooltip` / `TruncatedText` 等截断提示组件，能换成 ClampText 的就换。不能换的写进报告说明原因。

### 3. 运行浮窗换成 RunProgressPanel
- `operation.tsx` 里原来的 `.operation-console` 显示部分，改用 `RunProgressPanel` 渲染。
- **数据和行为逻辑不变**，包括轮询、恢复、停止接口、错误详情来源。
- **状态映射**：

  | 原状态 | 新状态 |
  | --- | --- |
  | running | running |
  | running，且 `pricePause.paused` | waiting |
  | stopped | stopped |
  | failed | failed |
  | completed | completed |

- **标题**：用短名，例如"Round 2 · Candidate A""Candidate D""Baseline"。不出现完整编号。
- **"停止运行"**：调用现有的 `stopEvaluation`。
- **"继续运行"**：调用现有的续跑入口，也就是页面上"继续 Sandbox"这类按钮背后的同一个接口。
  - 如果等待中时续跑会绕过平价规则，等待中必须置灰。组件已经是这样设计的。
  - 没有对应续跑接口的运行类型，不传 `onContinue`，按钮自动置灰。
- **删掉**："确认按高峰价运行本任务""继续等待平价时段"两个按钮和说明。`PricePauseNotice` 在浮窗里不再显示，后端平价规则不改。
- **错误详情**：失败时 `errorText` 用一句人话。原来"查看错误详情"里的技术信息（Operation ID、Provider、Model、Attempt）从浮窗里拿掉；如果有测试依赖，改测试。
- **多个运行同时存在**：浮窗按现有 `operation-stack` 的方式堆叠，每个宽度都是 360。
