# 123b Agent 假设先行与定向检查（不花钱）

依据：互审 59 第四节；用户 11-26 08:59 拍板。前置：123a 完成。

## 要做的事

1. **新实验不再向 Agent 提供 176 组的全量检索预演**。
   - 旧实验（E2～E5）保持原样，按版本号区分。
   - 规划输入里只保留：当前底座、Bad Case 症状与错因、标准证据在链路中的位置、合法参数范围、本实验已完成的真实验证结果。
2. **两段式规划**：
   - **第一段**：Agent 提交最多 3 个假设，每个假设写明错因、要改的参数、预测会修好的题、可能弄坏的题、希望检查的配置。保存为「预演前预测」，之后不可覆盖。
   - **定向检查**：程序只执行 Agent 申请的配置。
     - 每轮最多 6 组，首次申请和后续修订合计；
     - 每组针对 1～3 道目标题，另外最多 2 道风险对照题；
     - 检索类只返回这几道题的证据进出情况；
     - 生成诊断每题每个配置 3 份回答，每轮最多 36 份，使用原 Judge；
     - D 方案额外最多 2 组。
   - **第二段**：Agent 看完检查结果，提交正式的 A/B/C，并保存为「预演后预测」。
3. **防白跑**：证据和请求与已跑方案完全相同的配置，不进入 Sandbox，不占预算，并告诉 Agent「该参数没有起作用」。
4. **三项指标**写进每轮复盘和接口：
   - 预演前预测命中率 = 实际修好的预测题数 ÷ 预测题数；
   - 实际修复覆盖率 = 预测到的修复数 ÷ 实际修复数；
   - 风险预测命中率 = 预测到的回退数 ÷ 实际回退数。
5. **统一编排接入**：上述流程走 122d 的编排器。生成诊断由编排器在 Agent 申请后自动执行，不需要人点按钮。
6. **单测**（假 Provider，临时数据库）：
   - 规划请求里不含全量预演；
   - 预演前预测保存后不可覆盖；
   - 定向检查超过配额会被拒绝；
   - 防白跑命中时不占预算；
   - 三项指标计算正确；
   - 旧实验的请求保持不变。

## 约束

- 不调用真实模型。
- 不改合格规则。
- 所有测试使用临时数据库。
