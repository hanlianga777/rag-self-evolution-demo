## 要做的事

### 1. 给 Agent 补上客观的检索事实
对每道目标错题，由产品代码从 Baseline 已保存的数据（`retrieval_trace`、冻结的标准证据、`judge_result.checks`）计算以下内容，并放进 Agent 输入：
- 每段标准证据（chunk ID）在**候选、重排、最终内容**三个环节的位置：第几位，或"未进入"；
- 当时的候选数和最终保留数（例如 candidate_k=12、top_k=4）；
- 未中的必答要点；
- 复核结论：真错题还是随机波动，3 次里错几次。只传这个结论和次数，不传 `analysis` 文字。

要求：
- 只能用已保存数据计算，不调用任何模型或检索服务。
- 字段名和计算逻辑写在产品代码里，任何 Baseline 都能用，不能为这 5 道题写死。
- 数据缺失时写"记录缺失"，不要猜。
- 写一个只读的展示办法（脚本或只读接口均可），能打印出 5 道题实际给 Agent 的这一段输入。

### 2. 修规划器状态

### 3. 诊断不重复计算（能安全做就做）
让规划诊断和列表诊断使用同一份冻结题来源，再复用结果，让 `test_page_performance` 那项通过。如果两边的冻结来源统一不了，或者统一会改变诊断结论，就不要做，只写清原因。
