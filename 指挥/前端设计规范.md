# 前端设计规范（总指挥维护，所有前端任务单都按这里执行）

适用场景：这个 demo 首先用于**面试展示**，其次可能给客户看。每一页都要先讲清楚三件事：这一步在做什么、结果是什么、为什么重要。技术细节随时能看到，但默认不占主画面。

两条底线：
- **不要过度简化**：设计巧思（冻结题卷、Probe/QC、门槛、错题分类与复核、三套方案、Sandbox、回归检查、方案 D、人工确认、回滚）都要留下，而且要让人看得见。
- **不要颠覆**：沿用现有的页面结构、左侧导航、页签和抽屉交互，只整理、统一、精简。

## 1. 颜色
- 只用 `styles.css` 里 `:root` 定义的颜色变量。新增的颜色也必须先定义成变量，页面里不准再写零散的色值。
- 中性色：沿用现有的 navy / ink / muted / line / canvas / surface。
- 状态色只有四种，全部沿用现有色值（用户认可现在的浅绿），每种一组“浅底色 / 边框 / 文字色”：
  - 成功（浅绿，现有 `--card-good-*`）：`#f2f7f3` / `#d8e7db` / `#315a3b`
  - 提醒（琥珀）：`#faf0d8` / 同色系浅边框 / `#75521a`
  - 失败（红）：`#f9e7e7` / 同色系浅边框 / `#8a3333`
  - 信息（灰蓝，现有 `--status-bg` / `--status`）：`#eef2f5` / `--line` / `#405776`
- 浅绿只表示“已完成 / 通过 / 合格”，例如已完成的阶段卡、通过的门槛、合格方案，可以整张卡片用浅绿底。
- 普通信息卡片（参数卡、主题卡、数字卡等）一律白底加 1px 浅边框，不用浅绿装饰，免得浅绿失去含义。
- **禁止**：玻璃效果、半透明、模糊（backdrop-filter）、渐变、多余阴影。
- 进度条和占比条：
  - 统一一种样式：浅灰底槽（`--line-soft`）加实色填充（灰蓝 `--status` `#405776`），高度 6px，圆角。现在 Baseline 耗时拆解里那种亮绿色的条不要再用。
  - 只有“未达标”才用红色填充。
  - 不同地方的条不准各用各的颜色。

## 2. 字号
| 用途 | 字号 |
|---|---|
| 页面标题 | 28px |
| 区块标题 | 16px，粗 600 |
| 卡片标题 | 14px，粗 600 |
| 正文 | 14px |
| 表格 | 13px |
| 次要说明 | 12px |
| 标签 / 徽章 | 11px（只限标签和徽章） |
| 关键数字 | 24–28px，等宽数字（tabular-nums） |

- 删除所有 9px、10px 的字。
- 除标签和徽章外，不出现小于 12px 的字。

## 3. 排版与对齐（原则问题）
- 并排的卡片必须**正好铺满一行**，行尾不留空位，同一行卡片等高。
  - 列数按卡片个数定：5 张就 5 列；9 张用 3×3；6 张用 6 列或 3×2。
  - 个数不整齐时，按业务含义分组，不要硬塞。
- 间距统一：卡片之间 16px，区块之间 24px，卡片内边距 20px。
- 同一区块内，标题、数字、说明的左边线对齐。表格表头样式统一，表格下方不留空白占位。
- 页面不出现内层滚动条（架构图、表格都随页面一起滚动）。
- 唯一例外：抽屉内部可以滚动。

## 4. 数字格式
| 类型 | 格式 |
|---|---|
| 秒 | 1 位小数，例如 7.3 秒 |
| 毫秒 | 一律换成秒 |
| 百分比 | 1 位小数，例如 90.0%；小于 0.1% 写“<0.1%” |
| 费用 | 美元，最多 4 位有效小数，例如 $0.0008 |
| 计数 | 千分位，例如 2,081 |

- 不出现 0.727598、0.1657% 这种原始小数。
- 数字一律从接口读取，不写死。

## 5. 文字
- 主画面不出现：运行编号、哈希、指纹、版本号（例如 business-vnext-1）、chunk 编号（例如 DOC-001-C-00180）、文件内部路径、`FAIL` / `PASS` 等英文状态词。
- 需要指代某次运行时，用易读名字，例如“Baseline · 11-02”。
- 不出现开发者口吻的说明和免责句，例如“方向说明不代表已生成候选方案”“补全诊断证据由…统一批量预检”。这类句子删掉，或收进技术详情。
- 同一个意思只说一次：标题已经说了的，副标题、徽章、表格里不再重复。
- 术语规范本轮不调整，沿用现在的用词（用户另行决定）。

## 6. 技术详情
每页最多一个“技术详情”折叠区，默认收起，**放在页面最底部**，不放顶部。编号、配置快照、历史评测、规则依据、审计链接这类内容都收进去。

## 7. 按钮和链接
- 每页最多一个主按钮，和这一步的故事一致。
- 已冻结、已完成、只读的状态下，隐藏不再适用的操作，例如：
  - 运行 Probe / 运行 QC / 编辑 / 替换 / 批准
  - 批量重跑异常项、创建 Golden、删除文档
- 会花钱或会改数据的入口（重建知识库、新增文档、新建测试集、重新运行 Baseline），统一收进页面右上角的“更多”菜单，保留原有的二次确认。
- 表格整行可点，点击打开抽屉。不再一行放“展开细项”“查看案例”两个链接。
- 删除指向空页面或重复内容的链接。

## 8. 加载与空状态
- 数据没读完时显示骨架占位。**不准先闪一个别的题卷或空工作集再跳回来**（现在 Golden 页会先闪“MINI · 20题”）。
- 空状态统一写法：
  - 一行说明“还没有什么”；
  - 一行说明“什么时候会有”；
  - 最多一个按钮。
  - 字号按正文，不用一堆小字。

## 9. 检查方法
- 每个改动的页面、页签、抽屉，在 1440×900 和 1280×800 两种窗口下截图检查。
- 不能有：文字重叠、挤压、横向滚动、行尾空位、按钮换行错位。
- 截图只留本机。
