# 指挥目录说明

这个目录是 Claude（总指挥）和 Codex（执行者）之间的任务信箱。

- `当前任务.md`：Codex 每次要执行的任务，只看这一个文件。
- `报告/`：Codex 完成任务后写的报告，文件名以任务编号开头。
- `历史任务/`：已完成的任务单存档。
- `队列/`：自动值班模式下排队的任务单，按文件名顺序执行；以 `_` 开头的是草稿，不执行。
- `自动值班/`：值班脚本和安装说明。`值班记录.md` 由脚本自动写入。
- `暂停`：这个文件存在时，值班脚本不再开始新任务单（总指挥用来远程叫停）。

## 两种运行方式

- **手动**：用户在 Codex 桌面版发固定的一句话，Codex 执行 `当前任务.md`，自己提交并推送。
- **自动值班**：`值班.sh` 调用 Codex 命令行版执行 `队列/` 里的任务单。Codex 只需提交（commit），推送由脚本负责；做完后用 `git mv` 把任务单移到 `历史任务/`。

## 给 Codex 的固定规则

1. 开始前先拉取最新代码。
2. 只执行分配给你的那张任务单（`当前任务.md` 或 `队列/` 里的）写明的内容，不自行扩展范围，不自行加限制或审批步骤。
3. 报告用中文、用大白话写；只写事实，每个结论注明来源（文件、数据库表、提交号）；不知道的写"未知"，不要猜。
4. 完成后把报告和任务要求的产出全部提交并推送，然后在回复里只说三件事：完成了什么、报告路径、有没有没做完的。
5. 仓库是公开的：任何时候都不要把数据库、`.env`、密钥、运行数据、大文件（单个超过 10MB）推送到 GitHub，这些一律只留在本地。
6. 本目录下的文件属于协作文档，不是产品规范，提交时不需要同步 SPEC 等文档（提交说明写 `No SPEC Change`）。
