## 本单范围（方案 #32–#37）
**页签**：概览｜Candidates 对比｜回归与推荐。原"进化路线"和"Sandbox 对比"合并进"Candidates 对比"。

1. **#32 概览**：做成和 RAG 概览风格类似的一屏。
   - 最终方案一句话，例如"推荐方案：第 N 轮 Candidate X"，按数据显示。
   - 相对 Baseline 改了哪些参数，用标签显示"候选数 12 → 24"这种格式，取 `changed_parameters_vs_baseline`。
   - 优化思路一句话：取 Agent 保存的轮次结论或推荐理由，不写模板话。
   - 四条原则：四个小标签加悬停说明，文案见"文案"第六节。
   - 删除"Bad Case 去向"表。
   - 不出现"每轮固定一个效率方向"之类的说法（方案"一、7"）。
2. **#33、#34 Candidates 对比**：每轮按三段展示，内容全部取 Agent 保存的数据（四部分输出、轮次结论），**不编写**。
   - **① Agent 策略**，按 1、2、3 结构化列出：
     - 上一轮总结（第 1 轮显示 Baseline 诊断总结）；
     - Bad Case 按层 / 细分类型的分布；
     - 每个方案要改的参数、要解决什么问题、预计修好哪些题、风险、依据。
     - 第 2 轮起，在合格方案上继续改的方案显示"在第 N 轮 Candidate X 的基础上"，继承参数灰显，新改动高亮。
   - **② 三个 Candidate**：三列卡片，第一眼是结论：合格 / 不合格、答对数、门槛通过数、修好几题、新错几题。抽屉去日志化：
     - 先结论；
     - 再逐题变化，修好 / 新错 / 仍错分组；
     - 最后配置和技术详情折叠。
     - 按钮统一圆角，不用链接样式。
   - **③ 本轮结论**：实际对比预测（预测修好的题是否真的修好）、弄坏了什么、可能是哪个参数造成的、带入下一轮的经验。原 Sandbox 对比表以折叠表的形式放在最下方。
   - 页面不重复：前面卡片已经出现过的信息，后面不再出现。
3. **#35** Round 1 / 2 / 3 / D 标签吸顶，滚动时不消失。
4. **#36 Candidate D** 分四段：
   - **合并了什么**：来源方案、参数、组合方式（Winner + 已验证参数 / 部分融合）。
   - **事先预测**：预计修好哪些题、可能弄坏几道、风险清单（032 之前已支持列表展示）。
   - **事后对账**：逐题对比预测和实际。
   - **结论**：D 不合格或不如 Winner 时，写清"保留 Winner"和原因，例如哪几项门槛没过、新错了哪些题。

   D 分析失败的历史记录只放技术详情。
5. **#37 回归与推荐**：
   - 结论改成分条："一、质量：……""二、安全：……""三、速度：……""四、回归：……"，内容按数据生成。
   - 保留合格方案对比表。
   - "落选原因"改为一行一个方案的简表（方案 / 没过的门槛或新错 / 一句原因）。
   - 删掉落选方案的 Bad Case 明细。
