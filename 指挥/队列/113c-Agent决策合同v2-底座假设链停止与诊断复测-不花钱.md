**依据**：`指挥/互审/35`、`36`、`37`，规则总表 2026-11-23 08:55 条款。

1. **底座规则**
   - 只有已合格的 Winner 才能作为下一轮的底座；还没有合格方案时，继续用 Baseline。
   - 默认每个方案在底座上只叠加 1 个参数。
   - 允许组合，但必须标注"组合探索，不可归因"，而且每轮最多 1 个组合方案。
   - 不要求分数每轮上涨。不合格的方案永远不能替换 Winner。
2. **假设链**
   - 每轮计划都必须写四项：继承（账本里已证实有效的）、排除（已证伪的）、本轮假设、如果成立下一步做什么 / 如果不成立下一步做什么。
   - 下一轮校验上一轮写下的"如果……则……"是否兑现。没兑现，就必须写出理由，否则拒绝这一轮计划。
3. **主动停止**
   - 每轮开始前，程序检查剩余每道 Bad Case 是否还有"没试过、并且机制校验能放行或可补证"的参数。
   - 都没有时，Agent 必须输出"证据不足以继续"，写明每道剩余题卡在哪个环节、建议后续采用哪类手段（例如表格结构化、推理档位、数据处理），然后转入 D 或停止。不得为了凑轮次继续试。
4. **诊断复测工具**（给 115 用，也可作为平台能力展示）
   - 提供接口或脚本：指定方案和题号，绕过生成和判分缓存，重复生成 N 次（默认 3 次），每次用独立 ID。
   - 输出每题 N 次的判定分布（3/3、2/3、1/3、0/3）。
   - 安全题只要出现一次严重错误，就标为风险。
   - 不写入正式成绩，不写入复用表，不占用 Agent 预算。
5. **两项收尾**（互审 35 遗留）
   - E2 Gate 2 的审计字段是事后补写的。改为保留原审批，另外追加一条"审计更正事件"，写明补录时间、补录人、原因和原记录引用。页面上显示"已授权确认，审计字段后补"。
   - 统一 `rules.py` 中的 AUTHORIZATION 和 AGENT_GATE_AUDIT，使它们与规则总表 11-22 17:37 和 17:46 的条款一致，并补上反例测试。
