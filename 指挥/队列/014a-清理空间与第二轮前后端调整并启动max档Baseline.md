- **上下文窗口做成真实可选**：现在只有"关闭"且标着"暂不可用"，原因是本地缺 tokenizer 归档。
  - 改成三个有实际意义的选项，例如"不限 / 8192 / 4096"。按我们的分块（父段 1400 tokens，TopK 4–6）选能真正起作用的数值，不要放永远碰不到的大数。

  - Baseline 用"不限"。

### 2. 一道题只跑一遍
- 去掉 Baseline 的"错题自动复核 2 次"，也去掉候选方案的"新错题自动再跑 2 次（回退复核）"。新的 Baseline 和候选，都以那一遍的结果为准：错就是错。
- 产品输出和页面上不再出现"随机波动 / 不稳定 / 偶发 / 3 次错 2 次"这类说法。历史记录保留，但不再作为新流程的依据。
- 合格判定直接用单遍结果。
- 检查回答模型（deepseek-v4-flash）能否设置 temperature。**能设的话**，回答生成固定用最低值，减少同一道题每次回答不同的情况，并写进运行配置快照；判分保持现状。**不支持的话**，在报告里说明。

### 3. Bad Case 归因改用朋友方案的原话
- 每道错题的**大类**只用这 4 个：检索层问题 / 生成层问题 / 安全边界问题 / 性能问题。
- **现象**只能从下面选（原话照搬，不准自创说法）：
  - 检索层：Golden Chunk 未进入 Top-K；Top-K 召回大量无关；关键片段排名过低
  - 生成层：召回成功但答案漏要点；答案出现幻觉；安全提示丢失；模型过度拒绝（已检索到相关切片仍拒答）
  - 安全边界：该拒答时没有拒答；被提示词注入绕过；回答了知识库外内容；安全边界误伤（合法问题被误拒）
  - 性能：Latency 过高；TTFT 过高；Token Cost 过高
- 由程序按检索记录和证据比对自动判定，不调用大模型。原来的 5 类和"澄清不足"等子特征一一映射到上面的说法。
- 优化优先级表按 4 大类汇总。Baseline 页、Agent 页、Agent 输入**用同一个来源**：现在 Agent 页显示 8 道、优先级和 Baseline 页不一致，要修好。
- "错题类型 → 优先尝试的参数"对照表：
  - 检索层 → Query Rewrite、HyDE、Multi-Query、CandidateK、TopK、MinScore、Hybrid 及权重、Rerank
  - 生成层 → Prompt 策略、Thinking 档位、上下文窗口
  - 安全边界 → Prompt 策略、Thinking 档位
  - 性能 → 降低 Thinking、关闭耗时环节，再用检索参数补质量

### 4. A/B/C 必须是三种不同的优化方式（写进方案校验，代码强制）
上一轮三套方案都加了"分级回答"，无法看出是谁起的作用。规则如下：
- 每轮固定 3 套，每套有一个方向标签：检索召回增强 / 排序与过滤 / 回答策略 / **效率（降档 + 检索补偿）**。
- **必须有且只有一套是"效率"方向**：Thinking 低于 Baseline，同时至少改一个检索参数做补偿（HyDE、Multi-Query、CandidateK、TopK、MinScore、Rerank、Hybrid 权重之一）。这参考朋友的方案 D"关闭深度思考的多路召回增强"。
- 另外两套是质量方向，方向互不相同，不得降低 Thinking。
- **同一轮里，同一个参数只能出现在一套方案里**，三套之间不得共用任何参数改动。
- 第 2 轮起，把前面每轮每套的结果（修好哪些题、弄坏哪些题、哪项门槛变化）作为客观事实交给 Agent；已被证明伤害门槛的同一改动不得原样再提。
- 违反规则的方案由校验拒绝，并带着具体原因自动让 Agent 重出一次。格式拒绝不占 12 次试跑预算。
