总指挥在 `frontend/src/ui/extra.css` 末尾加了通用版式工具：
| 类名 | 用途 |
| --- | --- |
| `.ui-card` | 白底细边小卡片 |
| `.ui-card-row` | 等高的两列或多列，用 `--cols` 指定列数 |
| `.ui-headline` | 决定性结论，16px 加粗 |
| `.ui-body-muted` | 弱化正文，13px 浅灰 |
| `.ui-kicker` | 小标签 |
| `.ui-field` / `.ui-field.lines-2` | 并排卡片里的同名字段，固定两行高度，保证横向对齐 |

本任务用这些工具重排，不再自写新样式。第一步先跑 `npx tsc -b` 和 `npx vitest run src/ui`。

## 1. Agent →「A/B/C/D」三张并排卡片的字段对齐（用户原话："各个字段没有在同一水平线……全部都需要做对齐。可以采用鼠标悬停显示悬浮效果，里面的内容保持两行就够了"）
- **字段结构**：每张卡的字段（思路、改动参数、针对的题、预期效果、风险、结果）都用 `.ui-field.lines-2`。正文一律 `ClampText lines={2}`，悬停看全文。
- **对齐要求**：同一行三张卡的同名字段，顶边必须在同一水平线上。
- **"风险"字段**：精简成一行一条，最多 2 条，其余进悬停。"1 道，完整内容见方案报告·…"这种前缀删掉，只留风险本身。
- **"结果"字段**：内部的指标行（Hard Gate、修复原问题、新增失败、Regression Check、P50、P99、候选合格、可发布）行高统一。三张卡的结果区顶部对齐。
- **"修好：……"长句**：放在结果区最后，用题号徽章（`QuestionBadge`）代替整句题目原文。
- **全站同类排查**：所有并排多卡（概览、发布、Sandbox、最终推荐等）都检查一遍，凡是同名字段没对齐的，用同样办法处理，报告列出。

## 4. 全站版式审查（用户原话："检查所有一级导航栏的每一张 tab……如果内容不多，尽可能不需要滚轮就能看到下面，第一视角撑满整个屏幕""其他的你也检查一下，都要按照这个标准"）
1440×900 下逐页逐页签检查，处理以下三类问题：
- **内容不多却要滚动**：压缩间距、把大卡片改成紧凑行、把次要内容收进"更多"，做到首屏看全。确实放不下的（例如 50 题表格、长回答）除外。
- **并排的栏和卡片高度不齐**：侧栏、并排卡片要等高，或者撑到与相邻内容齐平。不允许一边很长、另一边下面大片空白。卡片内部留白可以接受，卡片外面露出大片页面底色不行。
- **字段不对齐**：同第 1 条。

**报告**：用表格逐页签写明"改前是否需要滚动 / 改后是否需要滚动 / 做了什么"。截图放本机。
