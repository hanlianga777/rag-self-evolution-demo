# 109i Gate 双审防绕过，及诊断口径补修（不花钱；GPT 批次二审的 P0/P1）

**依据**：GPT 对 109a～109g 的批次二审，见 `指挥/互审/33`。新实验必须等本单和 109h 都通过之后才能启动。

## P0-1：Gate 2 和 Gate 3 不得绕过双审
- **现状**：`policy.py` 的 `delegated_gate_audit()` 里有一行 `if reviews is None and actor != rule['executed_by']: return {}`。也就是说，只要换一个 actor（例如 `local_user`、`human`），或者不带双审依据，就能直接确认报告或发布。工作台的"确认报告与 Winner"按钮和发布页按钮，现在都走这条路径。
- **修改**：对 `decision_contract_version=109c` 的实验（今后的新实验都属于这一类），不管 actor 填什么，Gate 2 和 Gate 3 **都必须**带合格的双审依据，否则拒绝，返回中文原因。旧实验保持只读，不受影响。
- 前端两个按钮对这类实验改为：缺少双审依据时置灰，并提示"需 Claude 与 GPT 双审通过记录"，不得发出请求。

## P0-2：双审依据必须和具体阶段绑定、可以核对
- `delegated_review` 的结构改为：`{experiment_id, stage: 'gate2'|'gate3', claude: {verdict, record}, gpt: {verdict, record}}`。
  - `record` 是仓库内互审文件的相对路径，例如 `指挥/互审/NN-xxx.md`。
- 服务端逐项校验，**全部满足**才通过：
  1. 两个 record 文件都存在；
  2. 文件内容包含该 `experiment_id`；
  3. 文件内容包含对应阶段字样（"Gate 2"或"Gate 3"）；
  4. 文件内容包含"结论：通过"；
  5. 两个 verdict 都等于"通过"。
- 不能只检查字段非空。同一份记录不能拿来用于另一个实验或另一个阶段。审计信息里保存两个 record 的路径和文件哈希。
- 测试要覆盖以下情况都被拒绝：
  - 任意 actor 加上缺失依据；
  - 依据里的实验 ID 不对；
  - 阶段不对；
  - 文件不存在；
  - verdict 不是"通过"。
  
  正常的双审依据要能通过。

## P1-1：Q05 的诊断口径
`_document_denial()` 会把"具体操作步骤"之类的后缀去掉，只拿主题词去和 Final 比对。但 Q05 的 Final 里只有"请参阅第865页的更新转数计数器"这样的**页码指引**，并没有具体步骤。所以把"错误否定"拆成两个子现象，都对应 Grounded 策略，但证据描述要写清楚是哪一种：
- `已有证据被否定`：Final 里明确有对应的事实、步骤或数值，回答却说没有；
- `资料边界过度断言`：Final 里只有章节、页码指引或部分信息，回答却断言整本手册没有。

Q05 预期属于后者。诊断结果要附上命中的原句，以及对应的 Final 位置。

## P1-2：TableCheck 去掉专属 Q15 的数字
把 `ai_service.py` 中的 `TABLECHECK_STRATEGY` **整段替换**为下面这段（逐字照抄）：
```python
TABLECHECK_STRATEGY = STRICT_STRATEGY + "表格核对：问题涉及表格、维护周期、清单、数量统计或对比时，先把资料表格中与问题相关的每一行按'项目=对应列的值'逐行核对，按实际表头列名和单元格内容归类，不得把不同周期、条件或型号对应的项目混在一起；核对完再统计数量、给出清单；不确定某行属于哪一类时如实说明，不要猜。"
```

- 新策略的指纹要重新验收；
- 补两个测试：一个是不同周期，一个是不同型号表格结构，不能只测 Q15 的场景。
