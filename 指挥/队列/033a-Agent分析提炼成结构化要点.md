## 为什么

Agent 工作台里，Agent 保存的策略、复盘、风险、结论都是长段原文，还夹着内部编号和英文参数名，例如 `CSV-20261101…-29`、`prompt_strategy=Tiered`。用户要求用结构化的总结语言展示，不要整段铺开，也不要折叠。

前端没法自己总结，所以本单用模型做**一次**提炼，结果单独保存，供下一单的页面使用。

## 范围

实验 `EXP-20261114175011989842`，第 1–3 轮，以及 Candidate D。需要提炼的原文：

| 段落 | 原文来源（字段名以实际为准，032f 的 `RoundStrategy.tsx` / `EvolutionStory.tsx` 已经读过这些字段，可在 `snapshot-032-ui-20261115` 分支参考） |
| --- | --- |
| 每轮"本轮策略" | 本轮规划里的思路、上一轮复盘、Bad Case 分布说明 |
| 每个 Candidate 的"设计意图 / 风险" | candidate reasoning 里的核心思路、假设、风险列表 |
| 每轮"本轮结论" | 每个 Candidate 的结论、预测对账、未符原因、参数判断、带入下一轮的经验 |
| Candidate D | 合并理由、事先预测、事后对账、结论 |

## 写法要求（写进提示词）

- **只用原文里有的事实**，不补充、不推测；原文写"无法确定"的，要保留这种不确定性。
- 题号一律写成 `Q29` 形式。参数用中文名，与 `frontend/src/display.ts` 的 `parameterNames` 一致，例如"向量权重 0.5→0.7""思考档位 Max→High""回答策略 有据生成→分级回答"。
- 不出现内部编号、英文 snake_case、`=` 号、"Positive / Negative"之类的英文括注。
- 口吻是业务人员能听懂的短句，不写"本 Candidate 不应采纳"这类审计腔。

## 防编造校验（程序做，必须有测试）

1. 输出里的每个题号，都必须出现在对应原文里；不在的，整段作废，重试一次。
2. 输出里的每个数字（百分比、秒数、分数），都必须能在原文里找到同值，允许四舍五入到 1 位小数；找不到的，整段作废，重试一次。
3. 输出里不能有 `[a-z]+_[a-z]+`、`=`、`CSV-`、`EXP-`、`GD-`。
4. 字数超限的，整段作废，重试一次。
5. 重试仍不通过的，该段标记为"提炼失败"，页面回退显示原文。**不许人工编写替代。**
