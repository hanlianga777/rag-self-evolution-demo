# 093：候选池扫描 → 按写定规则组卷（只扫描，不导入、不出成绩；少量付费）

## 背景

081、085、089 三次扫描说明了两件事：
- 在 v2 大父块下，"答案要 5 个父块"的题，任何检索配置都补不回；
- "答案在 1～2 个父块"的题，Baseline 几乎全中。

唯一被调参补回的是 Q20 这类题。它的答案只有一行、全库独一份，但同一批关键词（防护类型、IP67、型号、货号）在维修手册里出现几十次，结果标准父块被挤到第 5、6 名。

总指挥按这个规律出了 26 道候选题（16 道正向、12 道消融），脚本是 `指挥/报告/092-候选池脚本.py`。候选题和 081 版的 30 道正向、消融题合成一张扫描表 `092-候选池.csv`，共 56 题，本地校验 0 错。

组卷规则在扫描前就写死在 `093-组卷脚本.py` 开头，只看检索层，不看回答和判分。规则是：
- 只选"Baseline 检索缺、同一个配置能补回"的候选题；
- 选中的题按固定顺序替换 Baseline 已经全中的槽位。

## 要做的事

1. `git pull`。本单不需要后端服务运行。

2. 导入 dry-run，只校验不写库：
   ```
   PYTHONPATH=backend python3 backend/scripts/import_friend_golden.py --csv 指挥/报告/092-候选池.csv
   ```
   - `error_rows` 必须为 0。
   - 如果只是因候选题号格式（P01、A01）报错，贴出原文后继续第 3 步。

3. 扫描：
   ```
   PYTHONPATH=backend python3 backend/scripts/retrieval_headroom.py --csv 指挥/报告/092-候选池.csv --output 指挥/报告/092-候选池扫描.csv
   ```
   - 原 30 题的检查点可以复用。
   - 原样贴出 JSON 中的 `knowledge_identity`、`baseline_gap`、`fixable`、`best_configs`（去掉 `sources` 明细）。
   - `knowledge_identity` 必须与 089 相同。

4. 组卷：
   ```
   python3 指挥/报告/093-组卷脚本.py 指挥/报告/092-候选池扫描.csv
   ```
   - 脚本会写出 `指挥/报告/093-题卷v4.csv`，并打印结论和 JSON。原样贴出。
   - **不要手工改题，也不要改脚本里的规则。**

5. 对生成的题卷再做一次导入 dry-run（同第 2 步，换成 `093-题卷v4.csv`）。`error_rows` 必须为 0。

## 报告

写到 `指挥/报告/093.md`。

**第一行**单独写组卷脚本打印的第一行，并按下面的条件改写：
- 打印的是 `组卷结论：达标（…）`，且第 5 步 `error_rows=0`：照抄这一行。
- 第 5 步 `error_rows` 不为 0：第一行改写成 `组卷结论：不达标（导入校验失败）`。

第二行起写各步的原文。

紧接着的 094 会读第一行，决定是否导入并跑 Baseline。
