# 122e 知识库、Golden、Probe/QC 断点续建（ST-04，不花钱）

依据：互审 56 第二节第 5 条。前置：122d 完成。

## 要做的事

1. **知识库重建**（`corpus_management.py:76-174`）：
   - 服务重启后，未完成的操作改为 `recovering`，自动从断点续建，不再只标「中断」等人工处理。
2. **MinerU 解析**（`knowledge_pipeline.py:1035-1068`）：
   - 远端任务的身份要持久化；
   - 上传、轮询、下载出现异常时走统一重试；
   - 重启后接着轮询原来的远端任务，不重新上传。
3. **切块与向量化**（`knowledge_pipeline.py:1106-1199`）：
   - 按文档、按批次记录断点；
   - 单个文档失败时进入 `retry_wait`，不中止整次构建；
   - 重试仍然失败时，列出失败的文档。
4. **Corpus 切换**（`corpus_management.py:20-54`）：
   - 索引身份与数据库身份不一致时，提供自动修复入口，修复方法是从持久化的切块重建索引；
   - 不能让 API 直接起不来。
5. **Golden 生成、Probe、QC**（`main.py:426-444`、`main.py:848-1015`、`main.py:1035/1150/1428`）：
   - 逐题记录断点；
   - 中断后续跑时，已经出过、验过的题不重复生成。
6. **单测与故障注入**：
   - 在 MinerU 轮询中途 kill；
   - 在向量化批次中途 kill；
   - 在 Golden 生成中途模拟 SSL EOF；

   以上每种情况都要能续建成功，结果与一次跑完的结果一致。

## 约束

- 不调用真实的 MinerU 或模型，用假实现。
- 所有测试都用临时目录和临时数据库。
