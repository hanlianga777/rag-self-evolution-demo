## 1. 重建知识库（新版本，不覆盖快照）
- 启用 `parent-child-v2` 分块和"文档名 · 章节路径 + 正文"的向量化输入；解析结果用 MinerU 已有缓存，不重新解析。
- 重新生成 Embedding（text-embedding-v4）、FAISS 索引和 BM25，生成新的 `corpus_snapshot_id` 和 `pipeline_version_id`。
- **重启后端**，让新索引生效。这是本单唯一一次重启；后面的 031d 开跑后不再重启。
- **验收**：
  - 知识库页能打开；文档、Parent、Child 数和 031b 统计一致；
  - 抽 3 个 Parent 核对：Child 范围、页码、章节路径都正确；
  - 去噪清单可读。

## 2. 题卷重新锚定（题目不变）
- **原样保留**：50 道题的题目、题型、负向子类、参考答案、必答要点和加分要点。
- 每道正向题和消融题的证据原文，在新 Child 中逐字重新定位，生成新的证据 Chunk ID（Parent 和 Child 都记录）。
- 每道题的知识主题按新的主题簇重新归属，见第 3 节。
- **生成新的题卷版本号**，旧版本保留不动。

## 3. 主题聚类（K-means）
- 在新 Child 的向量上重新做 K-means。保持原来的选 k 规则，随机种子固定，写进版本信息。
- **主题命名**：用 DeepSeek 为每个主题簇起一个 2–6 个字的中文名（例如"电池与充电"）。
  - 只给模型看该簇中最有代表性的 5 段文字；
  - 名称不能重复。
- **题位规划统计**：按新主题簇重新算一遍正向、消融、负向的规划题位。只用于展示，不改题。

## 4. 重跑校验
- **硬校验**：50 题全部重跑，例如证据能否逐字找到、要点是否出自证据。
- **探针**：
  - 正向、消融题跑"检索召回探针"：用 Baseline 默认配置检索，看标准证据能不能被找回，记录排名；
  - 负向题跑"假负向探针"：向量探针和全文字面探针，确认知识库里确实没有答案。
- **质检（QC）不重跑**：题目没变。旧版本的 QC 结果关联到新版本，报告里注明。
- 有题目不过时，**不要删题**，在报告里逐题列出原因，交给总指挥判断。
