# 122d 统一编排入口：接入生成诊断、D、最终复测和发布，加故障注入回归（ST-05，不花钱）

依据：互审 56 第二节第 1、4、6 条。前置：122c 完成。

## 要做的事

1. **新建 `app/workflow_engine.py`，作为唯一的编排服务**。下面三种入口都调用它：
   - 前端「下一轮」：`EvolutionPage.tsx:265` → `main.py:1870-1880`；
   - 前端「自动优化」：`main.py:2432`；
   - 服务重启后的恢复。

   编排服务负责：
   - 读取授权范围和目标阶段，例如只跑本轮、只跑某个 Candidate，或一路跑到发布；
   - 按状态机判断下一步；
   - 自动执行前置步骤；
   - 调用现有的业务执行器；
   - 写审计记录。
2. **把 E5 脚本里的能力迁进正式后端**：
   - 生成诊断（`generation_probe.run_probe`）：当目标层是生成层、而当前底座还没有生成诊断时，由编排器自动执行，按样本记录断点，费用走 122b 的账本和该实验的授权；
   - 最终独立复测；
   - 发布前检查和发布后验证；
   - 统一 D 复盘失败的处理口径：`optimization_cycle.py:478-485` 现在普通模式和外部运行器模式的处理不一样。
3. **前端改动**：「下一轮」被拒时，页面要显示原因以及「系统将自动先做生成诊断」或「需要你做什么」，不能只是失败。
4. **`scripts/run_e5_unattended.py` 改成薄壳**：只负责启动或查询编排任务，不再自己实现任何步骤。删除 `scripts/run_e5_forever.sh`。
5. **故障注入回归**（隔离临时数据库 + 假 Provider + 复制的真实记录，不跑真实 E5）：
   - 在 Sandbox 的第 25 题、生成诊断中途、D 中途、最终复测中途分别模拟 SSL EOF、429、503，流程都能自动恢复；
   - 在 Sandbox 中途 kill 进程，重启服务后自动续跑，已经落库的题不重跑；
   - 分别用按钮、脚本、服务重启恢复三种入口，把「第 1 轮 → 生成诊断 → 第 2 轮 → D → 复测 → 发布」完整跑一遍。三条路径的阶段判断、资格、推荐和费用记录必须一致。
   - 验收**不要求**一定产生 D 或一定发布。没有增量收益时，正确结果就是保留当前线上版本。
