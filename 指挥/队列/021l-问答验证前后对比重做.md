## 页面结构（对照设计稿，从左到右、从上到下）

### ① 左侧题目列表（宽 300，跟随滚动，列表内部滚动）
- **筛选**：顶部用分段切换："修好的 N"（默认）、"仍未修好 N"、"全部 50"。N 按保存结果计算。
- **搜索**：下方一个搜索框，按题目原文过滤。
- **每题一行**：
  - 短题号 Q04；
  - 题目原文，两行截断，悬停看全文；
  - 第二行是两个小圆点表示"优化前 › 优化后"的对错（红、绿），再跟题型（正向题、消融题、应拒答题，用现有 `test_category` 映射）。
- **选中态**：浅绿底，左侧 3px 绿条。
- **原来那排大卡片按钮删掉。**

### ② 题目头
- 小字"Q04　正向题"；
- 题目全文，19px，半粗；
- 右侧判定变化徽章："优化前 答错 › 优化后 答对"，颜色按对错。

### ③ "这道题为什么变好" + "必答要点对照"（一张卡，左右分栏；窄屏时上下排）

**左栏：竖向三步时间线**（配置变化 → 关键证据位置 → 回答结果），按以下规则生成：
- **配置变化**：判断哪个参数是本题的关键。
  - 优化前该证据已进重排，但没进回答（`final_rank` 为空，`rerank_rank` ≤ 优化后的证据条数），优化后进了回答 → 关键是"回答证据条数"。
  - 优化前该证据没进候选（`candidate_hit=false`），优化后进了候选 → 关键是"查找候选条数"。
  - 其他情况，这一步写"配置差异见下方"，不指定关键参数。
- **关键证据位置**：用两边 `diagnostic_view.evidence_checks` 里同一条证据的 `candidate_rank`、`rerank_rank`、`final_rank` 生成，例如：
  > 说明书里"只在室内存放设备"这段重排第 5 位：优化前被截掉，优化后进入回答第 6 位
- **回答结果**：写出"补上了必答要点 ①……"，对应下面的新满足要点。
- **数据缺失**：缺了就省略那一步，不编。
- **应拒答题**：写"优化前没有拒答、优化后正确拒答"这类事实，依据是保存的判定。

**右栏：必答要点对照表**
- **行**：每条必答要点，来自 `judge_result.atomic_results` 里编号形如 `Qxx-Rn` 的项，不含 `auxiliary_*`。要点文字用 `reference_answer` 的对应行，去掉行首编号。
- **列**：优化前、优化后，显示 ✓ 或 ✕。`state=MET` 为 ✓，其他为 ✕。
- **新满足的行**：浅绿底，加"新满足"字样。
- **序号圆标**：①②③ 用深色圆标，新满足的用绿色。同一序号也用在回答正文的高亮上。

### ④ 两栏回答（等高，正文区固定高度、内部滚动）
- **栏头**：
  - "优化前 / Baseline"，或"优化后 / 方案 D"；
  - 右侧徽章写"答错　要点 2 / 3"或"答对　要点 3 / 3"。
- **栏头下方提示条**：
  - 左栏有遗漏的要点时，用风险色写"缺少要点 1：……"；
  - 右栏有新满足的要点时，用绿色写"新满足要点 1：……"。
  - 没有就不显示。
- **回答正文结构化渲染**：这是用户最在意的一点。
  - **Markdown 要真正渲染**：标题、加粗、有序和无序列表、段落。不许露出 `**` 之类的符号。
  - **修掉现在的错误**：文件名里的下划线被当成斜体。做法是先把引用文本整体换掉，再交给 Markdown 渲染。
  - **引用改成编号小圆标**：`（《xxx.pdf》，章节，第N页）`、`按《xxx.pdf》"章节"（第N页）`、`（同上）` 这类引用，从正文里拿掉，换成上标小圆标 1、2…。同一来源同一页用同一个编号，"同上"沿用上一个编号。
  - **只动引用**：除了引用文字，回答的任何字都不改、不删、不调换顺序。
  - **结尾说明框**：回答末尾以"证据边界："、"未确认条件："这类加粗标签开头的段落，放进浅灰说明框。
- **正文高亮**：只用保存判分里的 `atomic_results[].answer_quotes` 定位。
  - 匹配前，把引文和正文都去掉 Markdown 符号和引用文字后再比对。
  - **新满足的要点**：对应句子用荧光笔绿底，前面加绿色序号圆标。
  - **两边都满足的要点**：对应句子加细绿下划线，前面加深色序号圆标。
  - 找不到原句就**不高亮**，不用关键词猜。
- **栏底"引用来源"**：
  - 列出编号和来源，例如"1　卡赫 KIRA B 50 操作说明，存放，第 85 页"，可以点开看原文（复用现有证据抽屉）。
  - 文件名转成易读的短名：去掉 `.pdf`，下划线换成空格。
  - **只列正文里真正引用的来源。** 现在把检索到的全部证据都列在下面，导致 KIRA 的题下面出现 B2 的文件，看起来像引用错了。
  - 下面一行小字："检索到 N 段证据，回答引用 M 段"。N 是 `retrieval_trace.final` 的条数。

### ⑤ 数据佐证卡（两栏回答下方，通栏）
- **"两次回答的配置差异"**：
  - 只列优化后和 Baseline 不同的参数，用胶囊标签显示，例如"回答证据条数 4 → 6"。
  - ③里认定的关键参数，胶囊加绿边绿底，并标"本题关键"。
- **"本题数据"表**：
  - 列：指标、优化前、优化后、对比条、变化。
  - 行：
    - 必答要点 x/y；
    - 本题回答耗时（`programmatic_metrics.latency_ms`）；
    - 首字时间（`ttft_ms`）；
    - 其中检索、其中生成（`stages` 里的 `retrieval`、`generation`）；
    - 进入回答的证据（`retrieval_trace.final` 条数）。
  - **对比条**：灰条是优化前，绿条是优化后。时间类各行共用一个刻度，刻度是两边总耗时里较大的那个；数量类各行按本行较大的值。
  - **加粗规则**：较好的一方加粗；较差的一方如实显示，不隐藏。时间越短越好，要点和证据越多越好。
  - **变化列**：只写差值，例如"−7.1 秒"、"+2 段"，不写"优势、提升"之类评价词。
  - **缺数据**：缺了写"未知"，对比条留空。
- 表下一行小字说明数据来源。
