## 为什么改（总指挥已核实）

021a 之后，Agent 对当前实验给出"不做 D"。理由是：回答证据条数 6（`top_k=6`）在历史上"伴随安全拒答率掉到 90% 并新增受保护题错题"。

但这两条副作用记录的**前提配置和 Winner 不同**：

| 历史方案 | 前提配置 |
| --- | --- |
| R1-C | 候选池 12、思考 high |
| R2-B | 候选池 12、思考 max |
| Winner R3-C | 候选池 24、思考 high |

候选池不同，进入前 6 条的说明段落就不同，副作用不能直接照搬。Agent 把"不同前提下观察到的副作用"当成了必然结果，从而放弃验证。

D 的产品逻辑应该是：Winner 合格但还有错题 → Agent 用前几轮总结的经验形成 D → 跑 Sandbox 验证 → 成功或失败都有原因。所以要改两处。

## 要做的

### 1. 事实表的副作用档案加"前提对照"

`d_facts` 里，参数副作用档案的每条记录都要加上：
- 这次观察的方案，相对 Winner 有哪些参数不同（大白话列出）；
- 一个标签：**"前提与 Winner 相同"** 或 **"前提不同：……"**。

Agent 提示词要写明：前提不同的副作用记录是**风险提示**，要写进风险清单、在 Sandbox 里重点核对，**不能单独作为放弃的理由**。

### 2. 有已验证的修题参数时，必须形成 D

**规则**：只要事实表里至少有一道剩余错题，存在满足下列条件的修题参数，Agent 就**必须生成 D**，不得只凭预测的副作用放弃：
- 历史上修好过它；
- 在 Winner 配置下证据位置支持这个参数能起作用；
- 取值在 Pipeline 选项里；
- 不撤销 Winner 的改动。

生成时，在 `side_effect_check` 里写清楚：
- 要重点盯哪些受保护的题和临界门槛；
- 前提相同和前提不同的证据分别是什么。

**"不生成"只在以下情况合法**：没有任何剩余错题存在这样的参数；或者所有可用参数都要撤销 Winner 的改动。

**代码校验**：事实表存在可用的修题参数、Agent 却返回不生成时，判为"不合规"，带原因重出，规则同现有 3 次重试。

其他 D 规则全部不变：
- 最多改 2 个参数；
- 已验证参数优先；
- 必须有副作用检查；
- D 必须胜过 Winner 才推荐；
- 门槛、评分要点、回归、发布资格不变；
- 只做一个 D，占 1 次额度（9/12 变成 10/12）。

### 3. 给当前实验重新判断 D
- 先确认没有活动评测，再重启后端；
- 对 `EXP-20261105143048349606` 重新发起 D。上一次"不做 D"的记录保留在历史里（技术详情可查），**前端主画面显示最新一次 D 的结论**；
- 生成 D 后自动跑完整 50 题 Sandbox，跑完自动重算推荐，到发布前停下，**不发布**；
- **Agent 看不到内部复核和内部试跑的任何数据**：它们在单独私库里，不许接入事实表或提示词。

### 4. 测试
临时库加 Stub 覆盖以下情况：
- 前提对照标签正确；
- 有可用修题参数时不生成被拒并重出；
- 没有可用修题参数时不生成合法；
- 生成的 D 里写有前提不同的风险清单；
- 前端 D 节点显示最新一次结论，旧结论只在技术详情里。
