# 101：规则指纹、运行快照绑定、端到端一致性核对（不花钱）

**依据**：规则总表十一；GPT 反审 V1 第六节（Claude 已采纳，见 `指挥/互审/03-*.md`）。

**前置条件**：100 已完成，规则一致性测试通过。100 没完成的话，先在报告里写明，再做本单里不依赖 100 的部分。

## 要做的事

1. **规则指纹**
   - 在 `rules.py` 里增加 `RULES_HASH`：取规则对象规范化 JSON（键排序、去空白）的 sha256，保留前 12 位。
   - `test_rules_sync.py` 里校验：规则总表文末规则块算出来的 hash，与 `RULES_HASH` 相同。

2. **每次评测（Baseline 和 Sandbox）绑定启动时的快照**，写入评测记录。字段如下：
   - `rules_version`、`rules_hash`；
   - `pipeline_config`：本次实际使用的完整配置；
   - `judge_config`：模型、思考档、温度、判分次数；
   - `search_space_version`：可调参数白名单及取值，取 hash；
   - `prompt_version`：Strict/Looser/Safe 三个回答模板、Judge 提示、Agent system prompt 模板，各取 hash；
   - `golden_version`、`knowledge_identity`。

3. **续跑保护**
   - 断点续跑前，重新计算当前的 `rules_hash` 和 `prompt_version`，与原记录比较；不一致就拒绝续跑，并报错写明哪一项变了。
   - 要补单元测试。

4. **端到端核对脚本 `backend/scripts/rules_e2e_check.py`**（不调用付费接口）。三方核对一致：
   - 实际构造的 Agent prompt（用 `build_agent_prompt` 和一份假的 Baseline 数据）；
   - 后端给前端的参数说明接口的返回值；
   - 将要发给 Provider 的请求参数。在发送前截获，**不真正发送**。

   检查以下几项：
   - 思考档关闭；
   - 温度为 0；
   - 搜索空间与 `rules.py` 一致；
   - 文字里没有"Baseline 用 Max/High""降档补位""保证一致"之类的旧说法。

   输出 `指挥/报告/101-端到端核对.md`，逐项写：一致或不一致，并附原文片段。

5. **值班脚本**：开工前的一致性检查加上这个脚本（或它的快速模式）。
