# 122b 统一 Provider 重试与费用账本（ST-02，不花钱）

依据：互审 56 第二节第 2 条。前置：122a 完成。

## 要做的事

1. **统一重试，只在 `app/providers.py` 一处实现**，覆盖 DeepSeek 和阿里云（`knowledge_pipeline.py:902-967` 的阿里云请求也改为走这里）。
   - **可恢复的传输异常**：SSL/EOF、连接重置、临时 DNS 异常、超时、HTTP 408/429/500/502/503/504。
   - **请求级重试**：首次请求之后最多再试 3 次，间隔 5、15、30 秒。遇到 429 时，优先遵守 Retry-After，单次等待最多 120 秒。
   - **任务级等待恢复**：请求级重试用完后，任务进入 `retry_wait` 状态，再按 1、2、5、10 分钟的间隔从断点续跑，最多累计 60 分钟。仍然失败才进入 `blocked`，并写明原因和继续的方法。
   - **重试计数共享**：Provider、`evaluation_stage.py:79-169`、编排器三层共用同一个计数，不得相乘。
   - **不可重试的错误**，直接 `blocked`：401、402、403、余额不足、身份不一致、数据损坏。
   - **重试期间禁止**：换模型、降低 thinking、修改参数、删减证据。
   - 用户主动停止时，所有自动重试立即停止。
2. **费用账本**（基于 `paid_run.py:82-164`、`paid_policy.py:30-58`）：
   - 每次真实请求都按「预留 → 发出 → 保存响应 → 结算」四步记账；
   - 结果不确定的请求（可能已执行但没收到完整响应）按上限保守占用预算，不得按 0 元计；
   - 同一实验的所有入口（按钮、脚本、恢复）读取同一份授权和剩余预算。
3. **删除 `scripts/run_e5_unattended.py` 中的 `no_transport_retry` 及相关 monkey patch**（149-157、494-498 行），改用统一重试。
4. **单测**（临时数据库 + 假 Provider）：
   - 连续 2 次 SSL EOF 后成功；
   - 429 带 Retry-After；
   - 请求级重试用完后进入 `retry_wait`，之后成功续跑；
   - 401 直接 `blocked`；
   - 请求结果不确定时，保守记账；
   - 三层重试的总次数不超过上限；
   - 用户停止后不再重试。

## 约束

- 不调用真实模型。
- 不改评测和合格规则。
- 所有测试都给 GovernanceStore 显式传入临时数据库路径（互审 47 事故）。
