# 125a：每轮填满 A/B/C，定向检查只排序不拦，累计上限改为 4（不花钱）

- **依据**：互审 62「E6 完成与复盘」。用户 11-26 18:27 指出 E6 每轮只跑了 A；18:4x 用户拍板：累计改动上限放宽到 ≤4，E7 不设预算上限，前端小问题留到 UI 改造时再修。
- **费用**：0。只改规则代码和测试。

## 问题（E6 只跑了 A 的三个原因）

1. **定向检查成了门票**：`agent_round_contract.py` 对每个可选改法跑一次 `validate_mechanism`，要求有定向检查（预演）证据，否则判为「拒绝」，导致 `available` 只剩预演证明有效的改法。
2. **组合名额**：`available_labels` 和 `layer_capacity` 要求每轮最多 1 个双参数组合（`sum(len(keys) > 1) <= 1`）。`combination_used and len(changes) > 1` 还会挤掉后续的组合。第 2 轮里「关键词权重 + 多路查询」已在预演中修好 Q24 的证据，却被挤掉了。
3. **累计上限 3**：`rules.AGENT['d_max_changed_parameters'] = 3`，第 2 轮后已经没有可走的改动，第 3、4 轮和 D 都触发不了。

## 要改的规则

1. **定向检查只用来排序，不再拦截**：
   - 预演有证据的改法标为「有证据」，排在前面；
   - 预演没有证据（或没做预演）的改法，只要 Agent 写清楚机制假设，也可以作为「探索性方案」进入 Sandbox，标为「探索性」；
   - 仍然拦截的情况：预演证明会让已答对的题变错，或会让已在 Final 的标准证据掉出去，这类结论保留为「拒绝」。
2. **每轮填满 A/B/C**：
   - 只要还有合法且没试过的配置，每轮就出 3 个方案（不足 3 个时，有几个出几个），每个方案对应不同的假设；
   - 每个方案改动不超过 2 个参数；同一轮内各方案的参数互不重叠，这条保留；
   - **取消「每轮最多 1 个组合」的限制**；
   - 目标层的合法改法不足 3 个时，按优先级从下一层补足探索性方案。
3. **累计上限改为 4**：`d_max_changed_parameters` 从 3 改为 4，Winner 链和 D 都按 4 计算。
4. **轮次与 D**：最多 4 轮、12 次 Sandbox（预留 1 次给 D）。只要还有 Bad Case 且还有合法未试配置，就继续跑下一轮；D 按 122f 的规则触发。
5. **不变**：资格判定（门槛、零关键回退）、Judge、题卷、Baseline 都不动。旧实验沿用旧决策版本，新实验写入新版本号 `125a`。

## 测试（临时库，显式传入临时库路径）

用 E6 的真实形态做两个夹具：

- **第 1 轮**：只有「关闭精排」有预演证据。修改后应出 3 个方案，其余 2 个标为探索性。
- **第 2 轮**：有两个双参数组合都有预演证据。修改后两个都能进入，且参数不重叠。

另外补充：

- 累计上限 4 生效，改动第 5 项时被拒；
- 预演证明会回退的改法依旧被拒；
- 旧实验的决策版本不受影响。
