## 2. 无人值守的状态播报
总指挥在云端只能看 GitHub，看不到本机后端。需要一个后台小脚本，定期把运行进度写到 GitHub。

- **新增两个脚本**：
  - `scripts/export_run_status.py`：只读，汇总当前状态，写成 `指挥/运行状态.md`；
  - `指挥/自动值班/状态播报.sh`：负责定时调用和推送。
- **`指挥/运行状态.md` 只放这些内容**，不放题目原文、回答原文、密钥：
  - 更新时间（多伦多时间）；
  - 当前阶段：知识库重建 / 题卷锚定 / Baseline / 第几轮第几个 Candidate / Candidate D / 已完成 / 出错；
  - 当前任务的完成题数 / 总题数；技术失败数；
  - 是否因非平价时段暂停，以及预计恢复时间；
  - 预算已用 / 总数；到目前的费用估算；
  - 最近一次错误的类型和一句话说明；
  - 已完成的评测：编号、答对、Hard Gate 通过数、P50、P99。
- **播报脚本的行为**：
  - 每 20 分钟运行一次导出；
  - 内容和上次一样就不提交；
  - 有变化时，只提交这一个文件：`git add 指挥/运行状态.md && git commit -m "运行状态：… (No SPEC Change)" -- 指挥/运行状态.md`，然后 `git pull --rebase --autostash` 并 `git push`；
  - 失败（例如 index.lock 被占用）就等下一轮再试，不报错退出；
  - 用 `nohup` 加 `setsid` 在后台常驻，PID 写进 `本机快照/状态播报.pid`；
  - 提供 `--停止` 参数，用来结束常驻进程。
- **例外授权**：这个播报进程是总指挥要求的常驻程序，本单结束时**不要关掉它**，这是 AGENTS 规则 8 的例外。脚本自己的 git 提交不违反"Codex 不运行 git 写命令"，因为提交的是脚本，不是你。
- **启动**：本单最后启动播报进程，并确认第一份 `指挥/运行状态.md` 已经生成（推送由脚本完成）。
