# 125a1：Baseline 的 Bad Case 改用和 Agent 同一套 122f 分层显示（不花钱）

- **依据**：用户 11-26 18:56 截图。Baseline「Bad Case 诊断」页显示检索层 8、生成层 8，严重程度全是「一般」，「层级与细分」只写「检索层问题」，主题全是「未知」。但 Agent 用的 122f 分层是：检索层 8 道（召回失败 3 道致命，排序或筛选 5 道严重），生成、安全、性能都是 0。两套结果对不上，用户看不出到底错在哪。用户确认先修这个，再跑 E7。
- **费用**：0。

## 原因（总指挥定位，供参考）

- `frontend/src/components/ProductDiagnostics.tsx` 按 `diagnostic_view.issue_layers` 计数，一题可以同时算进多层。检索没找到导致答漏要点，又被算进了生成层。
- 严重程度取自旧 `diagnostics.py` 的分类，不是 122f 的 `agent_mechanism.faults_for_cases`。
- M2 题卷没有业务主题字段，所以「主题」一列显示「未知」。

## 要做的事

1. **后端**：Baseline 诊断接口为每道错题返回 122f 结果，和 Agent 读到的完全一致，包括层（检索、生成、安全、性能）、细分（例如「没检索到」或「检索到但没进最终资料」）、严重程度（致命、严重、中等、轻微）和原因。必须复用 122f 同一个函数，不能另写一套判断。
2. **前端「Bad Case 诊断」**：
   - 四张层卡片按 **122f 根因**计数，每题只算一层，总数等于 Bad Case 数；
   - 「层级与细分」显示例如「检索层 · 没检索到（召回失败）」「检索层 · 检索到但没进最终资料（排序或筛选）」；
   - 「严重程度」显示 122f 的级别（致命、严重等），颜色沿用现有语义色；
   - 由根因带出来的现象（例如「回答漏了要点」）放在详情抽屉里，标为「连带现象」，不计入生成层卡片；
   - 「主题」一列：没有主题时改为显示「题型细分」（M2 的 `question_subtype`），列名相应改成「题型细分」。前端不出现「未知」。
3. **一致性测试**：Baseline 页显示的各层数量和逐题细分，与 Agent 工作台 / 122f 的结果一致。用临时库加模拟数据测试，覆盖 E6 Baseline 的形态（8 道全在检索层，3 道致命、5 道严重）。
4. **核对**：用正式 Baseline `EVAL-20261126212249302614` 打开页面，在 1440×812 下截图核对，截图不提交。页面应显示：检索层 8（致命 3、严重 5），生成、安全、性能都是 0，逐题细分正确。
