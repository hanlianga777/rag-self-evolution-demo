# 088：Agent 策略展示精简——第一眼看懂"改了哪里、依据什么、结果如何"（不花钱，只改前端）

## 用户要求（2026-11-19 08:50）

前端的 Agent 策略文字冗长、AI 味重。思考过程不能删，但第一眼要能看懂 Agent 优化了哪里、根据什么优化。表述要简单、清楚、意图明确，用短句，不要长难句。

## 参照朋友的写法

- **Colin**：卡片标题写成 `A | 加大候选池+放宽top_k`，下面两行：
  - `针对: retrieval_miss`
  - `动作: boost_candidates → widen_top_k`

  另有一张"异同对比"表，列出 Baseline、A、B、D 的门槛通过数、失败题、动作、参数值。
- **扣子**：方案写成 `方案A：「激进检索优化」（检索优先）`，核心思路只有一句话，下面是"参数 / 基线值 / 方案值 / 预期影响"四列表。

## 要做的事

所有新文字都**由程序从已保存的结构化字段拼出来**，不调用模型，也不改后端数据。

### 1. Candidate 卡片首屏（`pages/EvolutionPage.tsx` 的 `CandidateCard`）

首屏固定为 5 行，每行一句：

| 行 | 内容 | 示例 |
|---|---|---|
| 标题 | `Candidate A · {strategy_name}`，名字过长时截断 | |
| 改了什么 | 参数英文名 + `基线值 → 方案值`，多个用"；"隔开 | `Candidate K 12 → 24；Top-K 4 → 6` |
| 针对 | 目标错题的题号，以及它们的诊断类别（检索层 / 生成层 / 安全边界 / 性能），按类别计数 | `检索层 5 题：Q16、Q17、Q18、Q20、Q21` |
| 依据 | 有检索预演（`experiment.result` 或 `audit` 里 Agent 输入保存的 `retrieval_preview`，按实际字段核对）时，写"预演：改后 Q16、Q20 的证据会进入资料"；没有预演时，写 `predicted_fixed_question_ids` | `预计修好 Q16、Q20` |
| 结果 | 已评测才显示 | `修好 Q16、Q20 · 新错 Q30 · 43/50 · 门槛 11/11 · 合格` |

原来的"思路"长段落（`direction · strategy_name · core_idea/hypothesis`）移到卡片内的"展开 Agent 完整思考"，默认折叠。完整报告抽屉保持不变。

### 2. 每轮"Agent 策略"面板（`components/RoundStrategy.tsx`）

最上面加一行摘要，例如：

> 本轮发现：检索层 5 题、生成层 2 题、安全边界 2 题 → A 检索召回、B 资料段数、C 回答提示词

- 类别计数来自 `bad_case_summary.groups`；方向来自各 Candidate 的 `strategy_name`。
- 原来的三段内容保留，但默认折叠在"展开详细分析"里。

### 3. 每轮"本轮结论"面板（`RoundConclusion`）

每个 Candidate 一行：

> Candidate A：预测中 2/5 · 修好 Q16、Q20 · 新错 Q30

- 这一行之后加"判断：{conclusion}"，按句号截断到第一句。
- 逐题原因和经验条目默认折叠。

### 4. 跨方案总表

在 Agent 工作台"Candidates 对比"页签顶部，加一张简表（学 Colin 的"异同对比"）：

- **列**：Baseline、各轮 A/B/C、D。
- **行**：改了什么、门槛通过数、答对数、修好、新错、是否合格。
- 已跳过或未运行的显示"未运行"。

## 文字规则

- 参数名用英文（同 073）。
- 每格一句话，不超过 40 个汉字；超出就截断并加悬停显示全文。
- 不出现"综上""值得注意的是""旨在"这类套话。
