# 126c Agent 策略 v126：每种情况都由 Agent 判断应对，加三层资格、主线和支线、D 按需综合（不花钱）

- **依据**：互审 63、64；用户 11-27 09:41 和 09:56 拍板。用户最看重这一单：**每一种情况都要有 Agent 的应对，不是写死的规则。**
- **费用**：0。用模拟 Provider，不调用付费模型。
- **决策版本**：`126c`。旧版本保持不变。

## 总原则：程序给信号、划边界，Agent 选动作、讲理由，Sandbox 当裁判

| 谁 | 做什么 | 不做什么 |
|---|---|---|
| 程序 | 算出事实和「情况信号」，给出这个情况下的**合法动作清单**和硬约束 | 不替 Agent 选动作 |
| Agent | 从合法动作里选，写理由、机制假设、预计修好哪些题、可能伤到哪些题 | 不能越过硬约束 |
| Sandbox | 实测收益和副作用，三层资格 | — |

**硬约束**（程序强制，Agent 不能改）：

- 参数白名单；
- 相对父方案每次最多改 2 项；相对 Baseline 累计最多改 4 项；
- 零新增错题才能算合格；
- 安全零回退；
- 性能门槛；
- 不允许重复配置。

## 一、诊断 → 工具范围（错因菜单）

用 126b 的「细分错因 × 题型」查表，得出「推荐工具」和「允许探索工具」，再交给 Agent：

| 细分错因 | 题型线索 | 推荐 | 允许探索 |
|---|---|---|---|
| 没检索到 | 别名 / 口语 / 弱关键词 | query_rewrite、multi_query | HyDE、关键词权重、hybrid_alpha |
| 没检索到 | 跨段 / 桥接 / 复杂子问 | query_decompose、multi_query | candidate_k、HyDE |
| 没检索到 | 其他 | candidate_k、min_score | multi_query、hybrid_alpha |
| 找到但没交给模型 | 任意 | top_k、rerank | candidate_k、min_score |
| 表格理解错 | 表格统计 | generation_thinking、回答提示词 | top_k |
| 漏要点 / 多步骤 | 跨段 / 多步骤 | top_k、回答提示词 | decompose、thinking |
| 过度拒答、该追问没追问 | 负向 / 条件 | 回答提示词 | thinking |
| 安全越界 | 安全 / 注入 | 回答提示词（Safe） | — |
| 慢 | 任意 | 按分阶段耗时，选 thinking、检索规模或查询增强 | — |

规则：

- Agent 优先在推荐里选。选「允许探索」的，必须写机制理由。
- 菜单以外但仍在白名单内的参数，只能作为 C 位的「差异化探索」，并写清楚理由。
- 白名单以外的参数一律拒绝。

**优先级**（程序给出排序，Agent 可以写理由调整名额分配）：

1. 安全违规；
2. 没过的门槛的根因；
3. 严重度；
4. 剩余错题数；
5. 上下游依赖（检索修好以后，生成问题才看得准）。

默认把 2 个名额给最优先的层，1 个给次优先的层或跨层。

## 二、每轮 A/B/C 的分工

| 位 | 角色 | 底座 |
|---|---|---|
| A | 主线：修当前最主要的问题 | 当前 Winner；没有 Winner 时用 Baseline |
| B | 互补：修主线还没覆盖的题，或改良支线 | Winner、支线或 Baseline 里任选，写理由 |
| C | 差异化探索：换一种机制、做组合、消除前面方案的副作用 | 按证据选 |

- 第 1 轮还没有 Winner，A、B、C 都以 Baseline 为底座，三个方案必须对应不同的假设。
- **允许 2 参数组合**的情况：参数之间有依赖；要用一个参数抵消另一个参数的副作用；跨层协同。标注为「组合机制假设，单项贡献尚未单独验证」。
- **取消同一轮参数互斥**，改成禁止重复配置、禁止重复假设。
- **允许撤销或替换已经继承的参数**，前提是保护已答对的题。
- 每个提案必须写：父方案、改动、机制假设、预计修好哪些题、可能伤到哪些题，以及用了哪条情况信号。

## 三、三层资格（三个独立标签，没达到不等于丢弃）

| 标签 | 和谁比 | 条件 |
|---|---|---|
| 合格 | 原 Baseline | 门槛全过、零新增错题、至少修好 1 题。**这也是发布资格**，和任何旧版本、旧线上版本无关 |
| 本轮有效 | 父方案 | 零回退，并且至少多修好 1 题（或修好一项性能门槛） |
| 晋升 Winner | 全局 Winner | 保住全部已有成果，并有严格增量 |

- 每个方案在前端显示三个标签。例如「合格 · 本轮无增量 · 未晋升」。
- 「修好了哪些题」「弄坏了哪些题」全部记进**经验账本**。

## 四、主线、支线和经验账本

- **主线**：当前 Winner，只有 1 个。
- **支线**：最多 1 条。选法看互补性，不看分数：修好了 Winner 没修好的题，或者性能明显更好。合格方案优先；不合格但局部有效的方案，可以把它的机制留给后面改良。
- **经验账本**：记录所有方案、修好的题、弄坏的题、预测命中情况。Agent 每一轮都要读账本。
- **E8 只用 E8 自己的账本，不读任何旧实验。**

## 五、情况手册：每种情况都由 Agent 选应对（必须全部实现并测试）

程序检测到下面的情况，就把「情况信号 + 合法动作清单」交给 Agent。Agent 选一个或多个动作，并写理由。

| # | 情况（程序信号） | 合法动作（Agent 自选） | 硬约束 |
|---|---|---|---|
| S1 | 第 1 轮，没有 Winner | 在 Baseline 上提出 3 个不同假设 | 三个假设不能重复 |
| S2 | 一轮里有多个合格 | 选 Winner；从剩下的里挑互补支线；把多余方案的经验记进账本 | 晋升 Winner 必须严格增量 |
| S3 | 一轮全部不合格 | 保留原底座；改良某个方案的局部有效机制（加缓解参数）；换机制；换层 | 底座仍然是 Baseline 或原 Winner |
| S4 | 有 Winner 后，这一轮全部没有增量 | 换支线做底座；换机制；撤销 Winner 里可疑的参数；试 D | — |
| S5 | 连续两轮没有增量 | 由 Agent 判断：还有可信假设就继续；有互补组合就做 D；都没有就结束并写明理由 | 结束要写理由 |
| S6 | 支线超过主线，并保住了主线成果 | 让支线晋升为新主线，原主线降为支线 | 按三层资格判定 |
| S7 | 支线总分更高，但丢了主线修好的题 | 不晋升；作为支线保留，后续用组合修复 | — |
| S8 | 单参数有效但有副作用 | 用 2 参数组合消除副作用；换等效参数；接受，留给 D | 零新增错题才合格 |
| S9 | 错题分布在多层 | 按优先级分配名额，Agent 可以写理由调整 | 安全优先 |
| S10 | 某层没有错题 | 不动这一层；除非有跨层作用，并写明理由 | — |
| S11 | 提质量需要更多耗时 | 可以，在门槛内；同等质量时选更快的 | 性能门槛 |
| S12 | 性能门槛没过 | 把性能当成目标，按分阶段耗时找原因 | — |
| S13 | 出现安全题回退 | 该方案不合格；Agent 分析是哪个参数导致，下一轮避开或缓解 | 安全零回退 |
| S14 | 剩下的题工具箱修不了（所有相关工具都试过，或诊断为知识库或切块问题） | 结束这类题的优化，输出「能力边界与工程建议」 | 要列出依据 |
| S15 | Judge 波动造成疑似修复（三样本不一致） | 不计为有效修复；按现有的「只复核结论变化的题」机制复核后再计 | 按现有判分兜底规则 |
| S16 | 全部答对，门槛也达标 | 正常结束，直接发布，不强制做 D | — |
| S17 | 提案被校验拒绝（格式、字段、约束） | 把拒绝原因反馈给 Agent，让它自动修正后重提。**不限次数，不停实验**；连续 3 次被拒，程序就把被拒字段改为结构化逐项填写 | 原校验标准不放宽 |
| S18 | Sandbox 技术故障（超时、截断、网络） | 从断点续跑，复用已付费结果 | — |
| S19 | 上一轮预测和实测偏差很大 | Agent 下一轮必须先复盘「哪条假设错了」，再提新方案 | 复盘写进 Trace |
| S20 | 累计改动到了 4 项 | 只能替换或撤销已有参数，不能再新增 | 累计 ≤ 4 |
| S21 | 预演显示可能回退 | 降低排序；如果仍然要提，必须附带缓解假设 | 预演只排序，不拦截 |

## 六、D：按需综合

- **触发**（同时满足）：
  1. 已经有 Winner；
  2. Winner 仍有剩余错题；
  3. 账本里有还没验证过的互补组合假设；
  4. 组合后累计改动 ≤ 4；
  5. 还有 Sandbox 名额。

  **时机**：主要的层已经探索完，S5 出现，或者快到上限了。
- **来源**：
  - 合格支线；
  - 不合格方案里局部有效的参数，必须同时附上缓解副作用的假设；
  - 撤销或替换已有参数；
  - 有可信机制的新参数。

  禁止为了展示而组合。
- **结局**：
  - D 晋升，成为最终推荐；
  - D 没晋升：拒绝晋升，保留 Winner；
  - D 没生成：写明理由。

  三种都是正常结束。

## 七、轮次和停止（11-27 10:05 用户裁定，覆盖原稿）

- **不设轮次上限，不设 Sandbox 次数上限。**
- 正常结束由「七之二」的收敛条件决定，Agent 写结论。**合格只是门票，不是终点。**
- 还没有合格 Winner 时**不能结束**。Agent 必须按 S3、S4 继续提出新假设，直到产生合格 Winner。
- 只有两种情况允许停：Codex 额度用完；DeepSeek 余额不足。停之前保存断点。
- 其他异常由 Codex 自修，然后从断点继续。**不得以「连续失败 N 次」为由停下来等用户。**

## 七之二、最终目标与「收敛才发布」（11-27 10:11 用户裁定）

**最终目标**：在不新增错题的前提下，让答对的题尽可能多。不是「比 Baseline 好就收工」。

**禁止提前发布**：合格只是候选进入下一步的门票，不是结束条件。例如第 1 轮就出现 43/50 的合格方案，也必须继续往下跑。

**结束条件**：程序检查，Agent 写结论。满足以下任一项才结束：

1. **满分**：50 题全对，并且门槛全过。
2. **收敛**：下面 4 条同时成立。
   - **a. 错题逐题穷尽**：当前最优方案剩下的每一道错题，都已经处理完。处理完的标准是下面两种之一：
     - 这道题对应的「细分错因 × 题型」推荐工具，都已经在主线或支线上试过（单独试或组合试都算），仍然没能在不伤别的题的前提下修好它；
     - 126b 诊断为「待确认」，或者属于知识库、切块问题，标为「能力边界」，并写出依据。
   - **b. 跨层都探索过**：有错题的每一层（检索、生成、安全、性能）都至少分到过一个方案名额。
   - **c. D 已经处理过**：账本里有还没验证的互补组合时，D 已经跑过；没有这种组合时，Agent 写明「没有可组合项」的理由。
   - **d. 进入平台期**：最近一轮没有任何方案晋升为 Winner。

**结束以后**：发布最终推荐。如果 D 晋升了，就发布 D；否则发布 Winner。发布条件是对 Baseline 合格。

**为什么这样定**：

- 用「每道剩余错题的可用工具都试过」作为终点，而不是用轮次数。剩下的错题多，就多跑几轮；少，就少跑几轮。
- 结束时每一道没修好的题都有交代：要么试过的工具都没用，要么是能力边界。
- 多层错题的最优解，可能是检索层修一部分、生成层修一部分，再组合起来。所以 b 和 c 两条要求跨层探索和 D 组合必须先做完。

## 九、测试（必须全部通过才能交单）

**说明（用户 11-27 10:05 关心费用）**：这里的测试全部是代码层面的自动化测试，用模拟数据和模拟 Provider（假的 DeepSeek 和 Judge 回包），**不调用任何付费模型，不重跑 50 道题，费用为 0**，几分钟就能跑完。

目的：在花钱的 E8 之前，把「提案被拒后卡住」「情况没被识别」这类代码错误提前抓出来。E7 曾因为提案连续被拒停在半路，这类测试就是为了避免同样的事发生。

1. 对 S1～S21 每条情况，各写一个小夹具：用几道假题、假结果构造出这种情况。验证四件事：
   - 信号能被检出；
   - 合法动作出现在 Agent 输入里；
   - 合理选择能被接受；
   - 违反硬约束的选择会被拒绝。
2. **端到端演练**：用模拟 Provider，依次经过 S1 → S3 或 S2 → S8 → S6 或 S7 → S5 → D 晋升或未晋升 → 发布，确认从头到发布不卡住。另外加一条「D 没生成，直接发布 Winner」的分支。
3. 三层资格、主线切换、撤销参数、累计上限，各写单测。
3b. 收敛条件单测：第 1 轮出现合格方案（例如 43/50），但还有错题的推荐工具没试过时，**不得结束**；4 条收敛条件逐条缺一项时，都不得结束；满分时可以立即结束。
4. 一律用临时库，显式传入临时库路径。
