# 任务 021b：前端"故事展现逻辑"——Agent 工作台（含方案 D）、发布、问答验证、概览（自动值班）

用户已授权：中间所有确认默认同意，不要停下来等人。**这次不是换视觉风格**，是调整页面讲故事的顺序和内容，让面试时能顺着页面讲完整条链路。**不调用任何模型。**

## 面试要讲的故事主线

知识库 → Golden 题卷 → Baseline 体检（44/50，6 道错题按四大类诊断）→ Agent 三轮 A/B/C 粗搜（每轮复盘、学到东西）→ 出现合格赢家 → 方案 D 在赢家基础上融合精修（或有理由不做）→ 最终推荐 → 人工发布 → 问答验证看到优化前后的变化 → 线上反馈还能触发下一轮进化。

页面上的数字全部从接口读，不写死。

## 已定的 UI 规则（必须遵守）

- **配色**：只用一种绿色；
- **版面**：不留大块空白；卡片和抽屉尺寸统一，内容多了在内部滚动；
- **表格**：两行截断，悬停看全文；
- **抽屉**：灰色遮罩；
- **进度条**：在所有 Agent 页签上都一直展开；
- **A/B/C**：并排显示；
- **问答页**：一屏放得下；
- **文字**：主画面不露编号、哈希、英文状态或日志样的文字。

**禁止出现**任何关于"大模型不稳定、随机、幻觉、波动、复跑、复赛"的文字。

## 要做的

### 1. Agent 工作台

**(1) 新增"进化路线"页签**，放在"问题诊断"之后，作为讲故事的主画面。从上到下是一条时间线：

**Baseline 节点**
- 答对数、门槛通过数、错题按四大类（检索层、生成层、安全边界、性能）分组。

**第 1…N 轮节点**（按实际轮次自动生成）
- 每轮 A/B/C 三张小卡**并排**，每张写：方向、改了什么（大白话参数名）、错题数和 Baseline 比的变化、修好哪些、弄坏哪些、门槛几道过了、结论徽章（合格 / 未通过及一句原因）。
- 每轮下方一条**"Agent 本轮复盘：学到了什么"**，取下一轮的复盘结论原文（021a 已按轮次保存），1–3 句，不显示 L1、L4 这类编号。
- 没保存的就不显示，不编。

**赢家标记**
- 第一个合格的方案上标"首个合格方案"。

**方案 D 节点**，按实际状态显示：
- **已生成**：标题写"方案 D · 在赢家基础上融合"，一句话说明改了什么、每个改动的来源，例如"已验证 · 来自第 2 轮 B"或"新尝试"。
- **合法不生成**：标题写"Agent 判断不做 D"，附理由。
- **排队或运行中**：显示进度。
- **建议校验失败**：写"方案 D 未形成"，附一句原因。

**最终推荐节点**
- 推荐谁，和 Baseline 的关键对比：答对数、门槛、P99、安全拒答率。
- "去发布"按钮。

**(2) "A/B/C/D"页签加轮次切换**，默认显示最新一轮。D 单独放一张详情卡，分四块：
1. **还剩哪些错题**：每道一行，大白话写证据位置，例如"相关说明排在第 10 位，没被选进回答"；再写历史上谁修好过它。
2. **采纳了什么**：每个改动一行，带来源标签，写清理由。
3. **副作用检查**：每个改动以前伴随过什么，会不会碰到已修好的题，打算怎么规避。
4. **结果**：D 和赢家并列比较错题、门槛、P99，最后一句结论："D 胜出，推荐 D" 或 "D 没有胜过赢家，保留赢家"。

**(3) Sandbox 和回归页签**也加轮次切换。D 运行时，和赢家并列显示。

**(4) "最终推荐"页签**
- 顶部是 Baseline 和最终方案的对比卡；
- 中间"为什么选它"，取保存的推荐理由；
- 下面"其他方案为什么没选"，每个方案一行原因；
- 人工确认已经做过时，不再显示确认控件。

**(5) 页签和进度条**：页签数量不要再增加。"Optimization Agent"页签（逐题覆盖矩阵）如果和"进化路线"内容重复，就并进"进化路线"的折叠详情里，或者改名为"Agent 规划"，二选一，报告里说明理由。

### 2. 发布页

**顶部"待发布方案"**：只有最终推荐方案，即赢家或 D。内容：
- 线上配置 → 推荐配置的**变化项**（只列有变化的参数，用大白话）；
- 质量对比：答对数、门槛、P99、安全拒答；
- 发布检查清单：门槛全过、零新增错题、已有修好的题、人工确认。每项打勾，或写一句为什么没满足；
- "确认发布"按钮（保持现有的二次确认）。

**已发布后**：显示当前线上版本来自哪个方案、发布时间，以及版本历史和一键回滚。

**删掉**主画面上对讲故事没用的审计提示文字，例如"发布审计未完整保存""发布来源需核验"这类，挪进"技术详情"折叠里。不露编号。

### 3. 问答验证页（三个页签保留，调整顺序和内容）

**(1) 实时问答**
- 用当前线上版本回答，顶部一行写"线上版本：第 X 轮方案 Y · 发布于……"，或"当前为初始配置"。
- 引用来源可以点开。
- 一屏放下。

**(2) 优化前后对比**
- 默认给出几道"代表题"按钮：最终方案修好的题，当前是 Q24、Q29、Q38，从数据读。
- 点开后左右并排：Baseline 的回答 vs 最终方案的回答（都用**已保存的评测回答**，不实时调用模型）。
- 下方一句大白话写证据变化，例如"优化前没找到说明书里'不得未稀释使用'这段；优化后排在第 1 位"。
- 保留自由提问的对比方式。如果会实时调用模型，按钮上写明，并且本任务里不点。

**(3) 线上反馈 → 再次进化**（原"监控"页签改名）
- 顶部用一行流程图讲清闭环：用户提问 → 人工标记坏例 → 触发新一轮 Agent。
- 现有功能保留，主画面不露 Trigger 编号。

### 4. 概览页
- 顶部一排"成果"卡：Baseline → 最终方案的答对数、P99、安全拒答率、Agent 轮次、试跑方案数。
- 下面是一条主链路小图（知识库 → Golden → Baseline → Agent → 发布 → 问答验证），每节点可点击跳转对应页面。
- 数字全部从接口读。
