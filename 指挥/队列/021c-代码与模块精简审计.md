## 为什么做

面试时可能有人看仓库。用户希望删掉"没有必要出现的模块"，让架构看起来清楚、有逻辑。但删错会弄坏 demo，所以这次**只审计、出清单**，由总指挥审过后再另开任务删除。

## 要做的

1. **后端** `backend/app/` 下每个模块：
   - 被谁引用（import、接口路由、前端调用）；
   - 属于主链路哪一环：知识库 → Pipeline → Golden → Baseline/Judge → Agent ABC → D → 复赛 → 发布 → 问答验证；
   - 是否是一次性脚本或历史排查遗留（例如 `q18_probe.py`、`retrieval_smoke_test.py`，但要以实际引用为准，不要猜）。
2. **前端** `frontend/src/pages/`、`components/`：每个页面和组件在导航里出现在哪、有没有被用到。
3. **接口** `backend/app/main.py`：每个路由有没有被前端或流程调用；没被调用的列出来。
4. **测试** `backend/tests/`：只测已删除或废弃功能的测试列出来。
5. 每一项给出建议，分四类：
   - **保留（主链路）**
   - **保留（支撑：存储、身份、费用等）**
   - **可合并**
   - **建议删除**

   每项写一句理由。"建议删除"的要写明删掉后影响什么、要同时删哪些测试。
6. 最后画一张**主链路模块图**（Mermaid，写在报告里），标出每个模块属于哪一环。面试讲架构时要用。
