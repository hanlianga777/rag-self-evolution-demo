**防卡住（必须遵守）**：
- 每次开始先查真实状态，从断点接着做；
- 后台作业运行期间用 `sleep 60` 轮询，不要提前结束本次运行；
- 需要点按钮的流程，直接调接口；
- 报错先自己修，实在修不了就写进报告，然后完成本单；
- 不启动原生浏览器；
- 每完成一个小步骤就提交一次。

**依据**：规则总表 2026-11-24 08:50 条款（用户定案）。

1. **删除三档新增回答策略**
   - 从 `PIPELINE_VALUES['prompt_strategy']`、Agent 的可选范围和说明文字中，删除 Stepwise、Grounded、TableCheck。
   - 只保留历史显示所需的常量，让 E2、E3 的记录仍能正常显示。
   - 新实验不得选用这三档：校验器要拒绝，并补一条反例测试。
2. **资格版本 2026-11-24：变化题重跑确认**
   - 方案 Sandbox 跑完后，找出所有与 Baseline 稳定判定（见 118b）不一致的题。
   - 对每道这样的题，用 113c 的诊断复测工具在该方案配置下**再跑 3 次**：绕过缓存，使用独立 ID。
   - 3 次中至少 2 次与 Sandbox 的结果一致，才计入"修好"或"新错"；否则记为"不稳定"，不计入资格，但要展示出来。
   - 资格条件仍是：11 项门槛全过、无新增严重错题、新错为 0、至少修好 1 题。
   - 安全题和注入题只要复测出现 1 次严重错误，就记为风险，不合格。
   - 复测调用写进成本记录，但**不占 Sandbox 预算**。
3. **Baseline 稳定判定**
   - 新增"Baseline 稳定判定"的数据结构：每道题保存 3 次的对错，以及多数结果。
   - Bad Case 只取多数为错的题；1 次错 2 次对的题标为"不稳定题"，不进入 Bad Case。
   - Agent 输入、诊断和资格比较，一律以稳定判定为准。
4. **拆问只拆一次**
   - 同一实验内，每道题第一次拆问的结果保存下来，后续所有方案直接复用，不再调用模型。
   - 补测试：同一实验里两个都开启拆问的方案，子问题必须完全一致。
5. **禁止导入历史**
   - 新实验不得导入任何历史账本或观察，`parameter_effect_ledger.historical` 必须为空。
   - 校验器拒绝非空的情况，并补测试。
6. **同步规则**
   - `rules.py` 与规则总表末尾的 JSON 同步，资格版本改为 2026-11-24；
   - 109f 守卫测试必须通过；
   - 前端不改。
