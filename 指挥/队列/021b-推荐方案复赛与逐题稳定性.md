# 任务 021b：推荐方案"复赛"——同配置再跑一次，给出逐题稳定性（自动值班）

用户已授权：中间所有确认默认同意，不要停下来等人。**用户 11-06 授权暂不考虑高峰价**，用法同 021a。

## 为什么做

推荐方案的成绩只来自一次 50 题评测。每次生成的回答文字都不一样，判分在边线题上也会有不同结论。另外，赢家是从 9 套方案里挑出来的最好一次，有"挑中幸运儿"的偏差。

所以发布前加一步**复赛**：用完全相同的配置和冻结身份，再完整跑一次，看改善能不能重现。面试叙事是：**粗搜 → 精修 → 复赛 → 人工发布**；单次跑分不可信，所以设计了复赛。

## 要做的

### 1. 复赛功能（产品流程的一步）
- **何时触发**：推荐确定（Recommended）之后、发布之前。无人值守授权开着时自动触发；关着时，在工作台提供"开始复赛"按钮。
- **怎么跑**：
  - 用推荐方案的配置；Golden、评分身份、索引、门槛和第一次完全一致；
  - 完整 50 题，每题只跑一次；
  - **不占 12 次额度**，单独记为"复赛"。
- **如果 021a 的 D 还在跑**：等推荐重新确定后再触发，不要在 D 跑的时候抢跑。

### 2. 逐题稳定性对比

按"Baseline / 第一次 / 复赛"三列逐题比较，每道题归入一类：
- 稳定修好、只一次修好；
- 稳定新坏、只一次新坏；
- 稳定仍错。

门槛、P50、P99 也两次并列显示。

### 3. 两次不一致的题，零成本归因

用已保存的数据，不调用模型，把每道题归入以下一类：
- **检索不同**：两次的证据位置不同；
- **生成不同**：证据位置相同，回答不同；
- **判分边界**：回答要点基本一致，判分理由涉及评分要点的歧义；
- **不确定**。

每道题写一句大白话依据。

### 4. 发布前置条件
在原发布资格上**增加一条**：复赛也必须满足候选合格条件，即：
- 11/11 门槛；
- 无新增关键错题；
- 错题比 Baseline 至少少 1 道；
- 至少修好 1 道目标题。

原有发布资格（以第一次为准：11/11 + 零新增 + ≥1 修好）**不改、不放宽**。复赛不合格就不能发布，页面写明原因。

### 5. 前端
在 Agent 工作台的推荐页签和发布页：
- 加复赛结果和稳定性表；
- 遵守已定 UI 规则：一种绿色、表格两行截断加悬停、不露编号、不留空白；
- 构建必须通过。

### 6. 测试
临时库加 Stub 覆盖：
- 复赛自动触发、不占额度；
- 身份一致性校验；
- 五类稳定性划分；
- 不一致题的三类归因；
- 复赛不合格时阻止发布；
- D 运行中不抢跑。

### 7. 给当前实验跑复赛
- **重启后端前必须确认没有活动评测**。如果 021a 的 D Sandbox 还在跑：
  - 每 5 分钟只读看一次，最多等 90 分钟，跑完再重启；
  - 超时就不要重启，报告写明，结束。
- 推荐确定后，确认复赛已启动、新完成 2–3 题且技术失败为 0，写报告结束。后台继续跑完。
- **不发布。**
