## 3. 随机性检测（本单重点）

只用已保存的数据回答下面的问题，每项给出数字和题号。

1. **完全相同的生成请求**（复用命中）：
   - 有多少题的回答与来源不一致？应为 0。
   - 判定与来源不一致的有多少题？
2. **回答文本完全相同、证据也完全相同**的题：
   - Judge 判定有没有不一致？有的话列出题号和两次判分理由。
3. **检索阶段的模型调用**：查 query_rewrite、multi_query、hyde 这些开启时会调用模型的步骤。
   - 它们走不走请求级复用？
   - 在已跑的 Sandbox 里有没有开启过？
   - 开启时，同一题的改写结果是否会因模型随机而不同，进而改变检索证据？列出受影响的题。
4. **对错翻转的题**：每个 Sandbox 相对 Baseline 翻转的题（对 → 错、错 → 对），逐题归类为以下三种：
   - **(a) 证据集合变了**（Child/Parent ID 不同）；
   - **(b) 证据集合相同，但提示词策略或生成参数变了**；
   - **(c) 证据集合和提示词都相同，只是证据顺序、分数或格式等细节不同，导致生成请求不同**。

   (c) 类是"随机性嫌疑"，因为配置并没有真正改变模型看到的内容。对每道 (c) 类题，附上两次判分理由的原文。
5. **跨 Sandbox 的同题一致性**：同一题在多个 Sandbox 里证据集合和提示词都相同时，对错是否一致？列出不一致的题。
6. **技术失败**：033e 修复之后，有没有新的技术失败？

## 4. 每轮 Agent 分析（原文导出）

第 1、2 轮和第 3 轮（已生成的部分）每轮各写以下内容：

1. **输入**：Agent 实际拿到了哪些字段（Bad Case 清单、上一轮逐题对比、上一轮对账结论等），每项多少条。
2. **思考设置**：这次分析请求的 thinking 或 reasoning 设置，以及返回里有没有 reasoning 内容、长度多少字。**不贴推理原文**。
3. **对上一轮的总结**（第 2、3 轮）：保存的对账结论和教训，**全文**原样贴出。
4. **本轮整体策略**：保存的原文全文。
5. **A/B/C 每个 Candidate**：
   - 改了哪些参数（旧值 → 新值）；
   - 改动理由原文；
   - 事先预测：预测修好哪些题、可能弄坏哪些题、风险，均为原文；
   - 实际结果：修好、新坏、仍错各是哪些题，对比以 Baseline 为准，同时与上一轮被参考配置对比。
6. **事后对账**：每个 Candidate 的预测命中几题、落空几题，以及保存的对账原文。
7. **规则符合情况**，逐条写"符合 / 不符合"并给依据：
   - 每个 Candidate 最多改 2 个参数；
   - A/B/C 方向不同；
   - 检索没变时不把变化归因给检索参数；
   - 事先预测保存在运行之前；
   - 输出是中文。
8. **花费**：本轮调用次数、token 和估算费用。
