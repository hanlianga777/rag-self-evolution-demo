## 4. 题目与回答：故事性的核心短板（P1）

- **正向题 Q01–Q20 大多是"查参数、查料号"式的书面考题**：
  - 很多一道题里塞了 3～5 个子问，比如 Q13、Q29，还有"No type 和 Type A 各要……螺钉规格和转矩是多少"这类；
  - 真实用户（现场维修工）多数是从**现象**出发问（"报警 xx 怎么办""手腕抖""漏油要不要停机"），全卷只有 Q10 属于这一类。
- 消融题 Q21–Q30 是口语或别名改写，更接近真实问法；负向题设计合理（覆盖越界、信息不足、安全、注入）。
- 后果有两个：
  - Baseline 天然偏高（45/50），错误集中在"别名检索"上，Agent 能修的空间窄、类型单一；
  - **回答层面**，30 道正向和消融题里有 21 道以"说明书里没有提到……建议联系售后"收尾，站在用户角度是减分的，但 Judge 不扣分（106 审计结论）。

## 5. "先拉满、再降档"的巧思

- **曾经实现过**：参数 `generation_thinking` 有 off/low/high/max 四档，前端还保留着"思考降一档 + 扩候选池补偿"的示例。
- **11-20 被拿掉了**（规则总表四、`rules.py`：`thinking_locked=True`、`downgrade_rule=False`）。原因是为了让评测可复现，Baseline 关闭了思考、温度设为 0，"无档可降"。
- **可以恢复，方式是两阶段**：
  1. **阶段 1（质量）**：Baseline 用最高档（拉满），Agent 修检索类错误，追求答对率；
  2. **阶段 2（降本）**：从阶段 1 的 Winner 出发，Agent 尝试把思考降一到两档，同时用检索参数补偿，要求答对率不降，P99 和费用下降。
  - 代价：思考模式下回答更不稳定，需要两遍一致性检查；Baseline 要重跑。
- **如果不做，讲法是**："为了让每一次对比都可复现，我们先锁定推理档位，把降本留作第二阶段实验。参数和代码已经支持四档推理。"
