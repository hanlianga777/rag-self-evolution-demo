## 一、核心发现：门槛对 Baseline 不起作用，Agent 的进步信号和噪声一样大

**事实**（来源：`指挥/报告/102b-Baseline-M1逐题原始记录.json` 中的 `metrics` 和 `gate_details`）：

| 门槛 | 要求 | Baseline 实际 |
|---|---|---|
| 正向 Correctness / Faithfulness / Completeness | 80 / 80 / 75 | 94 / 95 / 94 |
| 消融 Correctness / Faithfulness / Completeness | 70 / 75 / 65 | 86 / 92 / 84 |
| 安全三项 | 95 | 100 / 100 / 100 |
| p50 / p99 | 25 秒 / 60 秒 | 2.9 秒 / 4.2 秒 |

- Baseline 的 11 道门槛全部大幅超过。历次所有方案也几乎都是 11/11，只有 R2-B 是 4/11，那次属于技术事故。所以**门槛对任何方案都不起筛选作用**。
- Agent 的全部"进步"只能来自 50 题里 5 道错题的翻转，而且这个翻转要靠单次运行来判断。
- 同时，`borderline_question_ids` 有 9 道题处在及格线边缘。Judge 是 0–4 分制，掉 1 分就从对变错；同一配置重跑，生成结果也会变（113a、115）。
- 结论：**信号（修好 2～3 题）和噪声（单次运行有 2～3 题翻转）处在同一量级。**
  - "同配置不同结果""A 新错一题就不合格""故事显得薄"，这三个现象都来自这一个根因。
  - 11-24 已定的"3 次多数 + 变化题重跑确认"是在治噪声，方向对，并且是必要的。
  - 但它不会让信号变大。

**朋友两套产品的做法**（来源：互审 38）：

- 两套产品的 Baseline 都没过门禁。Colin 消融 67.5 / 63.7 没过；朋友 2 消融 57.8 / 34.4 没过，延迟也超标。
- Agent 的任务是把挂红的那一类**平均分**拉过线。平均分是连续量，单题抖动会被平均掉，信号大、故事直观。
- 他们的门槛和我们一样，延迟门槛 25 秒/60 秒也是照他们抄的。但他们用的是 Coze 加深度思考，p50 约 30 秒，所以延迟门槛对他们有约束力；对我们（2.9 秒）完全没有。

**这件事不能靠事后改门槛解决**（用户规则：不为故事改规则）。可选做法：

1. **不改规则，改讲法**：我们的合格标准本来就和 Colin 的"逐题非回退门"一致（新错 0、修好 ≥1；D 打平就保留赢家）。故事从"把门禁拉过线"改成"门禁早已全过；Agent 只修真实的稳定错题，并且保证不搞坏别的题"。这符合朋友 2 的核心结论："真正难的是避免修好 A 搞坏 B"。
2. **加一个只展示、不判定的连续指标**：增加"证据进入最终上下文"的比例（朋友 2 的 Recall@K 口径），作为诊断层的连续信号。数据已经有，即每题的 `standard_evidence_in_final`。这个指标不进门槛、不改资格，所以不算事后改规则。
3. 延迟门槛保留，但在页面上如实说明"本项目生成快，这一项不构成约束"，不拿它讲取舍故事。
