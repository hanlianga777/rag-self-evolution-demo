# Agent 因果逻辑、评测稳定性与前端叙事：重设计方案（Claude，2026-11-23 13:50Z）

用户提出三个问题：
1. 同样的参数，上一次实验和这次实验结果不同，这是模型不稳定还是判分不稳定，能不能从根上解决？
2. Agent 每轮真的分析了 Bad Case 吗？轮与轮之间有没有叠加判断？第 3 轮感觉在到处碰壁。
3. 前端没有"一轮比一轮走向高潮"的说服力。

## 1. 结果不稳定：根因已经查清
- **事实**：旧实验 R1-C 和 E2 R1-C 的配置完全相同（alpha 0.7 + decompose），旧实验 48 分（修好 Q05、Q21、Q27），E2 只有 46 分（Q05 仍错，新错 Q20）。
- **机制**：
  - 系统有"相同请求复用"机制（`request_reuse.py`、`providers.py:325`、`ai_service.py:357/379`）：同一评测身份下，只要检索请求、拆问请求、生成请求和 Judge 请求的内容逐字相同，就直接复用第一次的结果。所以**同一身份内，输入相同，结果必然相同，Judge 本身不制造随机性**。
  - 复用身份等于题卷快照、知识库身份和 Judge 合同三者的组合。109a、109b 改了规则和提示词登记，身份随之改变，E2 就无法复用旧实验的回答，全部重新生成。
  - **结果变化的来源是生成模型**：即使温度为 0，只要请求重新生成，或者送进去的资料稍有变化（例如拆问后多了一段资料），回答就可能翻转，Q05、Q20 就是这样。所以这是"生成对输入扰动敏感"加上"首次生成本身有波动"，不是判分随机。
- **从根上解决**：
  1. **只重新生成受影响的题**：方案没有改变某题的最终资料和提示词时，这道题直接复用对照组（Baseline 或当前 Winner）的回答和判分，这部分零噪声。现有复用机制已经能做到这一点，需要再把"受影响题"显式标出来并展示。
  2. **受影响的题生成 3 次，按多数票定对错**：每次生成用不同的请求序号，避免被复用。Baseline 同样做 3 次多数票，作为新 Baseline B2。题卷和知识库都不变，只是评测口径升级，因此新旧身份分开，旧成绩只读保留。
  3. 资格里的"新错"和"修好"，只认多数票稳定的翻转。单次偶然翻转记为"不稳定"，单独展示，不计入资格判断。

## 2. Agent 因果逻辑：把"写理由"升级为"按证据推理"
E2 已经做到每轮写错因、写预测、逐条处理上一轮的经验，但还缺下面四样，所以看起来是在乱试：
1. **参数效果账本**（由程序计算，跨轮累积）：对每个试过的参数取值，只用"单参数对照"（同一底座只改这一项）统计它对每道 Bad Case 的作用，包括修好、弄坏、无效，以及证据排名的变化。多参数合改的结果只记为"组合观察"，不做归因。每轮都把这本账交给 Agent，前端也展示。
2. **"故障环节 ↔ 参数作用环节"一致性校验**（GPT 在互审 35 中提出）：
   - 每道 Bad Case 先由程序标出故障环节：未召回、排序靠后、没进入 Final、生成·错误否定、生成·表格归类、生成·漏子问。
   - 每个参数都有固定的作用环节：candidate_k、alpha、decompose、min_score 作用于召回和排序；top_k 和 rerank 作用于是否进入 Final；三个提示词策略作用于生成。
   - 方案所针对的题，故障环节必须和参数的作用环节一致，否则直接拒绝。按这条规则，R3-B（用 Grounded 修 Q17 的缺证据问题）和 R3-C（用 min_score 修 Q15 的读表问题）都不会出现。
3. **爬坡式轮次加假设链**：
   - 第 1 轮从 Baseline 出发；从第 2 轮起，以**当前 Winner** 为底座，每个方案只叠加 1 个新参数。
   - 每轮计划必须写清："继承什么（账本中已证实有效的）""排除什么（已证伪的）""本轮验证什么假设""假设成立时下一步做什么，不成立时下一步做什么"。
   - 下一轮校验是否兑现了上一轮写下的"如果……则……"。
   - 这样分数会逐轮爬升，轮与轮之间有因果链。
4. **边界识别与主动停止**：如果剩余 Bad Case 的故障环节已经没有尚未试过、且环节匹配的参数，Agent 就宣布"能力边界"，转入 D 或者停止，不再乱试。Q15 在 TableCheck 失败后应当判为边界，交给数据工程或更强的推理手段处理。这本身也是故事的高潮之一。

## 3. 前端叙事：把"高潮"做出来
1. **首屏"进化曲线"**：横轴依次是 Baseline、第 1 轮、第 2 轮、第 3 轮、D，纵轴是每轮最好成绩和当前 Winner；每个点标出合格数、稳定修好的题号、被拦下的原因。
2. **参数效果账本矩阵**：参数 × Bad Case，颜色分别表示修好、弄坏、无效，点开后显示证据排名的变化。
3. **因果链**：每轮"假设 → 验证 → 结论 → 下一轮继承或排除"，用箭头把各轮串起来。
4. **结局卡**：最终 Winner、哪些修复是稳定的（3 次多数票）、能力边界（Q15）、D 为什么被拒、发布建议。

## 4. 重跑范围与成本

- 新建 B2（50 题 × 3 次）。
