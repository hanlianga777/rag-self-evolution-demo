# Agent 重设计：合议结论与总指挥裁定（2026-11-23 14:10Z）

## 一、Claude 接受 GPT 的更正
1. **"Judge 不随机、波动全部来自生成"这个说法证据不足，撤回。** 缓存命中只能说明"同一个请求，回放的是同一份历史结果"，并不能证明模型稳定。温度为 0 时，生成和 Judge 仍然可能出现差异。要先分开核查三层：请求本身是否相同、生成结果是否相同、判分是否相同。
2. **三次多数票不改正式资格规则。** 它只作为诊断性的稳定性观察，结果按 3/3、2/3、1/3 展示。安全题只要有一次出现严重错误，就记为风险，不能靠多数票抵消。
3. **暂不重建 B2。** Baseline 45/50 继续作为正式基准。
4. **故障环节与参数作用环节的匹配，改为三档判断**，而不是一刀切：
   - 放行：作用机制与故障环节明确对应，并且有预演或历史证据；
   - 补证：存在跨层作用的可能，但需要先说明中间机制并拿出证据；
   - 拒绝：与已知事实直接冲突。
5. **底座规则**：只有已经合格的 Winner 才能作为下一轮的底座，否则继续以 Baseline 为底座。默认每轮只叠加一个参数；允许组合，但必须标为"组合探索，不做归因"。不要求分数每轮都上涨，真正的保证是"不合格的方案不会替换掉已验证的 Winner"。
6. **前端用两条曲线**：一条是每轮的最好成绩（可以上下波动），另一条是累计合格的 Winner（只在满足资格条件时更新）。参数矩阵放进抽屉，增加"未知"和"多参数无法归因"两种状态。要先把后端记录做实，再改前端。

## 二、总指挥裁定（和 GPT 不同的一点）
GPT 建议：以 E2 的 R2-B 为锚点做小规模配对验证，暂不新开 E3。

**我决定在完成第 0、1 阶段之后新开 E3，从第 1 轮跑起**。知识库、M1 和 Baseline 45/50 都不变，E2 完整保留为"改造前"的记录。理由如下：
- 用户最核心的疑问是"Agent 有没有因果推理"。只有用改造后的决策合同完整跑一次，才能直接拿出证据回答。补验证 R2-B 只能说明 R2-B 稳不稳，回答不了这个问题。
- "改造前 E2 与改造后 E3"的对照本身就是有力的故事：同一张考卷、同一个 Baseline，看 Agent 的推理质量有没有提升。
- 费用很低。E2 的 10 次 Sandbox 约花 0.7～1.5 美元。真正的瓶颈是 Codex 额度，而第 0、1 阶段本来就是必须做的。
