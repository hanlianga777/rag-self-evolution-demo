## 二、用户追问的结构问题（Claude 核查）

1. **「（补充）」要点**：这是 11-20 二审给 Q04、Q10 加的规则（规则总表三.11）。参考答案里带「（补充）」的要点漏答不扣完整性，实际效果等于「选答点」，与用户 11-16 定的「不再有必答 / 加分」相冲突。
   - 学术界的 TREC RAG 评测确实把要点分为 vital（必须有）和 okay（有更好）两档，所以这不算凭空自创；RAGAS 的做法则是按参考答案逐条比对事实（TP/FP/FN），不分主次。
   - **结论：M2 取消「（补充）」。参考答案里写的每一条都是要点，不需要的内容就不写进参考答案。**
2. **「要点 1、要点 2」**：这是前端把参考答案按行拆开后的显示方式，Judge 的「完整性」也是按这些要点逐条比对。M2 的参考答案统一写成 1. 2. 3. 的编号形式，并保存每条要点的命中记录（现在显示「记录缺失」，就是因为没存）。
3. **回答为什么那么乱、「资料边界」是什么**：
   - 生成提示词（`ai_service.py` 的 `GENERATION_STRUCTURED`）规定的格式是：先一两句结论 → 「注意：」安全警告 → 1. 2. 3. 步骤 → 最后一句「说明书里没有提到……建议联系售后」。
   - 前端（`StructuredAnswer.tsx:227`）把最后这句单独抽出来，放进灰框，起名叫「资料边界」。这是我们自己起的名字，不是翻译问题。
   - **对 Bad Case 判断的影响**：
     - 简单事实题也被套上了警告、步骤和「没提到」这一整套格式，内容变长，多出来的话更容易被判「无依据」；
     - 「最后一句说说明书没提到」这条规则，会诱导模型说出「资料里有、却说没有」的错误否定，Q05 的错因正是这一类。
   - **结论：M2 之前先定稿新的回答格式，并在 Baseline 跑之前冻结。** 不能看到结果以后再改。

## 三、一次性方案（双方一致，细节以 GPT 方案为底，Claude 补充第 5、6 条）

1. **出 100 道新题，分成两份卷**：
   - M2-Dev（调参卷，50 题）：Agent 可以看错题、做诊断；
   - M2-Holdout（盲测卷，50 题）：Agent 看不到，只用于最终验收。

   两份卷按同一张能力蓝图出题，但事实不重复；同一组消融配对、同一段核心证据只能放在同一份卷里。

   每份卷的题型分配（与现行 2:1:2 比例一致）：

   | 大类 | 小类 | 题数 |
   |---|---|---|
   | 正向（20） | 单事实 | 4 |
   | | 多条件 / 多段聚合 | 6 |
   | | 表格统计 | 4 |
   | | 桥接 / 跨文档 | 4 |
   | | 型号辨别 | 2 |
   | 消融（10） | 弱关键词 / 口语 | 4 |
   | | 隐含指代 | 3 |
   | | 多子问 | 3 |
   | 负向（20） | 证据不足（可以回答一部分） | 6 |
   | | 需澄清（相似型号） | 6 |
   | | 安全关键（混在正常维修咨询里） | 5 |
   | | 注入（混在正常请求里） | 3 |

   负向题既要测「该拒没拒」，也要测「过度拒答」。
2. **取消 176 组全量预演，改为「先写假设，再申请验证」**：
   - Agent 先只看错题的症状，写下假设和预测修好哪些题；
   - 然后才能申请对少数几组配置做定向预演；
   - 预演前、预演后两次预测都要保存，作为「Agent 推理能力」的指标展示：预测命中率、实际修复覆盖率、风险预测命中情况。
3. **生成诊断保留**，但同样必须先有 Agent 的假设，再执行。
4. **新建 E6**：
   - 不沿用 E5 的成绩，也不导入历史；
   - 用原始 Pipeline 分别在两份卷上跑 Baseline，每题 3 个样本；盲测卷的 Baseline 结果在最终方案锁定前不打开；
   - Agent 只在调参卷上按逐层规则推进 A/B/C → 下一轮 → D，然后锁定推荐方案；
   - 盲测卷上每题跑 3 份独立生成做最终验收：通过就发布，不通过就保留线上版本，**不准回头换别的候选去试**。
   - M1 保留作为历史回归卷。
5. **（Claude 补充）参考答案和回答格式先定稿**：
   - 参考答案用编号写，不设「（补充）」；
   - 回答格式改为：简单事实题直接一两句话答完；操作题用 1. 2. 3.；安全警告只在与问题相关时写在最前面；只有在用户问到的内容资料里确实没有时，才说明「资料里没有」，不再固定追加一句「没提到」。
   - 这两项在 Baseline 之前冻结，前端照原样分行显示，不再拆出「资料边界」灰框。
6. **（Claude 补充）出题公信力**：
   - 先由用户确认蓝图和每类题的数量；
   - 题目全部出完、冻结以后才跑 Baseline，不针对 Pipeline 的弱点出陷阱题；
   - 出题过程（蓝图 → 出题 → 探针 / 质检 → 冻结）全部留痕，面试时可以作为「题卷是怎么来的」来讲。
7. **预期**（规划设想，不是验收指标）：
   - 每份卷 Bad Case 预计 5～12 道，8～12 道最适合展示；
   - 合格率不会刻意压低。失败的方案要有说得清的原因，成功的方案要有可以核验的依据。
   - 如果题卷依然不足 5 道错题，按照事先冻结的难题池升级到 M3，最多做 1 次；再不足就如实接受结果。
