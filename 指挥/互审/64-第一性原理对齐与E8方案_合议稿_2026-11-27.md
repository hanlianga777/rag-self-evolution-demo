# 64 第一性原理对齐与 E8 方案：Claude 与 GPT 合议稿（11-27，待用户拍板）

- **依据**：用户 11-27 09:02 的提问；互审 63；ChatGPT「Agent阶段风险审查」11-27 的第二问回复（GPT 核对了代码、RAGAS 和 TREC 的官方资料）。
- **目标（用户定）**：用题卷制造难题，让 Baseline 出现 Bad Case；Agent 以可解释的方式分类错题、排优先级、选方法修复，不新增错题；过程有起有落，最后提升正确率。面试官关心的是诊断和决策逻辑，不是题目文字。

## 1. 错题怎么分类、怎么修：规则定事实，Agent 做假设，Sandbox 做裁判

| 环节 | 谁来做 | 做什么 |
|---|---|---|
| 事实提取 | 程序 + Judge | 对错、证据位置（候选池 / Final）、延迟、安全行为 |
| 故障诊断 | 程序规则（Agent 不能改） | 层、细分、严重度。题型细分（桥接 / 表格 / 跨段 / 别名 / 口语）只是线索，不等于根因。例如表格题缺资料，先算检索问题 |
| 优化假设 | Agent | 从「错因 → 参数菜单」里选。菜单分「推荐」和「允许探索」两档；Agent 要写清机制、预测会修好哪些题、可能伤到哪些题 |
| 方案准入 | 程序 | 白名单、身份、重复配置、预算。白名单以外一律拒绝 |
| 效果验证 | Sandbox | 实测收益和副作用，三层资格 |

**错因 → 参数菜单**：

| 错因 | 参数 |
|---|---|
| 召回失败，别名或口语 | query_rewrite、multi_query、HyDE、hybrid_alpha |
| 召回范围不够 | candidate_k、min_score |
| 排序或筛选漏掉 | rerank、top_k、candidate_k、min_score |
| 跨段证据缺失 | decompose、multi_query、top_k |
| 证据齐全但表格理解错 | thinking、prompt |
| 过度拒答 | prompt、thinking |
| 性能超标 | 按分阶段耗时定 |

**怎么看待预测没命中**：这叫「假设没被验证」，不算幻觉。编造证据或用白名单以外的参数才算幻觉，由准入校验拦下。

## 2. 轮次策略：主线 + 互补支线 + 三层资格

**三层资格**：

1. **基础合格**：和 Baseline 比。门槛全过、零新增错题、至少修好 1 题。
2. **本轮有效**：和父方案比。零回退，并且多修好至少 1 题。
3. **晋升 Winner**：和全局 Winner 比。保住全部已有成果，并且有严格的增量。

**支线怎么保留**：看互补性，不看分数排名。

**改动上限**：相对父方案每次最多改 2 项，累计最多 4 项。最多 4 轮、12 次 Sandbox，其中 1 次留给 D。

**各种情况怎么处理**：

| 情况 | 决策 |
|---|---|
| 第 1 轮三个都合格 | 选出 Winner，保留一条互补支线 |
| 第 1 轮全不合格 | 底座仍用 Baseline，根据各方案的局部修复和副作用提出新假设 |
| 有 Winner 后，下一轮全部无效 | 保留 Winner，换支线或换机制 |
| 连续两轮没有增量 | 还有可信的组合就试 D，否则结束 |
| 支线超过主线，并且保住了主线已修好的题 | 支线晋升为 Winner |
| 支线总分更高，但丢了主线修好的题 | 不晋升，继续作为支线 |
| 单参数有效但有副作用 | 允许用两参数组合去消除副作用 |
| 提质量要多花时间 | 允许，但不能突破性能门槛 |
| 降耗时导致新增错题 | 不允许晋升 |
| 剩下的题工具箱修不了 | 结束，输出能力边界和工程建议 |
| Judge 波动造成疑似修复 | 独立复测，不计入有效修复 |
| 全部答对，门槛也达标 | 正常结束，不强制做 D |

## 3. D：不强制，三种结局都能讲

D 的来源可以是：互补的合格方案、不合格方案里局部有效的部分、有可信机制的新参数、撤销或替换已有参数。**禁止只为了展示而组合。**

| 结局 | 怎么讲 |
|---|---|
| D 晋升 | 综合了多条路径的经验，取得增量 |
| D 没晋升 | 系统识别出副作用，拒绝晋升，保留 Winner（在 Sandbox 里失败不能叫「回滚」） |
| D 没生成 | 系统不做没有价值的重复实验 |

## 5. 答案侧和证据侧：必答 / 选答 vs 必要证据

- **答案侧维持 11-26 的决定**：参考答案按 RAGAS reference 写成普通答案，不分必答和选答，前端不显示这类标签，非必需信息放进 notes、不评分。
- **证据侧另有一个术语**：「事实级证据覆盖（Claim-level Evidence Coverage）」。意思是参考答案里的每个事实，至少要有一条支撑证据进入检索结果，与 RAGAS 基于 LLM 的 Context Recall 一致。一个事实可以有多个等价来源，也可以由多条证据联合支撑。TREC qrels 只管「相关」，不等于「不可缺」。
- **为什么现在提**：复核时发现锚点证据把召回诊断搞错了（Q29）。这一条只改诊断，不改答案。
