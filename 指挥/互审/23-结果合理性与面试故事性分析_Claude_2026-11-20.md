# 结果合理性与面试故事性分析（Claude，2026-11-20 20:10，用户提问）

**用户的问题**：Agent 第 1 轮 3 个方案全部合格，D 也没有跑，故事显得单薄。结果是否合理？还有哪些地方可以优化？

## 一、结果是否合理：数字本身没问题，但有 4 个让故事变弱的结构性原因

1. **"合格"没有要求"有提升"**
   - 合格条件是 11 项门槛全过、新增严重错题为 0。
   - B（宽松提示词）什么都没修好，也算合格。
   - 结果是"3 个都合格"，听起来像每个方案都有效，实际只有 A 和 C 有效。
2. **Baseline 已经很高（45/50），可修的空间小**
   - 只有 5 道真错，其中 Q15 是检索修不了的表格理解问题。
   - 能修的只剩 4 道，第 1 轮就修得差不多了。
3. **Judge 偏宽松，掩盖了真实错误**
   - 已确认 Q05、Q17 的回答里有无依据的"说明书没有"说法，Judge 照样给了满分。
   - 这类话术在 30 道正向、消融题里出现了 21 次。
   - 如果 Judge 严格，Baseline 的真实错题会更多，Agent 也会有更多空间。
4. **D 没跑**，是因为 D 必须先过 Gate 2（报告确认），而 Gate 2 要等用户命令。它不是"没形成"，是在等人确认。

## 二、现在的故事有哪些亮点（应该保留）

- **数据层**：K-means 簇不等于业务主题；全库约 1/3 内容逐字重复；章节识别出错。
- **评测层**：冻结题卷、四道检查、判定两遍一致。
- **Agent 层**：按错因分层，区分"证据有变化"和"只有结果变化"；安全类题逐题零退步。
- **人机协同**：Gate 2 / D 必须由人拍板；两个 AI 互审一共抓出约 30 个问题。

## 三、优化方案（不造假、不为凑故事改题）

### 方案 1：最小改动

- 用户确认 Gate 2，跑 D。
- 讲法改成："单方案各修一层（A 修排序、C 修查询理解）→ 组合后能否两层都修好，能否到 49/50 → 由人确认"。
- 不管 D 是被采纳还是被拒绝，都是好故事。
- 成本：一次 Sandbox。

### 方案 2：先把评测修严，再优化（推荐，故事最强）

**2a. 修 Judge**
- 新增检查：回答里说"说明书没有…"这类否定句时，要核对资料中是否确实没有；资料里有却说没有，就扣忠实度。
- 用保存下来的回答**只重新判分**（Baseline、A、B、C 全部用同一个 Judge v3 重判），不重新生成回答，成本很低。
- 预期：Baseline 的真实错题会从 5 道增加到 7～9 道。
- 面试的讲法："我们发现了评测本身的盲点，先修评测再优化。"

**2b. 合格条件加一条"有净提升"**
- 至少要有 1 道"证据有变化"的修复，否则不算合格，而是"无效方案"。
- 这样 B 会被判为"无效"，故事就变成"Agent 的三个方向里，提示词方向没用，检索方向有效"。
- **这条要改规则，需要用户拍板。**

**2c. 第 2 轮针对生成层**
- 第 1 轮修好了检索层，剩下的错误集中在生成层："说明书没有"话术、Q05/Q22 概念混淆、Q15 表格理解。
- 新增一个回答策略选项"资料边界"（Grounded）：只能说"当前检索资料中没有"，不能说"说明书没有"；回答前逐条核对资料。这会改动 Agent 的可调参数范围，需要用户拍板。
- 第 2 轮让 Agent 在检索修复的基础上攻生成层，然后进 D。

**2d. Q15 的定位**
- 写成"Agent 识别出自己修不了的问题，交给数据工程处理"（表格周期字段的序列化方式），而不是硬让 Agent 去修。
- 面试的讲法："Agent 知道自己的边界。"

**完整故事线**：数据可信 → 评测可信（并修好 Judge 盲点）→ 第 1 轮修检索 → 第 2 轮修生成 → D 组合 → 人工 Gate 2/3 → 识别出 Agent 能力边界并转交。

**成本和风险**
- 重新判分便宜（只调用 Judge）；第 2 轮要 3 次 Sandbox，加上 D，大约半天。
- 风险：修 Judge 后 Baseline 下降，可能被质疑"为了凑错题故意修严"。
- 规避办法：
  1. Judge 修改的依据只来自已经审计出来的具体证据（Q05、Q17、Q24）；
  2. 所有历史运行都用同一个 Judge 重判；
  3. 新旧 Judge 的结果并列展示，不隐藏旧结果；
  4. 修改前先双审。

### 方案 3：加难题卷（M2）

- 不推荐。规则只在错题少于 5 道时才允许加难；而且加难解决不了"故事层次"的问题。
