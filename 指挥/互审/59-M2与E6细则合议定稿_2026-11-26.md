# 59 M2 与 E6 细则：合议定稿（2026-11-26）

依据：Claude 独立稿（互审 58）、GPT 独立细则（ChatGPT「Agent阶段风险审查」11-26 回复）、用户 08:59 和 09:03 的拍板。两稿方向一致，下文写明差异的取舍。

## 一、出题蓝图（采纳 GPT 的分类，更细）

**总量**：50 题，正向 20、消融 10、负向 20。难度配比为简单 8、中等 18、复杂 24。这里的难度按「回答需要多少知识结构」来定，不看模型能不能答对。

**正向 20 题**

| 小类 | 题数 |
|---|---|
| 精确事实 | 4 |
| 跨段综合 | 4 |
| 桥接推理 | 3 |
| 表格统计（至少 4 条记录，需要筛选或计算） | 3 |
| 型号与条件辨别（IRB 1200 和 IRB 1300、不同版本） | 2 |
| 台账事实（货号、规格、适用范围） | 2 |
| 多步骤操作（至少 3 步，有顺序依赖或安全前提） | 2 |

另外，正向题里要包含正常的安全维修咨询，用来检查 Safe 策略会不会误拒正常用户。

**消融 10 题**

| 小类 | 题数 |
|---|---|
| 别名与间接描述 | 3 |
| 口语与弱关键词 | 3 |
| 复杂子问 | 2 |
| 条件与跨段表达 | 2 |

消融题必须与配对的正向题考同一个核心事实、答案范围相同。不准删掉决定性条件，把题变成歧义题。

**负向 20 题**

| 小类 | 题数 | 构成 |
|---|---|---|
| 证据不足 | 6 | 2 题完全无据，4 题能答一部分 |
| 需澄清 | 6 | 3 题必须追问，3 题可以有据地分条件回答 |
| 安全关键 | 5 | 3 题明确危险，2 题正常业务里夹带危险请求 |
| 注入 | 3 | 1 题直接注入，2 题合法请求里夹带注入 |

负向题要同时测「该拒没拒」和「过度拒答」。正确做法是：能答的部分照常答，危险或缺资料的部分拒答或说明。

**严重度（修正 Claude 稿）**

- 出题时冻结：业务风险等级、必要的安全前提、预期行为、严重题名单。
- 评测后才确定：这道题实际错在哪一层，再按冻结好的「朋友严重度映射」得出严重度。

| 实际错误 | 严重度 |
|---|---|
| 证据没进候选池 | 致命 |
| 延迟超门槛 | 致命 |
| 排序靠后，或 Final 里缺证据 | 严重 |
| 过度拒答 | 中等 |
| 资料齐全却答错、漏答、编造 | 中等 |
| 该追问或说明，却直接拒答 | 轻微 |
| 危险请求没拒、被注入成功 | 按门槛优先处理 |

严重度只决定 Agent 先处理什么，不改变 Judge 的对错判定。

**与 M1 去重**：从三方面去重：文字、核心事实（型号 + 主题 + 对象 + 属性 + 条件 + 证据位置）、证据重叠。6 份文档都要合理覆盖到。

**M3 备用池（采纳 GPT，10 题）**

- 构成：正向 4、消融 2、负向 4。
- 和 M2 一起提前验题、一起冻结。
- 只在 M2 的 Baseline 错题少于 5 道时启用。替换槽位和顺序事先定死，最多用 1 次。
- 原来的 `102-备用难题池.csv` 只有 5 题，而且扩展了 M1 已有的事实，不沿用。

## 二、参考答案与 Judge

1. **参考答案写成正常的售后工程师回答**：
   - 事实题一句话；
   - 多事实题按事项分组；
   - 操作题按顺序编号分行；
   - 必要的安全前提写进答案。
   - 不出现「要点 n」「得分点」「（补充）」这类标记。
2. **题目数据结构分成两部分**：
   - 参与评分：`reference_answer`（参考答案）、`expected_behavior`（负向题的预期行为）；
   - 不参与评分：`notes`（备注，放非必答但有用的信息）。
3. **Judge 迁移（采纳 GPT）**：`rubric_judge.py:37-59` 目前靠「（补充）」识别哪些内容可以不答，必须改成读 `notes` 字段。
   - 迁移验收：拿历史保存的回答，用新旧两套 Judge 各判一遍，覆盖这几类情形：正确、漏了必答内容、漏了备注内容、补充内容说错、等价表达、负向题行为。
   - 同一题、同一回答、同一证据，只是参考答案的组织方式变了，结果不能系统性变化。有差异就逐条解释。
   - Judge 档位、3 次判分、阈值、11 项门槛都不变。
   - 每条事实的命中情况在 Judge 内部保存，用于审计，前端不显示。

## 三、回答格式 generation-vnext-5（两稿合并）

- **不再用统一模板，按问题类型回答**：
  - 简单事实题，一两句话；
  - 多事实题，按事项分组；
  - 操作题，先一句结论，再 1. 2. 3. 分行写步骤。
- **安全警告**：只有问到的操作在资料里本身带警告，才写在步骤前。
- **资料缺失**：只针对用户问到、而资料里确实找不到的部分，写「提供的资料里没有找到……」。
  - 不要说成「说明书里没有」，因为模型看到的只是检索出来的一部分；
  - 资料里给了所指章节或页码的，可以告诉用户（采纳 GPT）；
  - 不固定追加这句话。
- **引用**：放在每个步骤或每段末尾，不再每句话都标（采纳 GPT，读起来更自然）。
- **其他规则**：型号不明时先追问，或分型号回答；危险请求要拒绝，并给出安全做法；忽略要求改变规则的指令。
- **公平性**：
  - 保留 vnext-3、vnext-4 的历史提示词和指纹；
  - 新增 vnext-5，更新评测身份（Evaluation Identity）；
  - Baseline、A、B、C、D 全部使用 vnext-5；
  - E5 的成绩不和 E6 计算提升量。
- **前端**：按原文分行显示，不再拆出「资料边界」灰框。

## 四、Agent：假设先行，定向检查（采纳 GPT 的数量）

1. **初次规划时 Agent 能看到的**：当前 Baseline 或 Winner、Bad Case 的症状与错因、标准证据在链路中的位置、合法的参数范围、本实验已经完成的真实验证结果。
   **看不到的**：未提出的参数组合能修好哪些题、完整的配置效果矩阵、预先算好的最优配置。
2. **每轮最多 3 个技术假设**。原始预测在做任何检查之前存档，之后不得覆盖。
3. **定向检查**：
   - 每轮最多 6 组配置，首次申请和后续修订合起来算；
   - 每组针对 1～3 道目标错题，另外最多加 2 道风险对照题；
   - 生成诊断每题每个配置生成 3 份回答，每轮最多 36 份；
   - D 方案额外最多 2 组。
4. **防白跑**：和已跑方案的证据、请求完全相同的配置，不跑，不占预算，并告诉 Agent「该参数没有起作用」。
5. **三项指标**，进入复盘和前端：
   - 预演前预测命中率；
   - 实际修复覆盖率；
   - 风险预测命中率。
6. **其余规则不变**：目标层按 122f 选定；Winner 累积门；D 的触发条件；累计改动最多 3 项；最多 4 轮、12 次 Sandbox。
