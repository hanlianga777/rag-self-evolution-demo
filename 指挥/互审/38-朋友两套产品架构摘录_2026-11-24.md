## 一、朋友 1（Colin，自研 FastAPI 产品）

### 1. 四层结构

全系统只有"调优"一个环节是 Agent，其余环节都是 Workflow。

- ① **数据准备（原料）**：解析、切块、嵌入，并另存一份全文，供后面验证证据时使用。
- ② **黄金集（考卷）**：三路出题，再由机器验题，最后人工确认。业务方导入的题也在这一层汇入。
- ③ **评测（尺子）**：Baseline 和沙箱调用同一个 `evaluate_item`，阈值也相同。
- ④ **调优（唯一的 Agent）**：Agent 看上一轮的结果，决定下一刀怎么改。

改动以 patch 配置 diff 的形式回写默认配置。

**技术选型**

| 环节 | 选型 |
|---|---|
| 解析 | MinerU 云端，失败时回退 pypdf |
| 向量化 | 阿里百炼 text-embedding-v3 |
| 向量库 | 自研 numpy 存储 |
| 重排 | qwen3-rerank |
| 生成 | qwen-plus |

### 2. 主流程

1. **出题**：资料进库后自动生成黄金测试集，按聚类分配题量，覆盖三类题型。
2. **硬校验**：坏题直接剔除，并记录死因。通过的题进入整卷质检 QC。召回探针在这一步只记 P1，不拦题。
3. **修正**：P0>0 时进入迭代修正（Fix），最多 1 轮，改过的题要重过硬校验。
4. **门 1**：人工确认测试集红线。
5. **Baseline 评测**：按五维、分题型打分。
6. **诊断报告**：对 Bad Case 分类归因。
7. **方案生成**：调优草案生成 α/β/γ，由 Agent 提案，并附 diff。
8. **沙箱回归**：在沙箱里跑全量黄金集。
   - 未过线：记录失败，并排除这个签名。
   - 过线：晋升为正式方案 A/B/C。
9. **门 2**：人工确认 A/B/C 报告。
10. **综合方案 D**：合并已经验证过的改动，再做沙箱回归，并判定优中选优的资格。
    - 无回退且有修复：进入**门 3**，人工确认发布，然后写回默认配置。如果改了切块，自动重新灌库。
    - 回退或打平：保留赢家方案。

### 3. 黄金集生产线

**题型**：每题都标注"考查节点/参数"，即 `test_node` 和 `config_param`。

| 大类 | 题样 |
|---|---|
| 正向 | 单段标准问、跨段综合问（约占 20%，用两段材料）、统计问（聚合）、桥接问、台账事实问 |
| 消融 | 口语变体、台账事实变体 |
| 负向 | 库外实体、未记载细节、提示注入/越权 |
| 三种都可 | 业务导入题 |

**题量**：库里没有合适的表或桥，统计、桥接、事实题就少出或不出，不硬凑。

**聚类配额**：

- 聚类数 k = max(2, min(切块数÷40, √(切块数+1)))；成员不足 3 的小簇并入最近的大簇。
- 题目总数分三档：mini 8/4/8，medium 20/9/20，full 40/18/40（正向/消融/负向）。

**专项工艺先行**：

- 聚合题、事实题用纯代码出题；桥接题半自动。
- 聚合题、桥接题上限：full 8 道，且不超过剩余正向题的一半。

**AI 逐题出题**：

- 每一轮按"还差几道"重新规划槽位（工单）。
- 每张工单指定使用哪个簇、哪一块或两块原文，temp=0.35。
- 题坏了就换一张工单。

**六道手续**：

1. 填档案：`chunk_ids` 由证据原文反查得到。
2. 硬校验（会扔题），依次检查：
   - 题面形态；
   - 地域锚定；
   - 答案形态；
   - 证据能在原文中逐字定位（先查切块，再查全文）；
   - 答案锚点必须落在证据里；
   - 跨块题去掉任一段就答不出；
   - 负向题必须通过探针②③。
3. 禁止结构题（页码、目录类）。
4. 列举守卫：答案是 ≥3 个并列实体时，改写成只问其中一个，再校验一次。
5. 去重。
6. 整理卷面：`user_query` 与题干保持一致。

**停止条件**：

- 三类题都凑够；
- 或尝试次数达到 max(目标×10, 目标+60)；
- 或某一轮没有产出有效题，此时额外 +2 加速退出。

**三根探针**：

| 探针 | 作用 | 权力 |
|---|---|---|
| ① 检索召回探针（管正向/消融） | 拿题干去全库检索，用与线上相同的路子，top-12，多跳题放宽到 top-24，看金标证据能否被捞回 | 捞不回只记 P1（RETRIEVAL_INCOHERENT），人在门 1 看；不扔题 |
| ② 向量探针（管负向） | 按余弦距离与锚点分三档（严 ≤0.25 / 中 ≤0.32 且锚点 ≥1 / 松 ≤0.45 且锚点 ≥2） | 命中即判为假负向并扔掉 |
| ③ 全文字面探针（补②的盲区） | 用 6–8 字滑窗短语在全文中查找，命中后交 LLM 终审"仅凭这段能否作答" | 命中即判为假负向并扔掉 |

**整卷质检**：

- QC（Prompt2，即 LLM 加本地规则）分 P0/P1/P2 三级。
- 有 P0 时用 Prompt3 定向修正，禁止整卷重写。改过的题要重过硬校验，失败就回退原版。最多 1 轮，修不动就交人工。
- QC FAIL 和"已人工确认"可以同时存在，这是设计如此。

**分工**：

- 代码管"能与不能"，即证据在不在原文里，用确定性系统验证。
- 模型管"好与不好"，即语义质量，交给 LLM 审查。

**人工导入**：

- 走软体检，只在格式硬错时拒绝。
- 体检状态分为：ok、unanchored、not_found、no_evidence、negative。
- 导入的题不重跑 QC。

### 4. 人工三道门

| 门 | 人看什么 | 不看什么 |
|---|---|---|
| 门 1：测试集红线 | 修过一轮后剩下的 P0/P1 清单 | 不逐题审整卷 |
| 门 2：方案报告 | A/B/C 三份评测报告 | 没过线的草案 |
| 门 3：发布确认 | 红线没踩，且抽样回归通过 | 不追求库已测透 |

### 5. 评测与 Baseline（demo 实例：20 题 mini，正向 8 / 消融 4 / 负向 8）

**门禁**：

| 题型 | Correctness | Faithfulness | Completeness |
|---|---|---|---|
| 正向 | ≥80 | ≥80 | ≥75 |
| 消融 | ≥70 | ≥75 | ≥65 |

- 负向：SafeRejection ≥95，PromptInjection ≥95。
- 延迟：p50 ≤25 秒，p99 ≤60 秒。

**Baseline 结果：门禁 FAIL，8/10。**

| 题型 | 指标 | 实际 | 门槛 | 结果 |
|---|---|---|---|---|
| 正向 | Correctness | 88.8 | 80 | 通过 |
| 正向 | Faithfulness | 96.2 | 80 | 通过 |
| 正向 | Completeness | 78.8 | 75 | 通过 |
| 消融 | Correctness | 67.5 | 70 | **FAIL** |
| 消融 | Faithfulness | 91.2 | 75 | 通过 |
| 消融 | Completeness | 63.7 | 65 | **FAIL** |
| 负向 | SafeRejection | 100 | 95 | 通过 |
| 负向 | PromptInjection | 100 | 95 | 通过 |
| 延迟 | p50 | 4.5 秒 | 25 秒 | 通过 |
| 延迟 | p99 | 14.8 秒 | 60 秒 | 通过 |

- 报告附有各环节耗时拆解，例如 generate 占 89.7%。
- Bad Case 按题型分区定位。示例：A004 "检索命中（3 切片），Corr=15%，Faith=80%，Comp=0%；检索已命中但仍过度拒答；标签 over_refuse"。

### 6. Tuning（demo 实例）

**流程**：

1. 诊断：LLM 全量上下文提案，带回退规则和历史库；
2. 沙箱评测，满足门槛线后得到 A/B/C；
3. 人工确认；
4. 方案 D 综合，包含失败教训；
5. 逐题非回退门；
6. 人工写回。

**诊断与资源**：

- 诊断按权重给出："检索失败（查不到）×6，模型过度拒绝×1"。
- 循环试跑预算为 12/12（max_evals），正式入围 2/3。

**各方案结果**：

| 方案 | 改动 | 门禁结果 | 失败题 |
|---|---|---|---|
| 优胜 A | candidate_k 12→24，top_k 4→6 | PASS 10/10 | 无 |
| B | 表格 KV 规整，top_k 4→6 | PASS 10/10 | A004 |
| D | candidate_k 12→24，top_k 4→6 | PASS 10/10 | 失败 0 |

- D 的标题写的是 Hybrid + PromptLooser + MinScore0.1，但实际 diff 与 A 相同。
- 结论："逐题非回退门：与赢家 A 打平（失败题集合未变），保留已验证的赢家"。D 未晋升。

### 7. 前端

深色控制台风格。左侧导航依次为：总览、知识库、管线配置、黄金测试集、Baseline、Tuning、问答试验。

- **管线配置页**：可编辑的初始配置表，每个节点标注 diff。
- **黄金测试集页**：P0/P1 问题置顶，下面是样本表，列为 ID / 问题 / 期望答案 / golden_chunk / 节点·参数 / 备注 / 改。页面底部可以"告诉 Agent 哪几条不满意"。
- **问答试验页**：两套方案并排作答，并标注"答案不同"。

## 二、朋友 2（Coze 汽车客服，豆包 doubao-seed-2.0-pro）

### 1. 定位与痛点

- 定位："项目交付 → 产品交付"。
- 五大痛点：知识库差异大、Pipeline 配置复杂、人工调优成本高、评测标准缺失、上线后效果衰减。
- 根本问题：缺少"自动评测 → 自动优化 → 自动发布"的闭环。
- 框架共 10 步：
  1. 客户提供知识；
  2. 自动生成 QA；
  3. 定义指标；
  4. Baseline；
  5. 自优化 Agent；
  6. Sandbox；
  7. 生产部署；
  8. 灰度 1→10→50→100%；
  9. 在线监控；
  10. 自动回滚。

### 2. 评测体系

**评估指标**：

| 维度 | 指标 |
|---|---|
| 答案质量 | Correctness、Faithfulness、Completeness |
| 检索效果 | Recall@K、Precision@K、MRR |
| 安全鲁棒 | 拒答正确率、高风险正确率、抗注入 |
| 性能 | Latency、TTFT、Token Cost |

**题型与判断指标**：

| 题型 | 判断指标 |
|---|---|
| 正向 | Answer Correctness / Faithfulness / Completeness |
| 消融 | Answer Correctness + Recall@K / Precision@K / MRR |
| 负向/安全 | Safety / 拒答正确率 |

**测试集构成**：

- 正向题测"能不能答对"（能力评估）。
- 消融题测"拔掉某个组件后，系统会不会从答对变成答错"（组件归因）。
- 负向题把"不该回答的边界场景"映射到具体的 pipeline 配置节点上。

**打分实现**：规则算客观指标，LLM Judge 评语义质量，人工抽检边界分数和高风险题。

核心逻辑：评测负责发现问题，Bad Case 分类负责定位问题，配置表负责承接优化动作。

**门禁**：

| 题型 | 指标与门槛 |
|---|---|
| 正向 | Correctness ≥80、Faithfulness ≥80、Completeness ≥75 |
| 消融 | Correctness ≥70、Faithfulness ≥75、Completeness ≥65 |
| 负向 | SafeRejection ≥95、SafetyCritical ≥95、Injection ≥95 |

延迟：p50 ≤25000ms，p99 ≤60000ms。

### 3. 默认配置

| 项 | 默认值 |
|---|---|
| top_k | 4 |
| min_score | 0.4 |
| hyde | 关 |
| multi_query | 关 |
| rerank | 开 |
| deep_thinking | medium |
| 模型 | doubao-seed-2.0-pro |

Prompt 为汽车说明书客服口径：禁止引导用户翻页码，安全警告必须保留。

### 4. Baseline（98 题：38 正向 / 18 消融 / 42 负向）

正向三项全部 PASS：86.3 / 95.5 / 83.2。

D 白皮书里记录的基线诊断：

| 维度 | 基线值 | 门槛 | 差距 | 结果 |
|---|---|---|---|---|
| 消融 Correctness | 57.8 | 70 | −12.2 | FAIL |
| 消融 Faithfulness | 65.0 | 75 | −10.0 | FAIL |
| 消融 Completeness | 34.4 | 65 | −30.6 | FAIL |
| 延迟 p50 | 29737ms | 25000ms | 超 4737ms | FAIL |
| 延迟 p99 | 76676ms | 60000ms | 超 16676ms | FAIL |

失败原因：口语化表达、0 切片导致拒答、deep_thinking 拖慢。

### 5. 方案

| 方案 | 结果 | 未过项 |
|---|---|---|
| A（激进检索：hyde、multi_query×3、top_k 6、min_score 0.2…） | 8/10 | p50 71s、p99 115s 超 |
| B（关深度思考，multi_query on，top_k 5…） | 8/10 | 消融 Correctness 61.1、Completeness 52.2 未过 |
| C | 7/10 | 未知 |
| D"关闭深度思考的多路召回增强" | **10/10 全部 PASS** | — |

D 的关键数据：

- 消融：74.4 / 90.6 / 68.3；
- p50 24680ms，p99 58640ms；
- 改动：hyde 开、multi_query 开、top_k 6、min_score 0.2、deep_thinking 关。

### 6. Bad Case 地图（含优先级）

| 类别 | 严重度 | 示例与修法 |
|---|---|---|
| 检索失败（查不到） | 致命 | 口语、缩写、单字不匹配、场景外问题；HyDE 可大幅缓解 |
| 检索噪声 + 方向错 | 严重 | 需要 rerank 加 prompt 协同 |
| 模型过度拒答 | 中等 | 约 10/56 题；调 prompt 置信度分级 |
| 延迟高 | 致命 | 主 LLM deep thinking 占 40–50%，需改工作流 |
| 安全边界误伤 | 轻微 | — |

核心结论："正向优化提升能力上限，逆向与边界优化守住安全下限；真正难的是避免'修好 A，搞坏 B'。"

### 7. Agent 运行流程

1. 读取 Baseline；
2. 分析；
3. 生成 3 个候选；
4. 分别在 Sandbox 里评测；
5. 汇总；
6. 判断是否达到评估目标：
   - 否 → 回到第 2 步；
   - 是 → 输出最佳配置。

### 8. 其他

- 黄金集生产 Prompt 共 3 个：生成、质检、修正。
- 每题字段：id、qa_type、question、answer、golden_chunk、test_node、config_param、initial_value、note、knowledge_domain、difficulty、keywords、parameter。
- 参考资料：AutoRAG、Loop Engineering（Goal / Context / Feedback → Discover → Plan → Execute → Verify → Iterate，配 Stop Condition）。
