## 1. 已经定下来的原则（用户历次说过的，讨论时不要推翻）

### 1.1 讲故事
1. **demo 是讲故事用的。**故事性第一，信息完整第二，好看第三。三者都要，但冲突时按这个顺序。
2. **方案 D 存在的意义**：第 3 轮方案 C 成功了，但没有完全成功，还剩错题。所以要在 C 的基础上，用前几轮总结的经验，找一组更好的参数组合，形成 D。D 成功有原因，没修好的题也有原因，都要能讲。
3. **"先把算力拉满，再降档"是用户自己的设计巧思**，面试会主动讲：Baseline 用最高思考档，Agent 去尝试降档并用检索来补偿。
4. **A/B/C 必须是三个真正不同的方向**，其中一套固定为"效率方向"（降思考档 + 检索补偿）。
5. **面试中不讲"大模型幻觉、大模型不稳定"**。内部复核可以做，但不在 demo 里出现。

### 1.2 页面措辞
6. **少用技术腔**：
   - 页面不出现日志式语言、内部编号、"线上 V1/V2"这类说法；
   - 常见行业术语保留英文，如 embedding、rerank、Hard Gate；只把冷僻说法翻成中文。
   - 主画面只露短题号，如 Q04。
7. **措辞中性**：以后可能给客户看，不写"绝对优势、大幅提升"这类自夸，让数字说话。
8. **不出现**"导入、内部、试跑、复跑、随机、不稳定"等字样。模型回答原文和题目原文里本来就有的除外。

### 1.3 信息呈现
9. **必要信息不能大幅删减。**UI 改版只改呈现方式，不改信息量。
10. **同类卡片等高对齐、不留空白。**文字溢出时，用固定尺寸容器加内部滚动；表格两行截断，悬停看全文。

### 1.4 UI 风格（11-06 定的方向，具体待讨论）
- **"适度圆角"规范**：
  - 圆角按组件大小分级：状态徽章用胶囊形，按钮和输入框约 10px，卡片约 14px，抽屉和弹窗约 20px，表格只在外框用 12px；
  - 内层圆角 = 外层圆角 − 内边距；
  - 用柔和阴影代替硬边框，8px 网格；
  - 主按钮用唯一的那种绿色；
  - 不要 24px 以上的大圆角，不要到处胶囊，不要毛玻璃和渐变。
- **参考的那个仪表盘视频**：喜欢它的丝滑交互和"简洁明了"，颜色克制、字体和图表精致。
  - 不要点阵图，因为每道题本身已经带有详细信息。
  - 不要真 3D，判断理由见 4.4。

### 1.5 执行方式
- 执行顺序：先定故事 → 再按卡片定 UI → 再定由 Claude Code 还是 Codex 实现；**代码或精确规格都由 Claude 来写**。用户说"我们要优化前端 UI"后才开工。
- 发布由用户亲自点，Agent 和 Codex 一律不点。

## 2. 故事主线

### 2.1 一句话版
> "我做了一个让 RAG 自己变好的系统：先用一套冻结的考卷给现有版本打分，找出错题；再让 Agent 按错题原因提出几套调参方案，在沙盒里用同一套考卷比较；只有'修好错题、且不弄坏原来对的题、所有门槛都过'的方案，才交给人来决定上线。"

### 2.2 三个核心论点（整个故事都在证明这三句话）
1. **先能量化，才能优化**：
   - Golden 考卷是怎么出的：按知识主题分配题位，程序校验，再加两道质检；
   - 冻结之后才能拿来评测，所以每一轮都用同一把尺子量。
2. **优化要可归因、可控**：
   - A/B/C 是三个互不相同的方向，每个改动都能说清"修好了哪题、弄坏了哪题、为什么"；
   - Agent 只能在白名单参数里调；
   - 修好错题不能抵消弄坏的题。
3. **机器提议、人来拍板**：
   - 门槛、回归检查、发布资格都由程序把关；
   - 最后上线由人确认，可以回滚；
   - 上线后的问题通过"线上反馈"回流，触发下一轮。

### 2.3 主线结构（9 拍）

| 拍 | 讲什么 | 在哪一页 | 关键数字 |
| --- | --- | --- | --- |

| ④ 诊断 | 6 道错题按层归因：检索层 5 道、生成层 1 道，决定优化方向 | Agent · 问题诊断 | 5 + 1 |

| --- | --- | --- | --- |

### 2.6 讲故事的几条"不要"
- **不要从技术架构讲起。**先讲问题和结果，架构图留给追问。
- **不要逐个念表格。**每页只说一句"这页证明了什么"，再点一个例子。
- **不要在页面上读到长段落。**页面上出现需要讲解者解释的长段落，说明 UI 需要改，见 5 节 P0-1。

## 3. 逐页拆解：故事角色 · 现有卡片 · 问题 · 建议 · 设计巧思

每页按同一格式：**这页证明什么 → 讲解一句话 → 现有卡片 → 问题 → 建议的卡片结构 → 设计巧思 → 交互 → 必须保留的信息**。

### 3.1 RAG 自进化项目概览

- **这页证明什么**：这是一个完整的闭环，结果可量化。
- **讲解一句话**："从知识到线上改善，6 步闭环；答对从 44 到 48，零新增错题，最终由人确认发布。"
- **现有卡片**：
  - 5 个指标卡：答对数、最慢回答 P99、安全拒答率、Agent 轮次、评测方案数；
  - "从知识到线上改善"流程条：6 个节点；
  - "当前下一步"卡：人工确认发布；
  - 线上版本说明一行；
  - 技术详情折叠；
  - 另有两个页签：业务架构、技术架构。
- **问题**：
  1. 5 个指标卡平铺，看不出主次。真正的"主角"是 44→48，它和其他卡一样大。
  2. "评测方案数 10 个 · 含已启动的融合方案"措辞别扭，改为"含方案 D"。
  3. 流程条每个节点只有一行小字，缺少"这一步的成果"。比如 Golden 节点可以写"50 题 · 冻结"，Agent 节点可以写"3 轮 9 套 + D"。
  4. 发布后，"当前下一步"和线上版本说明都要变化，目前未验证，021o 会补。
- **建议的卡片结构**：
  - **主指标卡**：答对 44 → 48，加一条"修好 4 · 新增错题 0"。
  - **3 个次指标卡**：P99、安全拒答率、预算 10/12。
  - **流程条**：每个节点写"状态 + 一个成果数字"，点击直达对应页。
- **设计巧思**：**"流程条就是目录"**。整个 demo 的讲解路线就是这条流程条，面试时可以说"我们按这条线走一遍"，每点一个节点就跳到对应页，讲完回到概览。
- **交互**：
  - 鼠标悬停在节点上，弹出深色提示卡，显示这一步的 3 个关键数字；
  - 点击节点跳转到对应页。
- **必须保留**：5 个指标的全部数字，线上版本说明，两张架构图。

### 3.2 知识库

- **这页证明什么**：考题不是凭感觉出的，而是按知识主题覆盖出来的。
- **讲解一句话**："说明书切块后按语义聚成 9 个主题，再按主题大小分配正向、消融、负向题位，小主题也有保底。"
- **现有卡片**：
  - 说明行："Child 向量化 → K-means 动态聚类 → …"；
  - 9 张主题卡，每张写"N 个 Child · N 个题位"和三类题位数；
  - 技术架构页签；
  - "更多"按钮。
- **问题**：
  1. "Child"是内部术语，讲解者要解释，建议改成"知识片段"。
  2. 9 张卡片信息相同、视觉相同，看不出"覆盖"的意思，缺一个总览。
- **建议**：
  - 顶部加一条横向比例条：9 个主题按片段数排开，每段里再分出正向、消融、负向题位的颜色。一眼看出"大主题多出题，小主题有保底"。
  - 下面保留 9 张卡，作为明细。
- **设计巧思**：**"小主题保护"**。片段少于 3 个的主题不会被大主题吞掉，保证冷门知识也有题考，这是覆盖规划里最好讲的一点。
- **交互**：
  - 悬停比例条的某一段，对应的卡片高亮；
  - 点击卡片，抽屉打开这个主题下的题目列表。
- **必须保留**：9 个主题全部数字，处理流程说明，技术架构页签。

### 3.3 Pipeline 配置

- **这页证明什么**：Agent 的权限是有边界的。
- **讲解一句话**："上半部分是固定底座，包括解析、分块、向量模型、判分模型，Agent 不能动；下半部分是 Agent 能调的 12 项参数，每项只有几个固定选项。"
- **现有卡片**：
  - 固定技术基座：8 项；
  - Agent 可选参数，按 查询理解 / 检索召回 / 筛选排序 / 生成 分组，每项是一个分段选择器，下面一行说明。
- **问题**：
  1. 这页现在相对清楚。
  2. 唯一缺的是和故事的连接：看不出哪些参数在优化中真正起过作用。
- **建议**：
  - 每个参数的分段选择器上，同时标出两个值：Baseline 用的值（灰点）和最终推荐方案用的值（绿点）。例如候选条数 12 是灰点、24 是绿点。
  - 参数旁加一个小标签，例如"第 3 轮 C、方案 D 使用"。
- **设计巧思**：**"白名单调参"**。Agent 不能发明参数，只能在这 12 项、每项几个选项里组合。这是"可控、可审计"的直接证据。
- **交互**：悬停在参数上，深色提示卡显示"哪几轮用过、当时修好或弄坏了什么"。
- **必须保留**：全部固定项、全部参数和说明。

### 3.4 Golden Dataset

- **这页证明什么**：尺子是可信的。
- **讲解一句话**："50 道题经过覆盖规划、出题、程序硬校验、Probe 实测、QC 质检、人工确认，6 步全过才冻结；冻结后每一轮都用同一套题。"
- **现有卡片**：
  - 6 步状态条，全部已完成；
  - 题目审核表：题号、题型、问题、出处、评分要点、Probe、QC、Baseline、操作；
  - 页签：当前测试集、候选池；
  - 题目详情抽屉。
- **问题**：
  1. "出处"列显示原始文件名"卡赫_KIRA_B_50完整操作说明…"，要统一用 021n 定的短名"KIRA B 50 操作说明"。
  2. "评分要点"列写成"必答 2 · 加分 0"，比较晦涩，可改为"2 条必答"。
  3. Baseline 列"错 · 检索层问题"很好，可以加一个小色点，和 Agent 页呼应。
- **设计巧思**：**"人只看红线"**。程序硬校验加 Probe 加 QC 先筛掉问题题目，人只需确认冻结，审核成本低，标准一致。
- **交互**：
  - 题型筛选（全部 / 正向 / 消融 / 负向）的选中块滑动切换；
  - 行悬停时预取详情，点击后抽屉即开。
- **必须保留**：全部列，详情抽屉内容，候选池。

### 3.5 Baseline

- **这页证明什么**：现状是"合格但不完美"，而且瓶颈在生成。
- **讲解一句话**："Baseline 用最高思考档：11 项门槛全过，但 50 题里错了 6 道；95.8% 的时间花在生成回答上，这是后面降档提速的伏笔。"
- **现有卡片**：
  - 回放说明一行，021p 会移进技术详情；
  - 门槛已通过横幅；
  - 4 个指标卡：门槛、答对、综合分、P50；
  - 耗时拆解表；
  - Recall@K、Precision@K、MRR 三张卡；
  - 页签：门槛、Bad Case 诊断。
- **问题**：
  1. "伏笔"不明显。耗时拆解是一张普通表，95.8% 没有被强调。
  2. Precision@K 29.2% 单看像很差，没有解释，面试官可能追问。要么加一句含义，例如"进入回答的 4 段证据里，平均约 1 段是标准证据，其余是相关的补充内容"；要么移进技术详情。
  3. 主画面没有出现"最高思考档"这个关键事实，只在 Agent 页的小字里有。
- **建议**：
  - 指标卡加一张"回答思考档位：最高"。
  - 耗时拆解改成一条横向堆叠条：生成占 95.8% 的大块、检索和重排各一小块，配一句"生成占绝大部分耗时"。
- **设计巧思**：**"先拉满再降档"**，这是用户自己的巧思。这一页只埋伏笔：先展示最高档的质量和代价；到 Agent 页再揭晓降档加检索补偿后，P99 从 42.2 秒降到 22.6 秒。
- **交互**：悬停在堆叠条的某一段上，显示这个环节的累计秒数和占比。
- **必须保留**：11 项门槛的全部数值和要求，耗时表，三个检索指标，Bad Case 诊断。

### 3.6 Agent 工作台（全 demo 的核心，6 个页签）

**顶部共用区**：
- 6 步状态条：诊断 → 生成 A/B/C → 方案 A/B/C/D → Sandbox → 回归检查 → 最终推荐；
- 进度行："第 3 轮 · 3/3 · 已评测 10/12 次（含方案 D）"。

**顶部共用区的问题**：
1. 副标题换行，末尾单独剩一个"修"字，要调整措辞或宽度。
2. 状态条的计数只反映第 3 轮，例如"3 个方案 · D 已评测"。故事要的是全局："3 轮 9 套 + 方案 D"。

#### 3.6.1 问题诊断
- **这页证明什么**：优化方向来自错题原因，不是拍脑袋。
- **现有**：
  - 本轮 Bad Case；
  - 优化优先级表：检索层 5 道 · 严重，生成层 1 道 · 中等；
  - 延迟说明；
  - 分类筛选；
  - 6 题明细：题号、分类、现象、严重程度、方向。
- **问题**：
  - "安全边界 0、性能 0"两个空筛选项占位；
  - "Golden Chunk 未进入 Top-K"按用户规则可以保留英文，但最好悬停时给一句中文解释。
- **设计巧思**：**"按层归因"**。错题先分到检索、生成、安全、性能四层，再决定方向，所以 A/B/C 不是随便选的。

#### 3.6.2 进化路线（讲解时停留最久）
- **这页证明什么**：每一轮都在学习，最终找到答案。
- **现有**：
  - 纵向时间线：Baseline 起点（错题按层分 4 张卡）→ 第 1、2、3 轮，每轮 A/B/C 三张卡，写修好、弄坏、参数 → 方案 D 大卡；
  - D 大卡包括：预测 vs 实际表、赢家与 D 并列表、没修好的原因、结论句。
- **问题**：
  1. Baseline 起点的"安全边界 0 道""性能 0 道"两张空卡占位，可以合并成一行小字。
  2. 每轮之间缺少一句"这一轮学到了什么"。例如第 1 轮学到"分级回答会伤安全题"，第 2 轮学到"重排会弄坏 Q13、Q17"。这是"可归因"论点最有力的证据，现在要靠讲解者口述。数据来源是每轮 Agent 的 reasoning 和事实表，**不编**。
  3. 每张方案卡的修好、弄坏列表是题目原文，很长，大多截断。可以改成"题号徽章"：修好用绿色 Q24、弄坏用红色 Q07，悬停看原文。
- **建议**：
  - 时间线每轮加一条"本轮结论"，一行；
  - 方案卡统一为：方向名 → 参数变化胶囊 → 修好 / 弄坏题号徽章 → 门槛结果 → 判定徽章；
  - D 卡保持现在的信息量，只做视觉层级。
- **设计巧思（全 demo 最大的一个）**：**"修好 A 不能搞坏 B，而且每一次失败都留下一条经验"**。
  - 前 8 套都"修好一些、弄坏一些"；
  - 第 3 轮 C 用"降档 + 扩候选"第一次做到零新增；
  - D 只加一个前几轮验证过的参数，并提前预测会修好什么、可能弄坏什么，最后用实际结果对账。
- **交互**：
  - 悬停在题号徽章上，弹出深色提示卡：题目原文、这题在 Baseline 和本方案的对错；
  - 点击方案卡，从右侧抽屉滑出方案详情。

#### 3.6.3 A/B/C/D
- **现有**：轮次切换（第 1、2、3 轮），三张方案卡，内容有方向、核心思路、参数变化、判定等。
- **问题**：这一页和进化路线信息重叠较多，定位要分清：进化路线讲"故事"，A/B/C/D 讲"每套方案的设计意图"。
- **设计巧思**：**"强制三方向 + 参数互斥"**。三套方案不允许用同一个改动，所以每个结果都能归因到一个方向。

#### 3.6.4 Sandbox
- **现有**：轮次切换，加一张大对比表：Baseline、本轮 A/B/C、方案 D，逐行列运行状态、门槛、Bad Case、修复数等。
- **问题**：
  - "目标问题修复、全部原问题修复、其他问题改善"三行概念接近，非技术听众分不清；
  - 表很长。
- **建议**：
  - 前 4 行为主：答对、门槛、新增错题、P99；
  - 其余行折叠为"更多指标"。
- **设计巧思**：**"同一把尺子"**。所有方案用同一套冻结题卷、同一判分身份，结果才可比。

#### 3.6.5 回归检查（问题最多，见 5 节 P0-1）
- **这页证明什么**：修好不能抵消弄坏。
- **现有**：
  - 赢家与 D 对比表；
  - **一段很长的日志式文字**，例如："候选方案 A：修复 1 个指定目标；新增严重 0、普通 3 个失败（上限分别为 0、1）。；正式阻断 0 题，资格仍按保存的 回归检查结果判定 保存判定：通过……"；
  - 新增失败表。
- **问题**：
  1. 这段文字是日志腔。
  2. **前后矛盾**：A 普通新增 3 个、上限是 1，却写"保存判定：通过"；段落说"新增严重 0"，下表却把 Q13、Q30、Q37 标成"严重退化"。
  3. "候选方案 A"没写是第几轮。
  
  面试官细看会直接问到。
- **建议**：
  - 换成一张表，每行一个方案：修好 · 新增严重 · 新增普通 · 上限 · 判定。判定必须和数字一致。
  - 规则写一行："严重新增上限 0、普通上限 1；修好的题不能抵消新增的错题"。
- **设计巧思**：**"零容忍安全题"**。安全关键题弄坏一道就直接不合格。

#### 3.6.6 最终推荐
- **现有**：推荐方案 D，Baseline 对 D 的对比表，"为什么选它"一句，"其他方案为什么没选"9 行（021o 已改成每行一句具体理由），去发布按钮。
- **问题**：
  - 9 行理由很好，但视觉上是一长串文字；
  - 可以做成小表：方案 · 修好 · 弄坏 · 没过的门槛，和 2.5 速查表一致。
- **设计巧思**：**"落选也有理由"**。每个方案为什么没被选都可追溯，不是黑箱。

### 3.7 发布

- **这页证明什么**：最后一道闸在人手里，而且可以反悔。
- **讲解一句话**："程序只给出发布资格，上线必须由人确认；发布会保存完整快照，任何时候都能回滚到上一个版本。"
- **现有卡片**：
  - 待发布方案：方案 D、参数变化、Baseline 对 D 的表；
  - 发布检查清单：门槛全过、零新增错题、已有修好的题、人工确认；
  - 确认发布按钮、评测报告；
  - 当前线上配置；
  - 版本历史与回滚。
- **问题**：
  1. 左栏头部"本轮推荐，尚未发布 / 线上配置 → 推荐配置 / Baseline → 推荐方案"三行小标题挤在一起，层级不清。
  2. 检查清单里的"人工确认 · 已满足"指的是**报告确认**，不是发布确认，容易被误解为已经发布。建议改为"推荐报告已人工确认"。
  3. 发布后各处的状态措辞未验证，021o 会补。
- **设计巧思**：**"可回滚的发布快照"**。发布时保存当时的配置、评测、门槛、推荐理由，回滚时恢复整套配置，而不只是一个参数。
- **交互**：
  - 点"确认发布"弹出确认框，列出将要替换的配置差异；
  - 发布成功后，线上版本卡平滑切换成方案 D。
- **必须保留**：清单、对比表、快照、回滚入口。

### 3.8 问答验证（3 个页签）

#### 3.8.1 实时问答
- **这页证明什么**：系统是活的，不是截图。
- **现有**：对话区、3 个示例问题、"当前为初始配置"。
- **问题**：
  - 发布后要清楚显示"当前线上：方案 D（候选 24 · 证据 6 · 思考 高）"；
  - 画面比较空，回答区可以复用前后对比页的结构化回答样式：引用编号、来源列表。
- **设计巧思**：**"回答带出处"**。每句话都能点开说明书原文。

#### 3.8.2 优化前后对比（021l/021n 刚按设计稿重做，是目前完成度最高的一页）
- **现有**：
  - 左侧题目列表：修好 4、仍未修好 2、全部 50，加搜索；
  - 题目头，带判定变化；
  - "这道题为什么变好"时间线：配置变化 → 关键证据位置 → 回答结果；
  - 必答要点对照表；
  - 两栏结构化回答：判分原句高亮、引用编号；
  - 数据佐证：配置差异胶囊、本题数据对比条。
- **问题**：基本没有。可以作为全站改版的样板页。
- **设计巧思**：**"因果链 + 判分原句高亮"**。从"改了哪个参数"到"证据排第几"再到"补上了哪条要点"，一条链讲清楚，并且在回答里直接标出判分时引用的那句话。

#### 3.8.3 线上反馈 → 再次进化
- **现有**："用户提问 → 人工标记坏例 → 触发新一轮 Agent"的说明，加反馈表。
- **问题**：
  - 有 2 条旧测试反馈，用户已决定删除（021p）；
  - 删除后需要一个引导性的空状态。
- **设计巧思**：**"闭环"**。线上发现的问题经人工判定后回到 Agent，不会绕过评测和发布。

## 4. 全局 UI 方案（需要和 GPT 讨论的重点）

### 4.1 方向
参考视频的气质：**大面积灰白，只在"最重要的那一个数"上用强调色**；字小而精，数字等宽对齐；线条细，留白多；交互顺滑。
**原则：只改呈现，不减信息。**

### 4.2 颜色（两个方案，待选）
- **语义色固定**：答对、改善用绿色；答错、弄坏用风险红。这两个颜色全站一致，不随强调色改变。
- **方案 甲（深绿强调）**：强调色就是答对的那个深绿。最安全，但"高级感"略弱。
- **方案 乙（橙色强调，接近视频）**：强调色用暖橙，答错改成深红或灰。更像视频，但橙色和红色接近，可能把"重点"和"错误"混淆。
- **待讨论**：是否有第三种强调色，例如墨蓝，既高级又不和红绿冲突。

### 4.3 字体与数字
- **字号**：页面标题 26、卡片标题 14 半粗、正文 14、辅助文字 12–13、关键数字 28–32。
- **数字**：一律等宽对齐（tabular numbers）。
- **变化标注**：用小胶囊，例如"↑ 6.1%""−7.1 秒"，颜色按好坏。

### 4.4 交互（"丝滑"的来源，成本都低）

| 交互 | 规格 | 用在哪 |
| --- | --- | --- |
| 抽屉滑出 | 从右侧滑入约 0.25 秒，缓出曲线，背景轻微变暗 | 方案详情、题目详情、证据原文、配置快照 |
| 页签、分段切换 | 选中块滑动过去，内容约 0.15 秒淡入 | 全站页签、轮次切换、题型筛选 |
| 深色悬停提示卡 | 约 0.12 秒淡入，内容为 3–5 行关键数据 | 题号徽章、流程条节点、图表数据点、参数 |
| 数字变化 | 发布后线上版本卡数字平滑过渡 | 发布页、概览 |
| 卡片悬停 | 阴影轻微加深，不位移 | 可点击的卡片 |
| 减少动态 | 系统设置"减少动态效果"时全部关闭 | 全站 |

- **不做真 3D 图表**。原因：我们的数据是"每题对或错"，3D 只增加阅读难度；需要引入大体积的 3D 库，投影仪或低配电脑上可能卡；实现最复杂，也最容易坏。
- **不用重型图表库**。图表用 SVG 手画，数据量很小。

### 4.5 可复用组件（建立一次，全站用）
1. **前后对比数值**："44 → 48"，前值灰色、后值黑色加粗，后面跟变化胶囊。
2. **题号徽章**：Q04，绿色表示修好，红色表示弄坏，灰色表示无变化；悬停看原文。
3. **参数变化胶囊**："候选条数 12 → 24"。
4. **因果链时间线**：从问答验证页抽出来复用，用在 D 卡、问题诊断。
5. **判定徽章**：合格、未通过、推荐、已发布。
6. **深色悬停提示卡**。
7. **右侧抽屉**：统一宽度、统一头部、统一关闭方式。

## 6. 面试可能被追问的问题（准备思路）

> 原则：**如实回答**，数据都在页面上能指给对方看。

| 可能的问题 | 回答思路 | 指向页面 |
| --- | --- | --- |
| Baseline 门槛都过了，为什么还要优化？ | 门槛是底线，不是终点；还有 6 道错题，其中 5 道是检索层问题，有明确的优化空间 | Baseline、问题诊断 |
| D 的 P99 比 C 慢（36.7 秒对 22.6 秒），为什么还选 D？ | 推荐规则是先比错题数，错题更少的胜出；相同时再比 P99 和成本。D 少错 1 道，P99 仍在 60 秒门槛内。这是明确写在规则里的取舍 | 最终推荐、回归检查 |
