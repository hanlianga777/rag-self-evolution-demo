## 加载调整中发现并修复的问题

1. Golden 回访先取轻量快照，已有完整题卷缓存也要重新等待。补用例先复现骨架，再修复完整缓存的选择和摘要刷新后的保留；缓存仍按现有身份和读版本规则隔离。
2. Before/After 原来等所有题目的回答都取完才显示列表。改为先显示列表，再按选择读取回答；题卷与 Judge 身份检查、取消过期回写、详情缓存和原文都保留。
3. Agent 的 planning 只读接口本机一次测得约 2,330 毫秒。改成概要先出、规划随后读；单个和批量 Sandbox 等依赖规划的操作均等待身份匹配的规划，不能因提速暂时放开原有限制。
4. Hard Gate 行用原生点击处理器，i 用 React 点击处理器，单靠 React 阻止冒泡太晚。行处理器现在忽略 i，键盘操作也不误开抽屉，且有定向交互测试。
5. 移除全量预加载后，Monitoring 接触到了轻量记录中的证据摘要对象，原 `missedEvidenceRank` 对它调用数组 find 会报错。现在只对真实数组查找排名，摘要不足时按未知处理；完整数组的原规则保留。没有改写保存记录。

来源：上述代码、`task032a-foundation.test.tsx`、`task022f-warmup.test.tsx`、`task021l-comparison.test.tsx`；先失败再通过的本机记录在 `cache-red.txt`/`cache-green.txt`、`lazy-comparison-red.txt`、`light-evidence-red.txt`。独立只读审查发现的两项问题均修复，最后复核无 Important/Critical 遗留。
