## 2. 判分现状

`BUSINESS_JUDGE_PROMPT` 按 Python `len()` 计 **7317 字符**（含空格、标点和英文）；去空白 **7313** 字符，UTF-8 **14743** 字节。不是 token 数。用 AST 取字符串常量，无需导入或启动后端。SHA-256：`31a8a09695970cbac4465ed6020c6fe77dcb70ac2db9f1344236e528b28477a6`。来源：`backend/app/evaluation_contract.py:484–547`。

### Judge JSON 字段

- 顶层：`verdict`、`atomic_results`、`checks`、`issues`、`reason`、`quality`。
- `atomic_results[]`：`atomic_id`、`check_type`、`state`、`triggered`、`reason`、`answer_quotes[]`、`support[]`。
- `checks[]`：`check_type`、`requirement`、`met`、`answer_quotes[]`、`support[]`；可选诊断扩展：`scope_support[]`、`reference_support[]`、`candidate_support[]`、`scope_resolved`。
- `issues[]`：`description`、`atomic_ids[]`、`failure_kind`、`answer_quotes[]`、`support[]`、`critical`、`safety_violation`、`scope_resolved`。
- `quality`：`correctness`（0–4整数）、`faithfulness`（0–1）、`completeness`（0–1）。普通support为 `source_id/quote`，scope_support另含 `heading_source_id`。
- 程序还会添加 `compiled_contract_hash`、`atomic_failure_keys`、`behavior_pass`、Usage/费用/重试/原响应等运行字段；这些不是要求Judge另行编写的输出。

来源：`evaluation_contract.py:536–544、468–470`；`providers.py:415–428`；`evaluation.py:581`。

### 会转成“技术失败”的校验

**按独立校验归组，共37条**：JSON解析1条、通用业务合同21个显式拒绝点、原子裁决14个显式拒绝点、三维quality类型与范围1条。重复执行同一校验不重复计数，循环检查多个引用也只计一条。通用合同中2条是输入完整性前提（类别、Final），列出但不把责任归到Judge。质量对象/范围在runtime与score层重复验证，按同一逻辑规则计1条。

这不是“仅37种可能异常”：字典缺键/错误嵌套类型也可能触发统一捕获的 KeyError/TypeError；超时、HTTP失败、空响应、截断属于传输/响应可用性失败，另见后文，不与Schema重复计数。冻结题卷编译错误是输入/预检错误，不算Judge输出校验。
