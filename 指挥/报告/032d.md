## 每条怎么处理

### #12 通用知识处理链路

改成一条无数字的通用流程，按任务单顺序展示：解析去噪 → 按章节组 Parent → Parent 内切 Child → 向量 + 关键词索引 → K-means 主题簇。每一步只有一句解释。原有样例里写死的分块编号和动态参数链路不再用于这个页面。页面说明仍沿用第三轮文案。

来源：`frontend/src/pages/KnowledgePage.tsx` 的 `processing`；新增前端测试断言整条链路不含数字。

### #13 分块诊断

新增 `GET /api/knowledge/chunk-diagnostics`，从当前索引目录的 `parents.json`、`chunks.json` 计算指标。前端直接读接口，每个指标使用现有统一的 `InfoTip` 说明重要性。

我是这样理解的：

- “碎块数”采用少于 **60 tokens** 的非表格 Child 数；短表格按既有分块规则作为例外。接口同时给出阈值和例外口径，悬停说明中展示。它不是纯页眉、页脚噪声块的计数。
- “Child 平均长度”采用入库时保存的 `token_count`，单位是 tokens；不现场加载 tokenizer 或模型。缺少长度记录时显示“未知”。
- Parent 不存在时，平均 Child 数和单 Child Parent 占比显示“未知”，不假装为零。

当前真实读数：

| --- | --- |
| Parent 数 | 40 |
| Child 数 | 200 |
| 碎块数 | 0 |
| 平均每个 Parent 的 Child 数 | 5.0 |
| 单 Child Parent 占比 | 5.0% |
| Child 平均长度 | 接口 216.18，页面 216.2 tokens |

来源：`backend/app/knowledge_browser.py::chunk_diagnostics`；本机 `output/task032d/live-summary.json`；接口 `/api/knowledge/chunk-diagnostics`。

### #13 分块浏览器

“查看分块示例”替换为“分块浏览器”。打开宽抽屉，三栏独立滚动：

- 左栏选择文档，再按章节、页码和 Child 数选择 Parent。
- 中栏显示完整 Parent 原文；按保存的字符范围交替标浅底色；悬停显示 `Child 序号 / 总数`；重叠部分显示双下划线。字符范围按 Unicode 字符处理，原文不截断、不改写；范围未保存时提示不能标色，不猜位置。
- 右栏只按冻结题卷保存的证据锚点关联考题，显示题号、题型和命中 Child。点击题号，高亮并滚动到对应范围；“查看题目”打开只读题目抽屉，显示问题、参考答案、预期行为和证据原文。

文档检查器的“分块结果”页签也进入同一个浏览器；PDF 原文、索引信息和表格案例入口保留。

新增 `GET /api/knowledge/chunk-browser`。知识库文件只读；题卷使用 SQLite `mode=ro` 和 `PRAGMA query_only=ON` 读取，不连接当前可编辑候选题、当前 Probe 或 QC 结果。

我是这样理解的：“被考题命中”表示题卷中已保存的证据关联，不代表在线检索或历史评测的召回结果。当前题卷采用最新 approved 冻结快照，与线上发布旧版还是新版无关。旧锚点无法对应当前分块时不算命中，并单独提示。本次读到冻结题卷 `GD-20261114160635` 的 50 道题，无法对应当前分块的锚点数量为 0。

来源：`backend/app/knowledge_browser.py::chunk_browser`；`frontend/src/components/KnowledgeChunkBrowser.tsx`；本机 `output/task032d/live-summary.json`。

### #14 知识主题抽屉

重排为任务单要求的三段：

1. 主题是什么：一句话、关键词和来源文档。关键词按该主题包含的章节标题出现频次提取，不调用模型。
2. 包含哪些 Parent：列出该簇所有 Child 所属的 Parent，去重；入口带章节、Child 数和页码，点击进入浏览器并定位。
3. 对应哪些考题：按正向、消融、负向分组；点击打开同一个只读题目抽屉。

有证据锚点的题按当前簇的 Child 关联。无证据锚点的题，只有冻结快照中的主题成员与当前主题成员完全一致时，才采用它保存的主题归属；不因两轮都叫同一个主题编号就直接认定相同。没有证据的负向题可以归属于主题，但不会冒充某个 Parent 的命中题。

来源：`backend/app/knowledge_browser.py::cluster_browser`；`backend/app/main.py` 的主题详情接口；`TopicDetails`；对应后端测试。

### #15 文档类别

文档列表新增类别列，长类别按两行展示并可悬停查看全文。规则集中在 `backend/app/knowledge_pipeline.py::DOCUMENT_CATEGORY_RULES`：电池/充电器优先，再遥控器，再清洁/KIRA/卡赫，再四足/巡检/B2，否则“其他”；英文匹配不区分大小写。

我是这样理解的：本单明确要求按文档标题归类，因此类别展示以标题规则为准，不再优先采用旧的人工类别或产品字段。只改变读取/归类规则，没有改已保存的索引文件。
