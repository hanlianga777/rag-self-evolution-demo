## 切块方式与导出口径

实际索引参数取自 `backend/data/index/manifest.json.knowledge_config` 及顶层 `target_tokens/overlap_tokens`，没有使用代码里旧索引的常量代替：

|---|---|---|

| 子块目标 | `child_target_tokens` / `child_target_min_tokens` | 250 / 200 tokens |
| 子块尾段下限 | `child_tail_min_tokens` | 80 tokens |
| 父块上限 / 下限 | `parent_tokens` / `parent_min_tokens` | 1400 / 400 tokens |
| overlap | `overlap_tokens` | 50 tokens |

| 解析器 | `parser` / `parser_mode` | MinerU / vlm |
| 表格处理 | `table_normalize` | table-kv-v2 |
| Tokenizer | `tokenizer_model` | BAAI/bge-small-zh-v1.5 |
| 去噪 / 标题上下文 | `denoise_version` / `heading_context` | mineru-noise-v3 / child-section-v2 |

以上大小为索引保存的配置参数，不是每块实际字数或重新计算的 Token 数。本单未重新分块。

我是这样理解的：“全部切块”以 `chunks.json` 的全部 200 个检索子块为主表；父块也是系统取证上下文，因此另附 `046-父块全量.csv` 的全部 40 个父块，避免把两种记录混在同一主表中而影响逐块计数。两份 CSV 列相同：`chunk_id`、`doc_id`、文档名、页码、章节标题或父级上下文、`chunk_index`、字数、切块原文。

- `doc_id` 来自保存记录的 `document_id`，文档名来自 `documents.json.name`。
- 页码直接采用 `page_start/page_end`，跨页写起止范围，不猜印刷页码；没有则写“未知”。本次所有父子块都有保存页码。
- 章节/上下文列为 JSON，保留记录已有的 `level_one_section`、`chapter`（若有）、`section_path`、`section_paths`；子块再保留 `parent_chunk_id` 和对应父块的 `parent_section_path`。没有重新生成标题。
- 索引没有单独存 `chunk_index` 字段。本单按各源 JSON 数组中文档内顺序，分别对父块、子块从 **1** 编号；逐条确认与现有块 ID 末尾编号一致。这是导出顺序号，不冒称数据库原有字段。
- 字数为 `len(chunk_text)`，包含标点、空白和换行，不是 Token 数。
- 原文采用 `chunk_text`（逐条确认与 `text` 相同），仅把真实换行转为字面 `\n`。未裁剪、清洗或改写，已有 OCR 错字、HTML/数学标记均保留。回读还原换行后，逐条与原文完全一致。
