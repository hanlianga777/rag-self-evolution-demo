## Agent 数据与诊断迁移

`buildEvolutionModel(experiment, evaluation.config, metric => gateNames[metric] ?? metric, schemeName)` 直接消费当前保存实验。`evaluation.config` 是正式 Baseline 运行快照，不是现在的线上参数或硬编码的样板配置。读取并在“Agent 规划 → Baseline 运行参数”核对：Candidate K **12**、Top-K **4**、Thinking **Max**、向量权重 **0.5**、Multi-Query **关闭**、回答策略 **有据生成**。来源：`evaluation.json`、`EvolutionPage.tsx`。

`baseline.badCases` 使用原 `agentDiagnosisRows` 的当前 Baseline Bad Case，现有诊断分类去掉“问题”后显示分层计数；本机为检索层 5、生成层 1。题目悬停沿用已有 `questionText`，卡片点击沿用 `setSelectedCandidate` 抽屉。Agent 顶部的轮次来自保存的 A/B/C 轮次，Candidate 数来自当前候选列表；发布状态来自实际线上版本；运行或等待文字保留断点进度、覆盖缺口、生成失败和 D 状态。来源：`EvolutionPage.tsx`、`api.ts`、`browser-check.json`。

| 原问题诊断的内容/动作 | 现在的位置 | 核对 |
| --- | --- | --- |
| 6 题完整列表、分类筛选、逐题打开 | Baseline → Bad Case 诊断 | 两尺寸旧深链跳转后均为 6 题；分类筛选与抽屉已点 |
| 优化优先级的层次、严重程度、修复思路 | 起点行显示分层题数；完整优先级表继续在 Baseline Bad Case 诊断 | 起点 5+1；完整表不删 |
| 问题诊断中的行点击 | Baseline 原有案例详情 | 保留同一批保存题目及证据 |
| 原处理进度“修复/待处理、组合须重新完整评测” | Agent 规划折叠区（没有最终推荐时） | 原字段和分支保留 |
| 旧问题诊断深链 | `#evolution?tab=bad` / `tab=diagnosis` / `stage=bad` → `#evaluation?tab=cases` | 浏览器和单元测试通过 |

原问题诊断没有别处没有的付费按钮；它的专有操作是分类过滤和行详情，均迁往已有 Baseline 入口。Agent 原顶栏、更多菜单及规划折叠区的动作仍保留。来源：`output/task021u/inventory-before.json`、接入前保存的页面源码和最终源码。

5 个 Agent 页签为：进化路线、A/B/C/D、Sandbox、Regression Check、最终推荐。`usePageTab` 保存 UI 页签到 sessionStorage，URL 用 `?tab=`；App 识别带参数的页面哈希；Baseline 同样支持 `?tab=cases`。首次没有保存状态默认路线；已有 URL/状态则恢复。来源：`usePageTab.ts`、`App.tsx`、`EvaluationPage.tsx`，浏览器 reload 和旧链接验收。

`storyText` 的英文规则保持 021r 已有实现，Winner、Thinking、High/Max/Low 等没有再译回中文；只替换题号展示组件，不改保存文案和英文映射。来源：`EvolutionStory.tsx` 的差异。
