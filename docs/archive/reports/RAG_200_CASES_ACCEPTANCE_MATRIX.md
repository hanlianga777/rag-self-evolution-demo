## 读取与定位约定

唯一记录键是完整 Run ID + Question ID。下表保留完整键；Q编号只用于阅读，不得成为实现条件。来源是 `backend/data/demo.db` 的 `evaluation_runs` 冻结 snapshot 与 `evaluation_case_results` 原始 result_json，实际回答=`model_answer`；Final=`programmatic_metrics.retrieval_trace.final`，必须读 `content` 全文，不能只读 `child_content/content_preview`。

D1/D2/D3/D4分别是 DOC-001/002/003/004；例如D1C00138表示DOC-001-C-00138，P表示Parent。`C→P@PDF起–止`记录实际Final入口及展开范围；页面为PDF文件实页（1起），不是印刷页码。matched_child_ids及来源别名保留在原Trace。每行A/F为完整回答字符串/完整Final列表的SHA-256前32位；F用ensure_ascii=False、sort_keys=True、紧凑JSON计算。省略原文不改变原始存储，完整哈希另列于行尾以便复核。

判定读取了每条完整回答和Final、冻结题意/必要事实，以及前轮已核对的PDF原页与本轮范围复核；没有重跑检索或Judge。Final列列出全部来源，不表示其中每条都能支持核心事实；判断以适用范围及必要事实为准。预期事实表的来源是规范依据，可能不在某条Final，不能倒灌成该条RAG证据。
