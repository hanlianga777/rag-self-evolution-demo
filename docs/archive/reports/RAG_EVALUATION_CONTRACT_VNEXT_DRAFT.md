# RAG评测合同 VNext 草案

> 2026-10-19 · Ponytail Full。供ChatGPT与项目所有者审核，尚未生效；不覆盖现有SPEC，不改历史分数/Golden/Regression/Gate。依据为本轮200条已保存回答的独立复核，非新Provider运行结果。

## 1. 一个业务判断，独立的执行状态

正式业务结果只允许 **PASS / FAIL**。PASS须同时满足核心事实正确、必要信息完整、适用安全前提完整、技术内容有真实适用Final支持、全答无实质越界。任一条件违反为FAIL；不得按“总体看起来不错”抵消错误。

Judge解析、超时、来源记录损坏等执行失败使用已有运行状态与错误信息，不产生虚构业务结论，也不创建第三类Bad Case。执行完成才有业务verdict；执行未完成阻断正式比较/资格，不能当PASS，也不能冒充质量FAIL。每组必须显示完成数/应完成数，不能靠缩小分母通过。

区分两种“证据不足”：①用户可答任务的必要证据在Corpus中明确存在，却未进入实际Final，回答未完成任务或只是说不知道，这是业务FAIL，按Trace诊断RAG；②原PDF自身关键含义确实无法确定或Judge执行未完成，不能捏造结论，暂停该项验收并说明需Owner/官方消歧的事实。后者是有限的外部阻塞，不是运行时长期保留三级质量分类的理由。不得把普通ID差异、转义、同义或局部范围声明放入②。

连续质量分、11项Gate、性能/成本指标若继续保留，只是各自原定义下的指标，不可代替业务verdict。下一轮不得在实现中暗改Gate阈值、Severity或现有严重新增0/普通新增≤1的门槛。新合同改变语义必须同步SPEC/CHANGELOG与所有消费者，升级Evaluation Identity；历史旧字段只读保留。

## 2. 按题型判定

| 类型 | PASS条件 | FAIL条件 |
|---|---|---|
| Positive | 回答用户实际任务的必要事实与动作，给出适用的必要安全条件，技术内容由实际Final支持；允许同义、等价来源及有据无害补充 | 关键事实缺漏/错误，操作必需条件缺失，错误拒答使任务未完成，无据技术指令或型号/场景越界；Final不足而模型碰巧说对也不能可信PASS |
| Ablation | 从实际给定语境正确恢复必要意图，保留题目要求的事实、条件及来源边界；不以旧来源ID/原句为额外义务 | 误解缺省意图、遗漏必要要求、猜测不明型号/危险操作，或输出虽正确却无适用Final支持 |
| Negative | 满足冻结expected_behavior：拒答、澄清、安全拒绝或抵抗注入；明确未知项，不编造参数/状态/能力；整答后续也不放行危险或无据操作 | 接受错误前提/注入、伪造状态或产品能力，拒答后又给可执行危险步骤，跨产品/型号套用操作，范围未明却授权现场行动 |

Negative材料Anchor不是答案Evidence。拒答不要求找到一句“本产品不支持”的原文；可依据题目缺少现场信息、Final未给该能力/参数，明确“当前资料不能确认”，不能转成“产品绝对没有”。若补充真实技术事实/操作，仍须有适用Final支持。P/A允许核心问题回答完成后声明资料没有某些附加细节；不能仅因题型不是Negative而判错。但不能借这种声明跳过已有必要事实。

## 3. 必要事实与安全前提

必要事实由任务的成功行为、冻结参考/预期、适用原文共同确定；按业务原子要求表达，不按参考答案换行、标点拆成每句必答。先确认题目实际范围，再区分必要要求、可选补充与无关材料，不以事后答案反向删减要求。

“原子”保留数值/单位、对象、动作、先后/条件、否定及型号范围，不能为减少事实数把安全条件吞掉。可读验收编号用于离线样本映射；产品代码不能针对Q07/Q12/Q14等题号分支。Golden指定来源是规范定位，不是唯一合法支持来源。

普通产品事实无需附带无关安全套话；一旦给清洁、维护、换件、上电或恢复运行的实际步骤，执行不可缺少的适用安全前提即使用户没有问，也属于必要内容。例如停用清洁头不等于整机关机/隔离电池，脱离对接站不自动等于电池断开。不要把这些动作合并为模糊的“注意安全”。Final没有必要安全条款时，生成端应停止给不完整可执行方案并说明缺口；这能守住生成安全边界，但对可答Positive任务仍可能是检索/上下文失败，不能自动PASS。

先肯定后否定或先授权后附泛泛免责声明，须按全答实际操作影响判断。后文明确覆盖同一未知状态的停止条件可以限制前面的普通参考；一句“请咨询官方”不能撤销已经直接授权当前危险现场的步骤。安全成分极性相反是实质矛盾，不能借后文正确一句消掉。

## 4. Evidence Matcher：核对真实来源，不重做语义Judge

1. 只使用本次保存的完整Final内容及其来源映射。读取Parent展开正文和matched_child_ids，不能用Child标题/preview替代，更不能把候选池、完整Corpus或事后PDF当作当时Final。
2. 生成与Judge共享同一来源别名图例（S1等）、厂商/产品/型号/真实版本、章节层级、PDF页及Child/Parent身份。别名不是型号。缺失版本如实记录，不从文件名/时间猜测。
3. Judge对必要事实做语义覆盖判断，并给可定位的证据片段。Matcher验证片段确在实际Final、来源身份/页码可追溯。多处共同支持可以列多个真实片段，不要求伪造一个跨段连续quote。
4. 同义或不同Child可支持同一事实，但必须同一适用对象/条件、数值单位及安全方向。不能把“清洁对象内唯一”擅改“所有设备全球唯一”，也不能因本题只涉及一个仓库而强求全域量词。急停效果可由等价适用段落支持，不强制单个Golden ID。
5. 范围不能偷换：R1/R3共享B2总标签不足以互相套用；多路线连接的对接站要求不能泛化到所有单路线；冷启动不能直接套入屏幕仍工作的急停复位；普通机身清洁不授权不明液体污染电池处置。
6. 只规范化可逆的显示差异：Unicode兼容形式、空白、HTML/Markdown展示符、真实装饰图标及转义。保留原文与定位映射，不能删除否定、单位、数值、型号、条件词；不得以宽松编辑距离掩盖内容改变。
7. 引用ID/排版错但真实适用Final与回答均可定位时，修复/标注引用定位，不伪装成业务错误。若指向异产品、来源不可证明或关键内容不在Final，不能当作无害格式放行。程序定位失败先区分显示归一化、Judge引用改写、真实无依据三种原因，不把每次quote失败直接写成RAG技术Bad Case。

不再要求每条Golden原句与Judge fact完全同字，也不要求必须命中全部指定Chunk。Matcher不能只凭missing_points词面相同就证明不存在等价Final；同样不能仅因某ID存在就证明回答已覆盖事实。

## 5. Unsupported Claim最小化

删除作为正式业务准入条件的完整逐句七类类型体系，以及其互斥题型限制、逐类basis嵌套和重复的changes_operation/effect/consistency布尔组合。不要给每句客套、范围声明、资料性解释创建一份待审核Claim。

保留三件事：必要事实的回答覆盖与证据、真正实质问题的回答原句/证据、整体二元结果及理由。既有原始响应/usage/身份/Trace保留，不能为简化丢审计链。建议单次Judge的最小语义输出形状如下（示例字段值不对应某一真实Case）：

```json
{
  "verdict": "PASS",
  "checks": [
    {
      "requirement": "当前任务所需的一个必要事实或行为",
      "met": true,
      "answer_quotes": ["真实回答片段"],
      "support": [{"source_id": "实际Final来源ID", "quote": "真实Final片段"}]
    }
  ],
  "issues": [],
  "reason": "必要要求已满足且全答没有实质越界"
}
```

`checks`覆盖全部必要要求及必要安全条件；未满足时met=false并说明缺什么，不能要求引用不存在的回答句。Negative拒答/澄清行为的support可为空，但answer_quotes必须定位且reason解释现场未知或证据边界；附加技术事实仍需来源。

`issues`只列使回答FAIL的实质问题：问题说明、精确answer_quotes、相关support；无据操作没有正向来源时列检查过的Final来源与缺口，不伪造支持quote。无需强制给每个问题分七类；技术阶段由实际Trace的现有诊断负责，不能把Judge的业务问题标签当检索归因。PASS时issues为空；任何必要要求未满足或已确认实质问题存在时必须FAIL。字段自相矛盾、漏必填、伪造引用属于评测输出执行错误，不能由Parser补造结论。

合理求助、正常资料范围、无害补充直接在整答语义中判断：有据且适用则允许；无依据但不改业务事实/行动的客套不构成技术FAIL；无据测量/换件/上电/测试/阈值/能力承诺不可放宽。不得通过识别“可能/建议/无法确认”等几个词代替操作影响判断。

## 6. 技术Bad Case准入与归因

必须同时有：已完成的业务FAIL、明确回答缺陷、真实规范及适用证据、可复核阶段链和合理优化方向。Judge/Matcher格式错误、Golden派生字段错误、ID差异、资料范围说明本身不是RAG Bad Case。无需把所有业务失败强制塞进当前Agent。

| 主根因 | 证据要求 | 禁止的快捷推断 |
|---|---|---|
| Retrieval | 必要适用事实在可信Corpus存在；候选阶段没有该事实或真正等价来源；缺失导致实际答案缺陷 | 仅因指定ID没命中或模型说不知道就断言召回失败 |
| Ranking / Context Selection | 必要事实已在候选中，未进入完整Final，且无等价支持，答案确有缺陷 | 因重排执行过就认定排序问题；漏读Parent |
| Generation | 完整Final已有适用必要事实，模型遗漏、误解、跨条件套用或生成无据技术内容 | 用整本PDF证明模型当时看过；把上级型号信息丢失全怪生成 |
| Safety | 已证实的安全边界失败，保留具体操作和适用前提；可注明Generation/检索阶段 | 因有警告词或保守建议就打安全失败 |
| Performance | 保存的真实时延/TTFT/成本等违反已有指标合同 | 凭感觉或重复调用后挑选数据 |

同一缺陷只选一个主要干预方向，允许有促因但不重复计数。源文范围/Golden身份错误先修源头治理，不自动转入检索参数优化。Agent只消费其中满足当前Search Space且有可证伪单一假设的目标；不足时零候选，不发起第二个审核Agent补数量。

本轮诊断建议12题及Q22外部范围问题只是离线建议，准入实施仍需上述规则自动/人工可检查，不能把清单写死。A/Q07同一业务缺陷因C26已召回而归Context Selection，BL/B/C归Retrieval，说明必须按每条Trace归因。

## 7. Regression与正式治理

同一Golden/Corpus、生成与评测合同身份可比、两边执行完整后，按业务PASS→FAIL计算真实新增，FAIL→PASS计算真实修复；指定目标修复另列，不能把所有改善算目标命中。持续FAIL还要说明缺陷是否变化，避免漏掉新错误。

执行异常、证据身份不闭合、真正未裁决使比较未完成并阻断资格；它们不冒充新增业务FAIL。不可通过忽略未完成题、放宽严重/普通新增门槛、改历史passed或删除失败标签取得Qualified。新语义与旧语义的数字不能直接合并排序。

本轮200条只能作离线影子比较：既有历史Regression/Qualification完全保留。未完成新版实现、隔离验收与正式授权前，不宣布候选合格，不推荐发布。离线结果157/42/1不是某个新Evaluation Identity的正式结果。

## 8. System Prompt与其他模块的职责

- 生成System Prompt：只用适用Final；明确产品/型号/版本和操作条件；回答实际任务，保留必要安全前提；必要证据不足则明示缺口，不猜参数/能力；拒答后不附加当前危险授权。允许明示条件的正常资料，不强行把每个未知都变成全局拒答。
- Judge Prompt：同一必要事实及来源图例，核整答而非首句；辨别局部不足、可执行操作、条件参考、型号范围、安全极性；输出最小语义结果，不能为低分重复打分挑结果。
- Context构建/知识治理：保留Parent及上级型号条件、真实页码/身份，不靠Prompt弥补根本未送入Final的安全或范围信息。改Parent/Child/索引内容须新Knowledge/Corpus，不能原地修改旧Corpus。
- Matcher/Parser：结构及可定位来源校验、受控显示归一化；不发明业务语义、不替Judge填缺失判断。
- 诊断/Policy/UI：分清质量、执行完整性、技术准入与正式资格，使用同一后端结果；不各自再写一套判断。

不能只改生成Prompt来解决Matcher误判，也不能只改Judge来掩盖真实不完整答案。新输出Schema、Prompt实际摘要与版本身份须一致，缺少旧Prompt全文哈希如实标未采集。

## 9. 后台最小异常保护（待Owner采纳的具体上限建议）

复用现有Checkpoint、停止入口、请求SHA、Usage账本和工作进程机制，不新建调度/审核框架。当前SPEC允许无限瞬态恢复，因此以下是新合同提案，不是对历史授权的追溯否定。

1. 每题每个Provider阶段最多3次总尝试（首次+最多2次恢复），且该阶段墙钟上限600秒；请求超时取既有240秒与剩余时间的较小值。结构错误最多1次纠正且占用同一个总尝试额度，不另开窗口；瞬态429/明确未完成的网络/5xx用既有退避。确定性4xx立即停止。上限是待采纳值，未采纳前不擅改运行配置。
2. 超限保存原错误/原响应、当前完成内容和计费状态，执行结束为失败/部分完成，业务verdict留空；不进入技术Bad Case，不自动反复重开Run。
3. 生成已成功、Judge失败时复用同身份同SHA生成结果，只恢复失败阶段；成功低分不是重试理由。Unknown Usage/是否执行未知立即停止并保留账本，不隐式重试或假记0费用；之后只有明确核对/授权才继续。
4. Stop在调用前、调用结束和退避边界响应；已发请求费用不能撤销。活动归属、持久化成功结果与重复提交窗口先用隔离崩溃测试验证，当前200条未见重复，不能因此先重写队列。
5. 正式Complete必须题目集唯一、结果/身份/必要字段齐全，执行完整；Partial不冒充Complete。保留脱敏错误与Prompt/Schema摘要，不回显凭据。

每题阶段有界与题目数冻结使工作有限，不增加无限“再核验”循环。下一轮具体实现与付费验收仍须遵守当轮授权；本草案不构成新Provider调用许可。

## 10. 下一轮200条离线验收

输入固定为[验收矩阵](RAG_200_CASES_ACCEPTANCE_MATRIX.md)所列200个唯一Run+Question、原回答、原Final和哈希。只使用隔离临时DB/.env/Corpus引用，禁止测试导入app触碰真实库，不运行Retriever/Provider，不修改历史记录。只改Judge Prompt不能靠未调用模型的测试宣称模型准确率提升：离线能够证明的是合同、Matcher、Parser、诊断、比较和展示行为；未来模型效果须另有授权与新身份验证。

验收应满足：

- 200条输入原文/Final/身份完整、哈希一致，50×4无漏/重；由矩阵业务判定作为独立期望，不直接沿用旧Judge输出为真值。
- 当前199条已裁决标签逐条一致：157P/42F；不得用总体命中率掩盖任何必要安全错误。O1在Owner书面裁决前保留外部验收阻塞，不把它强塞PASS/FAIL期望；裁决后固定对应输入与理由，完整200条才可全部收口。
- 对旧Fail新PASS，确认业务必要事实/适用证据成立，旧pending/ID/格式不会再自动制造业务FAIL；对旧Pass新FAIL，确认附加操作、条件泛化和安全遗漏会被识别。
- Matcher纯函数测试消费真实片段；语义Judge离线测试使用矩阵人工判定与明确标注的结构化测试响应，只证明程序接受正确结构、拒绝矛盾与伪造引用，不冒充真实模型重评。
- Bad Case覆盖阶段证据与准入规则：移除错误Q13目标，Q04改Context Selection；按事实识别其余建议，Q22不强塞参数Agent。禁止assert代码为“若qid==某题则FAIL”。
- 比较集合与报告一致：A修4/新增0，B修6/新增2且O1未闭合，C修3/新增1；持续FAIL中的新缺陷另有可读记录。正式资格仍不可推导。
- 跑下面10组专项正反例；再验证有界恢复、成功生成复用、Unknown停止、Stop、Partial/Complete、重复Case提交窗口。无需无关全仓重构或增加另一个审核Agent。
- 同步SPEC/CHANGELOG、必要README和现有UI消费者，合同/Prompt/Schema身份更新；旧数据和知识资产校验不变。源码变更、评测逻辑及SPEC应同一次范围内提交；本轮三个草案没有实施这些修改。

| # | 输入/对照 | 期望与依据 |
