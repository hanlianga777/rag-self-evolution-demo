共性代码缺陷及修复：

1. 原来主要保存整段回答/评分；成功Embedding后Rerank或后续生成失败，已支付RPC结果可能丢失，显式续跑会重复Embedding。现沿原Checkpoint追加`provider_requests`，发送前保存本地请求身份，返回后保存完整且校验通过的结果/Usage。同题同阶段按Provider、端点、模型、完整payload摘要匹配，复用成功Embedding/Rerank/回答；不跨Candidate、题目、阶段共享。错误向量/重复Rerank索引不能缓存为成功。Judge无效内容仍沿原纠正机制，不复用成合格评分。
2. 原DeepSeek对明确429拒绝统一记`failed`，导致被误当费用未知。现明确拒绝记`rejected`，按原最多3次/600秒及Retry-After执行；401/403、余额等永久拒绝不重试；超时、连接中断、不明5xx与缺Usage停止。没有新增重试次数、超时、Token或费用上限。
3. 原超时记录不能区分已收到HTTP头后读正文超时。新记录保存已观察到的HTTP状态/请求ID、是否已收到完整响应头、请求摘要及传输cause类别；旧B/A记录不回填猜测值。读取错误响应后关闭HTTPError对象，避免错误路径持有响应资源。
4. 持久RPC事件与阶段事件按本地请求身份去重；Worker死于阶段落盘前，RPC结果及Usage仍可审计，不重复计费事件。外层inflight、未知RPC、未知费用继续保守阻断；不能因服务重启或人工费用确认清除Unknown。
5. 检索包装明确区分`query_embedding`与`rerank`，保留底层Provider细节；不再只显示泛化的retrieval_pipeline。原已完成Case复制、答案仅补Judge、停止、Worker所有权和事务身份保护继续复用，未重构Agent/Judge/API/UI。

修改业务源码：`evaluation_stage.py`、`knowledge_pipeline.py`、`providers.py`、`retrieval.py`、`evaluation.py`、`paid_run.py`。另新增共享离线故障矩阵，调整受影响Provider mock边界，并在API测试清理临时SQLite前等待其Worker完成Recommendation保存（隔离测试曾提前删除目录导致后台线程报错，非正式库异常），同步SPEC、变更记录、README及中断文档。架构节点/连线未变，无需重新绘图。
