## 确认的根因与最小修改

1. App每次导航都等待同一10接口；StrictMode重复启动读取。实际首次打开共24次API，累计50,877,770字节。恢复器额外两次读取全部历史修订，每次13,284,657字节；它只需要恢复活动任务。现在按页选必要数据、概览使用light摘要、恢复器查询active_only；默认历史列表与详情保持完整。取消已卸载初始化及Baseline读取，最终初次8次API、5,610,431字节。没有持久跨请求缓存。
2. optimization和bad-cases为最慢两个初始化接口。只读剖析发现31次诊断、62次整批Case读取、143次SQL；重复Corpus哈希、JSON解析和证据校验占主要时间。SQLite查询/fetch累计约0.3秒，不支持把锁等待或Provider网络当成主因。诊断现在只取目标Case；Bad Case用SQL按当前Run过滤；Baseline身份扫描提前排除Sandbox并保留原全部身份校验、兼容旧目标记录。
3. 仅在单个只读响应内复用纯诊断/Canonical读取，输出独立副本，响应结束失效；下一请求重新验证。执行/评分/审批路径不建立此缓存。剖析中的批Case读取变为0（40次精确单Case），SQL降至99次；该离线剖析仅辅助解释，最终以独立浏览器/API测量为准。
4. 当前页未就绪时复用原加载/错误画面，避免拿上一导航数据伪装新页面；原详情入口仍完整读取。无新导航、UI重设计、模型或索引调整。
